# 战法分层与状态覆盖草案

日期：2026-11-08。状态：当前基础覆盖核对及后续设计底稿。规则151已接入陆战兵种／舰船3小3大、兵器3小1大池、人物特点固定分配、横扫／扰阵命名及御术等基础来源，见[固定战法规则](固定战法与稀缺专属-规则64.md)。下方候选矩阵用于核对剩余覆盖，不代表所有条目均已接入。

## 1. 用户确认的方向

- 普通战法名称尽量使用两个字。
- 普通战法尽量覆盖现有正面状态、异常状态及基础战斗行为，例如魔免、眩晕、位移、群体伤害。
- 强力战法由普通战法组合、加强而成，例如群体伤害加眩晕，也可以包含特殊机制。

具体名称、效果归属、数值、可得性、兵种与人物分配尚待逐项设计。“尽量覆盖”不表示每种状态必须独立成为一个战法，也不表示所有战法采用相同门槛和收益。

## 2. 设计层次与当前术语

| 设计层次 | 设计任务 | 示例 | 与当前配置的关系 |
| --- | --- | --- | --- |
| 基础效果 | 名称简短、主要用途清楚，建立容易理解的效果模块 | 护盾、魔免、眩晕、击退、横扫 | 优先讨论普通小战法；单纯群伤也可以是基础模块，具体层级看范围、强度和代价 |
| 组合强化 | 组合基础效果，或加强范围、目标数、强度、时长、条件收益 | 群伤加眩晕、突进加伤害、群体护盾加减伤 | 可用于通用大战法、技术兵种战法或人物专属，不自动限制给名将 |
| 特殊机制 | 改变伤害关系、行动方式或局部战场规则 | 连环传导、反击、疑兵、持续区域 | 依据实际收益确定层级；使用共同处理器，不因名称或稀缺性直接认定强弱 |

当前源码中的“普通战法”包含非专属的小战法和高级战法。本稿以“基础效果／组合强化／特殊机制”描述设计结构，不直接变更 `learningTier` 或取消现有固定携带制度。

基础战法允许必要的附属效果，优先让一个用途成为记忆重点；强力战法需要体现效果之间的关系，例如用突进接近目标、用控制帮助群伤兑现。每项效果分别检查免疫、控制保护、伤兵、护盾、路径、次数与来源，不能绕过共同规则。

## 3. 当前可用性基线

当前战法定义91项，其中16项为指定人物专属。陆战兵种／舰船池为3小3大、兵器为3小1大；哪些普通战法已经进入池，以正式分配表及逐池实际持有者检查为准，不能用同兵种所有候选作为单将携带配置。

覆盖记录应分别标注：有状态定义、有公共处理器、有合法施放来源、已进入固定配置、存在实战合格机会、产生实际贡献。状态或效果库存在，不表示普通武将已经能携带；同一状态还可能由羁绊、军略或任职特性提供。

## 4. 基础状态覆盖矩阵（候选）

以下覆盖42项可讨论为基础模块的状态，分类只用于设计核对，不更改状态语义。表中两字名称均为候选；同名状态与战法是否直接同名，实施时统一处理。

| 方向 | 状态键与现有状态 | 两字战法候选 | 实施重点 |
| --- | --- | --- | --- |
| 硬控与行动限制 | `stun`眩晕、`confuse`混乱、`seal`封技、`taunt`嘲讽、`disrupted`失阵、`root`定身、`disarm`缴械 | 扰阵、扰乱、扰策、挑衅、挫锐、缚足、卸兵 | 定身仍可攻击施法，缴械仍可移动施法，失阵只移除ZOC；不要把这些全部做成眩晕 |
| 数值与距离压制 | `slow`迟滞、`armorBreak`破甲、`weaken`疲弱、`powerDown`挫锐、`attackSlow`缓攻、`shortRange`短射 | 迟滞、破甲、疲弱、挫锐、缓攻、短射 | 疲弱降低攻击，挫锐降低双战法威力；短射只改普攻射程，保留各自用途 |
| 战意压制 | `despair`丧志、`intentSuppression`抑气 | 丧志、抑气 | 持续损失已有战意与降低战意收入分别评价，不混成同一种削战意 |
| 持续损伤 | `burn`灼烧、`plague`疫伤 | 火矢、疫矢 | 分别体现叠燃与减疗；同时核对实际可得的解除手段 |
| 伤害关系 | `link`连环 | 连锁 | 保留来源比例、非递归与合法目标；是否属于高级效果由实际收益决定 |
| 免疫与自保 | `magicImmune`魔免、`resolve`坚定、`stasis`避战 | 魔免、坚定、避战 | 保留现有语义；魔免解除并免疫异常且仅承受物理普攻，避战期间停止行动；分别安排时长、目标数及代价 |
| 保护与恢复 | `shield`护盾、`ward`减伤、`guard`护卫、`regrowth`休整 | 护盾、减伤、援护、休整 | 护卫状态的分担与护卫羁绊的护盾不是同一个效果；恢复只使用真实伤兵 |
| 阵地增益 | `phalanx`方阵、`bulwark`坚阵、`camp`营垒、`nexus`阵枢 | 方阵、坚阵、营垒、阵枢 | 这些已有组合属性与移动代价；分别核对实际定位，不为统一分类强行拆除现有效果 |
| 机动与输出增益 | `phase`穿阵、`haste`疾行、`attackHaste`速攻、`longRange`远射、`valor`奋战 | 穿阵、疾行、速攻、远射、奋战 | 移速、攻速、攻击、无视ZOC和射程各有用途；穿阵不能穿过占位及不可通行地形 |
| 受击回应 | `riposte`反击 | 反击 | 使用共同触发、每回合次数和非递归规则；需要实际承受近邻直接攻击 |
| 隐蔽与识破 | `stealth`伏兵、`insight`洞察、`decoy`疑兵 | 伏兵、洞察、疑兵 | 潜行、识破和幻象各有真实作用；先检查双方实际可得性 |
| 普攻转化与作战形态 | `burningAttack`燃击、`strategyAttack`谋攻、`anchored`抛锚、`emplaced`架设 | 燃击、谋攻、抛锚、架设 | 分别改变普攻或驻定形态；保留强化普攻互斥、射程及移动限制 |

眩晕和魔免可以成为普通战法候选，不能只因效果强而自动排除。是否适合普通层，由实际覆盖、时长、启动、独立冷却、限次、目标资格及固定配置共同决定。当前扰阵提供近距眩晕，御术作为藤甲池中的短魔免接入；方阵保留。具体持有者和试调参数见固定战法说明。

## 5. 来源绑定、组合及约束状态

余下11项也纳入覆盖核对，但不要求逐项复制成独立普通战法。

| 状态键 | 当前用途 | 草案处理 |
| --- | --- | --- |
| `commandInvincible` | 军略来源的军阵无敌 | 保留来源与限制，作为强保护模块参考；不直接把军略来源改成普通战法 |
| `guardInvincible` | 护卫羁绊满档破盾后的免伤 | 作为条件触发机制记录，保留破盾及每场次数条件 |
| `peachFury`、`peachInvincible` | 桃园来源的奋战与无敌 | 继续属于指定羁绊来源；强度读取该来源的实际参数，不凭状态默认文案另造一套 |
| `swiftRush`、`rapidAdvance`、`pursuit` | 突进窗口、神速、后阵追击 | 可解释为机动、穿阵、攻速和后排追击等模块的组合；现有来源分别保留 |
| `heavyAttack` | 限次物理普攻增伤及尝试混乱 | 作为强化普攻的组合例，是否设置普通来源另议 |
| `attackOrb` | 强化普攻的通用记录 | 覆盖具体装填效果，不为内部容器再新增一个同义战法 |
| `stasisLock` | 避战重复获得的间隔 | 内部约束，随避战模块检查，不作为可施加技能 |
| `hunger` | 真实军团缺粮 | 继续来自真实供给，不把战法直接施加战略缺粮列为本次覆盖要求 |

## 6. 不属于状态的行为模块

| 行为 | 两字名称候选 | 组合方向与边界 |
| --- | --- | --- |
| 单体直接伤害 | 突刺、狙击 | 与破甲、残兵、距离等条件配合；使用既有武技／谋略及目标规则 |
| 群体直接伤害 | 横扫、贯阵、乱射 | 直线、扇形和范围各自形成站位价值；单纯群伤也可作为基础模块 |
| 自身位移 | 冲锋、退射 | 接近或撤步后再攻击；使用真实空格、占位、水陆与ZOC规则 |
| 敌方位移 | 击退、牵引 | 改变接触关系或打断准备；检查位移免疫、合法落点及阻挡，不隔着部队拖拽 |
| 战意收支 | 鼓舞、夺气 | 直接给予或削减战意，与丧志／抑气状态区分 |
| 救治与修复 | 救护、修缮 | 分别针对真实伤兵及存活建筑，不复活或重建 |
| 解除与驱散 | 镇静、整军、扑火、破阵 | 保留各自解除列表及资格；不把所有解除效果统一成万能净化 |
| 次数与冷却 | 整备、策应 | 恢复次数、增加上限和缩短冷却分别登记；继续遵守普通补次边界，不自动取得重整旗鼓的专属补次例外 |

## 7. 强力战法的组合示例

| 示例名称 | 组合结构 | 状态 |
| --- | --- | --- |
| 雷霆震击 | 群体伤害＋眩晕 | 候选；用于表达用户提出的组合方向，不代表已经新增 |
| 铁骑冲阵 | 合法突进＋伤害＋失阵 | 候选；各段分别执行移动、命中与状态判定 |
| 烈焰连环 | 范围伤害＋灼烧＋连环 | 候选；核对传导来源、触发先后和非递归，不能默认所有伤害均传导 |
| 清心护阵 | 群体解除＋坚定＋护盾 | 候选；明确可解除列表、目标数和生效时机 |
| 横扫 | 扇形群伤＋近身实伤救治＋护盾 | 现有效果，用于说明组合结构；不因本稿新增收益 |
| 白毦护阵 | 多队护盾＋减伤 | 现有效果，用于说明通用强力支援可以由技术兵种提供 |
| 连环奇计 | 范围伤害＋3回合非递归伤害传导 | 现有庞统专属，体现特殊伤害关系 |
| 神火燎原／火烧连营 | 范围伤害＋灼烧＋利用既有灼烧 | 现有专属结构，后续分别讨论差异化；此处的火烧连营指陆逊专属，不是同名军略 |

强力战法还可以沿着“范围扩大”“多目标”“条件引爆”“延迟落点”“持续区域”“受击回应”等方向设计。特殊机制先检查已有公共状态和处理器，再决定是否需要扩展；军略、羁绊的既有来源和专属资格不因组合示例自动改变。

## 8. 下一步设计顺序

1. 按矩阵确认哪些基础效果进入本轮实际配置，先补眩晕、魔免、控制细分、保护、位移及对应反制的可得性，再决定具体数量。
2. 为每项基础战法填写名称、目标、范围、主效果、门槛、代价、独立冷却、次数、适用兵种、来源与解除方式；两字名不能造成多个不同效果难以区分。
3. 将通用大战法、技术兵种高级战法和16名专属逐项映射到基础模块，记录组合带来的新用途、成本及条件，不直接给全体武将扩大携带数量。
4. 在现有兵种与适性配置下检查覆盖是否够用；若需要扩大固定配置，单独形成具体分配方案，不能以效果库扩充代替实际可得性。
5. 实施时共用自动施放、控制保护、道路／战场移动、范围、次数、真实伤兵及双方结算。游戏AI仍不规划羁绊，也不增加玩家单队微操。
6. 对照基础技能与组合技能的真实收益，检查铺垫能否赶上爆发、免疫和强控是否仍有应对空间、支援是否可见。分别报告机制正确、局部体验和未验证部分。
