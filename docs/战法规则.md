# 战法与战斗规则

当前规则入口见[规则总览](README.md)。本页整合已确认的有效规则；具体战法数值只维护于[战法一览表](design-tables/战法一览表.md)对应的正式设计源。

## 能力与配置

- 特技是身份固定、开局可用的正面能力，不占战法名额；战法由兵种、适性与主将属性决定；军略由合资格的军团长、军师提供。
- 每兵种固定两个小战法和一个大战法；S三项、A一个小战法加大战法、B/C一个小战法，按武智、统政、魅力依次选择。专属限确认的16人，额外携带，所有等级可用。详见[固定战法规则](固定战法与稀缺专属-规则64.md)。
- 战法自动携带、自动施放。玩家界面只查看效果与携带条件，不提供换装或施放顺序调整；AI也不能换技能、重抽或优化技能顺序。

## 行动与施放

- 每步按已有顺序检查战法的行动资格、战意、独立冷却、调息、剩余次数和合法目标；无合法目标跳过，每步最多施放一项。
- 战意上限100，无自然增长；各兵种普攻、存活受击收入以 `combat-rules.mjs` 的 `TROOP_INTENT` 为准。伤害战法不提供施法者普攻战意，反击和持续伤害不产生战意。
- 当前普攻／受击战意：枪3／2、戟3／2、骑5／1、弓3／1、弩5／1、投石与冲车及井栏6／1、舰船4／2。同次多段战法对每个存活受击者只提供一次收入；完全被护盾吸收不提供受击收入。受击不扣战意，也没有随时间自动增加或衰减。
- 一队真实溃败后，同方其他实际在场部队以远处20、2格内30为战意损失基准，乘以“溃败队本场初始兵力÷本方开场首发平均初始兵力”，系数限制为0.25～1，合计后四舍五入取整数，战意最低为0。基准取保存的固定首发名单，不因伤亡、救治、撤离、后备或后到援军重算；没有开场首发的合法一方沿用完整基准冲击。后备、未到援军及已离场不受影响；主动撤离、疑兵消失和城门被破不触发。同一伤害批次结束后逐队结算，每支溃败部队每场一次，触发记录随存档保存，双方共用。
- 大多数战法不扣战意，少数爆发例外以各项 `intentCost` 为准。战法类别由 `learningTier` 决定，不能按战意门槛推测高级或低级。
- 每队每项战法独立限次，补次、增加上限和缩短冷却是不同效果，详见[战法次数与整备](战法次数与整备-规则48.md)。
- 属性、威力、抗性和概率分别见[部队属性](部队属性规则.md)、[威力与概率](战法威力与概率规则.md)。控制、免疫、护卫、疑兵与伏兵使用[公共状态机制](部队状态与特殊机制-规则62.md)。

## 战法连携（规则128）

站位与落空的本轮试调见下节；连携仍以实际命中或有效支援结算为准，蓄势开始不提前建立连携。多个蓄势战法可以重叠准备，在原有短窗口内先后命中；窗口不随蓄势延长。

- 不同实际在场、存活且未撤离、未脱战、未避战的同方武将，可在首个真实有效战法完成后的3个模拟回合内连携。窗口始终由首发锚定，不因后续施法续期。
- 三种衔接：同一目标的协同集火；真实获得前一个战法支援的友军接续施法；以友军战法支援上一位进攻者的接应掩护。后两种还要求当前发动者距上一位发动者不超过2格。真实支援指实际救伤、获得战意或增益、解除异常、恢复次数或缩短冷却，空施法、满战意无收益及自身增益不能作为支援起点。
- 与上一位仍在场的发动者按当前关系值判定，65即65%判定机会，不是整场触发率。失败不加成，当前有效战法成为新起点，已使用的前序支援窗口不再重复利用；同人不能在同一链内重复参与，多段命中不重复参与。
- 二连携的后续战法伤害及可放大的数值效果提高25%，三连携提高40%，后续同链不继续加档；控制与状态额外延长1个模拟回合。公共免疫、抗性、限次、战意、目标与移动规则仍逐项判定。补次不放大次数，不让队友免费施法，也不回溯放大已经结算的首发战法。
- 队友自动战法顺序和AI策略不因连携改变；双方与普通、独立战役共用结算。实际支援对象、窗口、发动者、关系随机流和演出类型随当前存档保存。界面分别显示协同集火、支援接续、接应掩护，不把内部回合误写为战略日期。
- 历史关系及演义边界见[历史协作](名将历史协作与战斗定位.md)，回归 `tests/historical-cooperation.test.mjs`、`tests/combos.test.mjs`、`tests/relationships.test.mjs`。

## 目标、战场与结算

### 战法形状、站位支援与落空（本轮体验试调）

- 贯阵使用连续两格直线；浴血横扫朝目标方向覆盖三个连续相邻格的扇形，不扫到背面；长弓狙射使用五格直线，最多命中三队，主目标外伤害为50%；乱射保留以目标为中心的两格范围及自身实际射程、最多三队限制。方向由合法自动目标确定，射线受山壁与实际建筑阻挡。
- 上述四项在发动时锁定施放位置、目标地点及覆盖格。贯阵、横扫蓄势一回合，长弓狙射、乱射蓄势两回合；蓄势期间不进行普通行动。双方本步行动结束后按锁定格内仍在场且可命中的真实敌军结算，移出可躲避，其他敌军移入可以代为受击，不追踪原目标，也不另选落点。没有敌军留在覆盖格时记录“落空”。
- 次数、战意消耗、独立冷却与调息从开始蓄势时计算。施放者混乱、眩晕、封技、避战、发生位移、脱战、撤离或溃败时中断，已经消耗的次数与战意不返还；没有造成的伤害、救治及连携不计功。蓄势记录与锁定格随当前存档保存，读档不重瞄、不重抽。
- 锁定格内仍可被命中的疑兵按现有独立耐久承伤；本体在范围外时不受伤，不产生真实伤亡或伤害功绩。疑兵命中记录保留实际战法身份与覆盖格，可保存续战。
- 振旅在原有距离、战意缺口及其他友军资格内，优先同横排前方最近者，其次前方其他人，再按实际站位与战意选择。救护、白毦护阵优先同列其他合资格友军；原有伤兵、接敌需求、护盾、减伤、人数及次数条件继续复核。位置改变优先对象，不凭空产生支援收益。
- 后备可在战前会议及援军军议预设本方布阵区内的实际入场位置，先预览、确认后保存。设置不让部队提前入场；有合法名额且真实抵达后，优先该格，被占用则从附近合法本方格补入。详见[后备与撤离](部队撤离与战前设置-规则65.md)。

实现为 `tactic-positioning.mjs`、`tactic-aim.mjs`、`reserve-entry.mjs` 及共同战斗处理器。机制回归为 `tests/autochess-positioning.test.mjs`；局部体验对照运行 `node scripts/audit-autochess-positioning.mjs --phase=development` 和 `--phase=validation`，界面核对运行 `node scripts/verify-autochess-positioning-ui.mjs`。对照仅研究布置、支援、入场顺序及落空效果，不作为全游戏或发行验收标准，不规定胜率、战斗时长或必须提升的幅度。

当前规则136的空间与后备对照使用 `scripts/audit-battle-spatial.mjs`，冻结源码和完整证据位于 `work/battle-ai-iteration-20261029/`。改前、改后各270局，覆盖平原、狭口、港口、赤壁、合肥、五丈原，包含双方换边、一个开发种子及两个独立种子。新版270局均通过确定性续战和起止存档校验；改前两场合肥结束档出现回守脱战目标错误，失败档原样保留。

玩家占阵位与后备顺序仍能改变战局；港口部分阵容的两侧差距、狭口近战长时间等待和合肥守军压力不足仍需继续验证。平均时长150.9→149.4回合，未证明拖尾稳定改善。全国原始官渡全AI观察60天，9次出征、2场战果、2次占领、无缺粮，两个确定性续行检查点通过。这些是局部体验与执行观察，不作为全局胜率、长期战争节奏或发行验收。

- 双方使用共同的走位、普攻、目标与施放引擎。近战遵守ZOC，远程遵守射程和最小射程；合法目标中的残血优先级见[目标选择](目标选择与避战及功绩-规则61.md)。
- 多面接敌按一次攻击预算分摊，详见[邻接分摊](邻接分摊与部队名牌-规则30.md)。突破见[ZOC规则](ZOC突破与远程优先-规则57.md)，地形见[地形规则](地形战斗规则.md)。
- 每军团至多十队、通常同时上场至多六队，奸雄任军团长时本军团可用第七名额；首发与补位遵守到达时间和合法空位。战斗意图、站位、出阵顺序和[逐队撤离条件](部队撤离与战前设置-规则65.md)在战前会议安排；撤离支持批量设置，实际离场才腾出补位名额。
- 普通模式无实际守军的据点到达即占领，不因城门或城墙创建战斗；有现役守军、驻守军团或守备兵才进行战斗。
- 战略一旬10天；战斗日和模拟步的换算及最大时限读取 `combat-rules.mjs` 的 `CAMPAIGN_TIME`，避免把效果的步数与战略天数混算。
- 功绩按实际贡献结算一次，详见[功绩成长](功绩成长-规则53.md)。当前版本保留确定性续战，旧档不迁移。

共享羁绊按正式设计表叠加：强攻、铁壁、迅击直接提高持有者攻击、防御、攻速。昂扬只提高实际在场持有者普攻与受击收入（50%／100%／150%），最终四舍五入；分击仍只发一份攻击收入，多段战法仍对每个受击目标只发一份收入。截气普攻有30%／60%／100%概率阻止该次受击收入，不阻止自身攻击及友军战歌、鼓舞，不削减已有战意。需要真实兵力伤害且目标存活，不能从全额护盾、疑兵、城门、反击或持续伤害触发。实际参数与个人名单见共享羁绊专题及设计表。
