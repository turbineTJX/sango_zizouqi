# 界面设计规范

当前方向：用户于2026-10-30明确偏好《三国志11》的界面风格，并要求现有及后续界面统一依赖一套设计。本文是全项目界面的共同依据。具体色值和尺寸是本项目采用的实现基准，不代表用户逐项指定。

## 视觉方向

以《三国志11》的实际对话框与剧本菜单作为主要配色依据：烟灰墨绢为内容底板，象牙灰框沿和暖白文字负责明暗层次，低饱和玉绿只用于选中与确认，旧金只用于少量数字、焦点和强调。用户已否定先前的暗色细边方案及后续青蓝铺底方案，并要求参考已有成功游戏的配色。当前实现是待评价的候选，不代表用户认可了具体色值。

参考[官方页面](https://store.steampowered.com/app/628070/11_with/?l=schinese)的实际画面：对话框有云纹转角、层叠亮暗框沿及接近中性的烟灰内衬，剧本菜单采用深玉绿雕饰。本项目提取这种大面积中性色、小面积功能色的关系，不把菜单的绿色铺满所有窗口，也不混用青蓝底、银白高光与橙褐按钮。亮沿须有暗槽与材质相接，不能仅以几根平直白线替代。名册保持紧凑，地图与人物仍是主体。以下色值是本项目对这一关系的适配，并非从原作逐像素抄取。

界面风格参考不改变既有玩法、手机横屏、信息按需查看和不增加常驻名册等约定。人物仍遵循[三母图流程](武将多场景美术流程.md)，城内空间与战斗演出继续按各自已确认要求制作；接入界面时遵守本规范的取景、颜色与密度。

| [ui-theme.css](../ui-theme.css) | 共享窗口、按钮、表单、页签、表格、标题栏、地图工具、帮助与提示的外观；兼容当前页面类名 |
| [细纹材质](../ui-materials/ink-grain.svg) | 共享中性明暗纹理，颜色仍由 tokens 控制；随程序离线提供 |
| [云纹镶框](../ui-materials/cloud-jade-frame.png) / [墨绢底板](../ui-materials/ink-silk-panel.png) | 原创生成的公共绘制素材；边框九宫格拉伸，底板由公共颜色罩层控制对比 |
| [素材来源](../ui-materials/provenance.json) | 原始生成记录与使用边界；不包含原作游戏像素 |
| [字体声明](../ui-fonts/font-face.css) / [字体来源](../ui-fonts/provenance.json) | 随游戏提供 Noto Serif SC 可变宋体；完整字符集、真实字重、固定来源与 OFL 许可，不依赖电脑预装字体或外部字体服务 |
| [界面样板](ui-style-guide.html) | 直接引用同一套样式的可打开样板，用于评审与后续开发对照 |
| 各业务 CSS | 页面布局、位置、滚动、响应式、业务特有的几何关系 |

主入口先加载 tokens，最后加载 theme。旧页面保留的局部声明属于兼容来源，共享组件的最终外观由 theme 决定；不要再在其后叠加一个页面皮肤。新增共享视觉规则直接修改这两个源文件。改动现有业务样式时，将碰到的公共外观逐步归入共享源，避免整段复制旧皮肤。

`--text`、`--muted`、`--gold`、`--sans`等旧变量在 theme 中映射为新的语义值。新代码直接引用 `--ui-*`。势力颜色、羁绊颜色、血条、战意与地形颜色属于游戏语义，不替换为界面强调色。

## 配色与材质

| 用途 | 公共变量 | 当前值 |
| --- | --- | --- |
| 全屏背景 | `--ui-canvas` | `#252426` |
| 窗口主体 / 浮起层 / 凹入层 | `--ui-panel` / `--ui-panel-raised` / `--ui-panel-recessed` | `#424044` / `#514e52` / `#302f33` |
| 玉绿功能色 / 深色变体 | `--ui-jade` / `--ui-jade-deep` | `#35473e` / `#23372e` |
| 正文 / 辅助文字 | `--ui-text` / `--ui-muted` | `#eeeae0` / `#cbc6bd` |
| 外框 / 内分隔线 | `--ui-edge` / `--ui-line-soft` | `#bbb5a5` / `#5d5958` |
| 选中 / 强调 | `--ui-selected` / `--ui-accent` | `#40564a` / `#d8c594` |
| 主要确认操作 | `--ui-primary` | `#425b49` |

大面积内容、题栏、表头与普通按钮均保持烟灰色系，依靠明度区分层级。底板的纤维和墨痕通过近中性的颜色罩层压低对比并隔离原素材的蓝色；正文暖白，确认和选中用低饱和玉绿。普通控件使用连续、克制的明暗变化，去掉原先高反差的塑料亮带。材质通过 `--ui-panel-fill`、`--ui-header-fill` 和 `--ui-control-fill` 统一接入。不用高强度噪点代替绘制质感，不将底纹做得比文字更醒目。

主要窗口使用同一张带透明中心的云纹镶框，源图按280像素切分九宫格；四角保持比例，只拉伸直边。标准绘制宽度44px，实际布局边距8px，外伸4px。标题和底栏为装饰留出内边距，小型指引采用28px框体变体。禁止把整张框图随窗口拉扁，也不把生成图中的文字当作可交互界面。

框沿具有象牙灰亮面、暗槽与灰青玉石内嵌；表格分隔线弱于外框，地图常驻工具保留较薄的同色边缘。未选页签不画成一排卡片。装饰集中于边缘，不遮挡关闭、表单或表格内容。背景遮罩保留场景明暗，不将地图整体压成黑底。

正常正文对比至少4.5:1；辅助文字也以此为目标。装饰和禁用态可降低对比，但不能把可操作入口做成灰暗禁用感。前景与背景成对定义，禁止只切换底色。

## 字体、密度与尺寸

参照[《三国志11》官方手册](https://cdn.akamai.steamstatic.com/steam/apps/628070/manuals/32sangokushi11wpk_manual.pdf)第42-44页的信息组织：名册按归属、能力、事务、兵力、钱粮等主题呈现，详情承载完整效果和说明。列名一般用2-4字，如姓名、所在、任职、兵力、粮草、耐久、收入、支出、结余；同一字段跨页同名。时间范围、预测性质和单位由表题及所在栏目说明，不在每列重复；预备兵、伤兵、费用、资格限制和情报日期保持明确。

- 文案使用游戏中的简短名称，避免将阵营、姓名、兵种串成一行标签。部队选择以姓名为主，阵营分组、兵种独立标识；状态标题统一为“状态”，不混写 BUFF 或在效果名称后重复附加分类。
- 窗口标题表达页面用途，对象姓名在选择区或资料区显示一次。“详细情报”“属性变化”“施放条件”“目标”优先于解释式长标题；状态来源用“曹操「鼓舞」”表示施加者及能力。
- 操作说明先写动作和结果，少用无必要的“真实、实际、合法”，不在普通操作区重复说明后台校验或存档实现。费用、限制、确认、暂停和战果等后果必须说清楚；用于比较人选的属性数值也须保留。

- 用户继续指出廉价感，并提出字体可能是原因。此前实际渲染为楷体标题和微软雅黑正文，字体混用、较小字号及多重阴影缺少连贯层次。当前候选改为同一家族的宋体层级，不把字体调整等同于整体美术已获认可，也不声称这是《三国志11》使用的字体。
- 标题、正文、按钮、日期与数值统一使用随游戏提供的 Noto Serif SC（CSS 别名 `Sango Serif`）；`--ui-font-title` 与 `--ui-font-display` 引用 `--ui-font-body`。WOFF2 为完整字体的压缩格式，保留30,928个字符映射与200–900可变字重。真实字体、来源和许可一起维护；只在字体异常或缺字时使用系统宋体回退。
- 正文16px、500字重；按钮和页签16px、600字重；姓名与表头650字重；窗口标题24px、700字重。辅助14px、次要注记12px、章节18px、页面标题30px。手机矮横屏窗口标题20px、表格14px；战斗模型上的既有紧凑数值规范独立保留。
- 标题字距0.08em，按钮及页签0.02em；正文保持自然字距、1.6倍行高。标题仅留轻微落影，按钮不加文字阴影，不用多重描边冒充字重。
- 间距以4、8、12、16、24px为基本级。列表优先通过对齐与分隔线组织，不把每一行做成独立大卡片。
- 普通控件最小38px，触屏42px；触屏应压缩周边留白而非缩小命中区域。表格行高遵循同一设备规则；宽表在容器内滚动。名册去掉重复竖线，依靠列对齐、弱横线与交替行组织信息，保留滚动和冻结列。
- 数值对齐并使用等宽数字；同一列名称、单位和精度保持一致。
- 选人列随任务区分，具体字段见[行动流程中的选人信息表](玩家行动交互流程.md)。矮横屏将查找与人数并排，收起重复标题和单选人选条；候选区须直接露出完整人选行，宽表在自身容器滚动，不把候选挤到窗口外。
- 时间控件使用进行、暂停、开战、继续战斗与变速，不显示推进一天、推进本日、单步或十步等模拟操作。日期保留在日历位置，交战天数保留在战况中。

## 共享组件约定

| 组件 | 当前接口 | 要求 |
| --- | --- | --- |
| 窗口 | `modal` / `detail-source-panel`；样板 `ui-panel` | 云纹镶框、烟灰题栏与墨绢正文；玉绿限于功能选择；统一遮罩；宽度和靠侧位置由业务决定 |
| 标题与底栏 | `modal-header` / `modal-footer` | 标题说明对象；底栏放提交、取消或返回；关闭与指引保持相同位置与造型 |
| 按钮 | `button`；样板 `ui-button` | 默认次要按钮；`primary`只表示当前主要确认；禁止仅靠颜色表达危险后果 |
| 图标按钮 | `close-button`、工具栏；样板 `ui-icon-button` | 清晰同线宽图标，有可访问名称，触屏足够点击面积 |
| 页签 | `directory-tabs` / `info-tabs`；样板 `ui-tabs` | 选中以深绿底、浅字、底线共同表示；使用真实`aria-pressed`状态 |
| 名册 | `personnel-table`；样板 `ui-table` | 共用表头、交替行、悬停及排序样式；保留既有冻结列、筛选与滚动行为 |
| 表单 | 原生`input` / `select` / `textarea` | 深色凹入底，清楚标签、焦点、错误说明；输入态不可与禁用态混淆 |
| 加载 | 原生`progress`；场景窗口`dialog.scene-loading` | 共用窗口材质与铜金进度；可计量时显示真实完成项，其他阶段保持等待状态，不模拟百分比 |
| 帮助与提示 | `page-guide-*` / `toast` | 同一材质与文字等级，提示不以额外皮肤覆盖内容 |

每个交互组件必须核对默认、悬停、按下、选中、禁用和键盘聚焦状态。减少动态效果偏好关闭装饰过渡。不得用变换位置造成工具栏跳动。

## 人物与地图的界面接入

同一列表或选择组使用统一取景。头像采用头肩，事件优先半身，人物详情可用全身；缺图回退仍须遵守同组的头像比例、底色与边框。是否有新母图不应改变同屏人物的脸部大小。不得用CSS拉伸人物比例。

地图预览使用真实地图数据，与实际地图保持水陆、城池和通道对应；显示精度可以简化，界面配色、标签和地点符号须统一。军团、敌我和状态的语义色保持可辨。人物原画、建筑、模型的质量调整另行执行，不能把统一窗口样式等同于美术全库已完成整改。

战斗部队详情复用同一窗口、按钮和字体，业务布局采用右侧紧凑简报：兵力、战意、护盾及战法次数优先，状态按实际效果查看，完整属性、计算来源和个人羁绊折叠。手机横屏面板保留约56%的战场宽度。关闭与“返回战场”保持暂停，“继续战斗”明确恢复；战前和援军军议仍使用原有确认。

## 新增与修改流程

战后回放使用同一窗口与表单样式，清楚区分“当前世界”和“回放”时间。原生时间条在拖动中保持原元素与焦点，只更新历史画面；回放倍速独立于实时推进。地图沿用实际战场地形，部队标记采用实际势力色，回放界面不提供军令或历史续战入口。

1. 先阅读本规范和样板。选择现有组件；业务布局只改变大小与排列。
2. 颜色、字体、边框、间距和控件状态引用公共变量。需要新公共变体时，在 theme、本文和样板中一起增加，不复制一套页面专用皮肤。
3. 使用实际内容检查短名、长名、空数据、禁用、资源回退、窄横屏和滚动；查看操作保持存档不变。
4. 运行 `npm run ui:style:check` 和 `npm run verify:ui-style`，目视查看生成截图。字体检查须确认实际渲染的字形来自随包字体，不能只检查 CSS 家族名；截图须等待字体加载。常规 `npm run check` 已先执行公共样式检查。样式检查不能代替功能验收。
5. 影响玩家手册的实际画面时更新对应截图，并依[手册维护流程](玩家行动交互流程.md)记录真实核对结果。不得批量认可未检查的旧截图。

当前接入覆盖公共窗口、管理表格、按钮、表单、页签、模式与剧本入口、历史战役卡片、战略工具及战斗信息框。测试抽查桌面与手机横屏，不宣称每个业务子组件或全部美术已经逐一验收。后续发现的旧局部覆盖应回到共享样式修正。
