# 敌方首发与补位择序

当前实现入口为 `engine.mjs` 的 `fillSlots` 与 `battle-ai.mjs` 的 `rankEnemyReserves`。

- 每方通常同时上场至多六队，奸雄任军团长时其军团可用第七名额；敌方在首发及产生空位时，从已到达、存活且可合法落位的预备队中择序，玩家按既定队列。
- 每补入一队重新评估当前分工；考虑现役兵力、属性、已学战法、前排与支援需求、可见敌军构成及攻城条件。有敌方城门或当前实际起作用的战斗设施时，考虑部队已携带的攻城器械，不授予新装备；设施价值共用[建筑选敌规则](内政战场建筑.md)。
- AI 不把羁绊点数、凑档、保档或替补进场后的组合收益计入选队评分；保留简单布阵和当前已生效效果的运用。偶然激活的羁绊正常生效。玩家可以按实际羁绊安排首发和后备队列，承担核心溃败后掉档的风险。
- 不提前到达；在场部队按[战前撤离条件](部队撤离与战前设置-规则65.md)实际离场后才腾出名额，不改变持久部队数组和行动顺序，不提供额外行动。断援、撤退、水陆通行及占位限制继续生效。
- 不选择、替换、重抽或重排战法。择序与初始格位规划是不同步骤，均遵守共同引擎。
- 评分细节以当前函数为准，不保留旧兵种与旧战法的评分副本。军略独立使用[固定条件触发](军略AI固定条件触发.md)。

行为验证检查合法到达、通常六队、奸雄七队上限、缺前排补位、非均分兵力、支援条件、存读档和玩家队列不变。平衡对照遵守[当前验收目标](战斗平衡优化目标.md)。
