# 武将多场景美术流程

当前规范参考三国志系列的克制人物表现，按用途分别生成头像、全身立绘、半身像和横幅场景。神态尽量中性、动作自然舒适；不同场景通过坐立、道具、视线和构图区分，表情只做细微变化。首批曹操、关羽、诸葛亮各十一张；实际完成数量以 `npm run art:officers -- status` 和运行时清单为准。

用户已确认从全人物队列连续分批推进，目标为832人、9152张。当前任务的续跑沿用同一项目与美术规范，实际完成数由文件哈希、当前规范与身份依赖确定，不按提示词数量或候选图数量宣称完成。

## 先确定人物类型

制作顺序固定为：读取稳定ID的身份与传记 → 记录美术主类型、次类型、依据与仪态 → 面部身份设计 → 服饰道具与十一场景动作 → 生成与审阅。类型记录在 `art-direction.json` 的 `profiles[id].role`，字段为 `primary`、`secondary`、`evidence`、`bearing`，有个人道具例外时使用 `propExceptions`。没有类型的任务标为 `blocked-role`，不输出生成提示词、不登记新素材。

| 主类型 | 代码 | 场景设计重点 |
| --- | --- | --- |
| 武勇将领 | `martial` | 军职站坐姿、近身兵器、装备检查、营防与补给；勇武不靠咆哮 |
| 战场统帅 | `commander` | 部署、巡视、组织军务；儒雅也保留军事职责 |
| 谋士军师 | `strategist` | 研判、观察、建议和军务统筹；不统一配羽扇 |
| 文臣学士 | `civil` | 依官职处理政务、编纂、记录或外交；不自动着甲冲锋 |
| 君主领袖 | `ruler` | 治理、接见、检阅和统领，保持个人领袖气质 |
| 特殊职能 | `specialist` | 先写明具体职能，再选择相应工作与道具 |

分类依据人物身份和传记，明确区分史实与演义。名册的 `type` 是战斗兵种，不是人物美术类型；不能用“智力高于武力”、能力排名、性别或阵营推断。主次类型允许文武兼备，不把人物僵化成只会一种工作。

中性指表情和动作幅度，不能把所有人画成执笔、拢袖、捧书的学士。阿会喃的演义身份为孟获部下、第三洞元帅，按武勇将领兼战场统帅设计：内政检查军需，外交以军职仪态听取意见，奏报可以口头汇报，告急可以在营地听军情。普通人类比例与原身份脸保留，不添加族群刻板造型。韦昭、伊籍、尹默依实际职能保持文职，周瑜则为儒雅统帅。关羽读春秋有传记依据，可用于合适场景；允许这样的个人例外，不让文书贯穿武人的全部动作。

生成提示词使用类型对应的场景工作，个人表演设定仍必须符合已记录的类型。审阅首先检查角色气质和职责，再检查中性神态、脸部一致性、手部、装备与构图。脚本只验证类型记录存在，角色契合仍须目视审阅。

## 素材规格与代码入口

| 素材 | 原图目标规格 | 自然姿态、神态与用途 |
| --- | --- | --- |
| `portrait` 独立头像 | 1024×1024，1:1 | 近正面头肩像，眉眼放松、嘴唇轻合、目光沉静。用于名册、选将、小名牌、羁绊贡献者、君主小头像与地图标识 |
| `detail` 全身立绘 | 1024×2560，2:5，真实透明 | 完整头饰至双脚，重心稳定、自然站姿，手臂放松或低位持标志物。武将详情、生平、势力大展示 |
| `domestic` 内政半身 | 1152×1536，3:4 | 依职责办理城务、军需或研究；武人可检查补给，文臣可读写账册，不默认统一执笔 |
| `inspection` 巡视横图 | 1536×1024，3:2 | 自然观察现场；衣装、道具和手势符合本人类型，不统一持卷拢袖 |
| `training` 训练宽图 | 1792×1008，16:9 | 武人检查装备，统帅监督整军，谋臣检查部署或器械，文职办理训练记录 |
| `diplomacy` 外交半身 | 1024×1280，4:5 | 轻微转头接洽或听取意见；武人保留军职仪态，文臣依使者或官职身份接待 |
| `command` 指挥宽图 | 1536×864，16:9 | 统帅部署、谋士研判、武将判断营防、文臣军务辅助；道具依据个人职责 |
| `travel` 行旅全身 | 1024×1792，4:7 | 普通小步行走、目光沿路、完整双脚，衣摆轻微运动，持物贴近身体 |
| `report` 报喜横向半身 | 1536×1152，4:3 | 自然口头汇报或使用本职记录；不默认每人双手捧卷，轻微满意、嘴唇闭合 |
| `report-concern` 告急近景 | 1152×1536，3:4 | 听取消息或审视单份急报，仍沉着克制；武人不默认置身书斋阅卷 |
| `battle` 战斗宽幅人物 | 2048×1152，16:9 | 武人稳健警戒、统帅督战、谋臣筹划、文职阵后辅助；标志物因人而异，神态中性 |

尺寸是目标分辨率，导入接受相同比例附近的高分辨率原图，记录生成器实际尺寸。每张独立生成取景、自然姿态、头朝向、道具和视线，不将同一原图裁剪成不同规格。脸型、年龄、胡须、头饰、体型、主色与标志物保持一致，表情差异控制在自然中性范围内。

中性和自然优先于表情差异。禁止怒吼、露齿、大笑、惊慌瞪眼、挑眉鬼脸、抓须扶额、向镜头伸掌、大幅挥击、伸臂指点、扭身、飞扬披风和夸张透视；不用这些动作强行区分场景。系列参考入口为 [三国志11官方武将介绍](https://www.gamecity.ne.jp/sangokushi/11ps2/warriors/)，项目素材继续使用独立原创身份与构图。

具体规格与场景选择函数集中在 [officer-art-scenes.mjs](../officer-art-scenes.mjs)；人物类型、视觉身份卡、逐人物场景表演与QA清单在 [art-direction.json](../assets/officers/art-direction.json)，生产提示词的类型校验和场景工作在 [officer-art-roles.mjs](../scripts/officer-art-roles.mjs)。

## 对应现有代码

名册、选将和战场小名牌由 `officer-roster.mjs`、`army-setup-view.mjs`、`battle-labels.mjs`、`bond-hover.mjs` 显示独立头像。小地图的行军、运输与使臣标识也使用独立头像维持辨识度；人物的完整行旅、外交、指挥图用于详情和实际场景。

`campaign-info.mjs` 的人物详情与君主大展示使用全身立绘，行动记录页按真实当前行动选对应场景；太守使用内政图，军团长与部队指挥详情使用指挥图。`city-scene.mjs` 的建筑上小标识用头像，建筑人员详情根据真实事务选择内政、巡视或训练。`diplomacy-view.mjs` 使用方案真实执行人的外交半身像。

`domestic-feedback.mjs` 从真实节点选择报喜或告急。失守、败退、被俘、灾情、受阻与离职预警用告急，平静或成功事项用常规报喜素材；没有对应武将的事件继续使用纪事标识，不能虚构汇报人。`ability-cues.mjs` 的发动卡展示宽图，`battle-effects.mjs` 的切入保留完整宽幅人物，文字置于另一侧的渐暗区域。

当前普攻、移动、受击、溃败仍由兵种队列、图集与状态特效表现，不为832人重复制作人形动画。俘虏和已故人物不因为显示图而变成正在出战；未侦察人物继续隐藏身份。

## 批量流程

固定入口为 [sango-officer-art skill](../.agents/skills/sango-officer-art/SKILL.md)。仓库中的 skill 是维护源，`npm run skill:officer-art` 将它安装到当前用户的 Codex skills 目录，安装副本与维护源校验一致。后续可使用 `$sango-officer-art` 直接接续；规格和逐人物设定仍以项目源文件为准。

批次工具默认每批3人，首次扩展批为刘备、张飞、赵云、孙权、周瑜、司马懿6人。先检查 `art-direction.json` 的 `roleReviews`，显式 `needs-rework` 场景优先返修，即使旧批次已经结束；随后 `plan` 优先恢复未结束批次，再按优先名单和全人物目录选择缺图人物。完整人物跳过，只有部分场景的人物继续完成剩余素材。状态从 `blocked-role`（缺人物类型）、`blocked-master`（缺已审阅头像）或 `pending` 到 `candidate`，目视审阅接入后才进入 `complete`。批次记录位于 `assets/officers/batches/`，候选原图位于 `assets/officers/candidates/`；运行时只使用通过审阅的原图。

角色返修保留正确的已审阅身份图。每张独立重绘并保存实际结果JSON和提示词，目视确认后将旧PNG和旧凭据归档到发行包以外，再用 `officer-art.mjs import ... --approve --replace --prompt-file ...` 接入；实际完成后才把对应 `roleReviews` 场景标为 `complete` 并记录新SHA。仅修改动作描述不能算图片已修复，也不能改写旧图参考哈希。阿会喃的内政、外交、报喜、告急四图已按武勇将领兼战场统帅重绘、目视审阅并接入；旧PNG和凭据已归档，正确的头像与其他合适场景保留。

```text
npm run art:batch -- status
npm run art:batch -- plan --limit 3
npm run art:batch -- record <批次ID> <生成结果JSON>
npm run art:review-batch -- <批次ID> --portraits
npm run art:batch -- accept <批次ID> --reviewed --scenes portrait
npm run art:batch -- plan
npm run art:review-batch -- <批次ID>
npm run art:batch -- accept <批次ID> --reviewed
npm run art:batch -- finish <批次ID>
```

生成结果JSON须包含 `officerId`、`scene`、生成器实际保存的PNG `file`、实际完整 `prompt` 和任务中的 `referenceSha256`。新身份优先使用准确对应本人的既有头像作为面部结构参考，无对应参考才不传输入图；已有身份的后续场景只用本人已审阅原创身份图，按任务刷新后的参考路径和哈希生成。内置工具的 `image_url` 可能是data URL，不能当作文件路径；从 `output_hint` 获取保存路径。`record` 检查后复制候选原图但不接入；`accept --reviewed` 表示操作者完成目视QA，Codex可自行完成，不额外要求用户逐图确认。各次登记和接入顺序执行，避免同时改写同一批次记录。

### 面部辨识度

`node scripts/officer-art-face-references.mjs --officers <人物ID>` 按本机资源清单中的准确人物映射解析现有头像，记录原文件路径及SHA，写入忽略的 `.local/officer-face-references.json`，不复制原素材到发行包。当前可解析713位人物，119位没有对应本地参考；缺失时须单独设计并检查面部差异，不能借用同名或其他人物的脸。

先目视参考图，提取脸长宽、额头、颧骨、下颌与下巴、眼形眼距、眉形、鼻梁鼻尖、嘴形和胡须，再用我们的画风重绘。保留面部辨识度，放松参考中的怒眉、吼叫或夸张神态；不能只更换帽子、衣色而复用模板脸。首批重点修正赵云与周瑜：赵云长矩形脸、明确下颌、较深眉眼和较宽直鼻；周瑜收窄下颌、细弧眉、较开阔眼形和较窄鼻梁。每批头像与相近已完成头像并排比较，再作为各自场景的统一身份参考。

真正换脸后，旧参考哈希的候选自动标为 `stale-identity`。重新生成该人的依赖场景并保留旧候选记录，禁止把旧图的参考哈希改成新身份来冒充一致。身份更换时自动按真实SHA存档旧原创身份；可用 `identity ... --approve --replace --reference-record <结果JSON>` 关联实际提示词、直接参考输入及来源链，核对输入哈希后登记。来源记录、旧身份和原始参考均不进入发行包。

`finish` 检查每人十一张全部接入后结束批次，并刷新全库队列及画廊。后续续跑读取当前批次和已有候选，接续缺失任务；不重复生成已接入图像。每轮完成可管理的范围，真实工具故障、额度限制或需要用户决定的质量阻断须保存已有结果并报告，不静默改用API。全库当前格式完成后停止续跑。运行本机续跑时保持桌面应用运行且项目可访问。

```powershell
npm run art:officers -- plan --officers cao,person-99,person-290
# 全库832人，每人11张，共9152个任务
npm run art:officers -- plan --all
npm run art:officers -- next --all
npm run art:officers -- status --all
```

每个任务记录人物ID、场景、画幅、透明要求、表演提示词、身份依赖与目标路径。使用内置 imagegen，每条任务独立调用，不把一套人物拼成一张图，无需API密钥。

1. 先审阅原创身份参考，保存脸型、年龄、头饰、胡须、体型、服饰主色与标志物。第一批沿用此前原创身份图；新人物可先生成并审阅独立头像作为身份参考。
2. 为每人补充逐场景自然姿态、道具和视线，结合文武身份。参考图只锁定身份和画风，不锁定皱眉；嘴唇闭合、眉眼自然，中性神态优先。不能只在统一提示词后换背景名。
3. 生成独立头像并审阅，再按各场景规格生成其余图像。立绘请求真实透明背景，所有可见肢体与双脚完整。
4. 同一人物全部图片并排检查，拒绝怪异神态、夸张手势、解剖异常、同姿换背景、文臣挥刀、尺寸不符或白底伪透明。表情可以保持克制相近，通过姿态、视线、道具和画幅区别场景。
5. 导入时记录实际使用的提示词；检查画廊原始比例和实际游戏入口。

```powershell
# 第一批已审阅原创身份图，也可通过导入独立头像建立新人物身份
npm run art:officers -- identity cao "C:\生成目录\身份参考.png" --approve
npm run art:officers -- import cao portrait "C:\生成目录\头像.png" --approve --prompt-file "C:\提示词\头像.txt"
npm run art:officers -- import cao detail "C:\生成目录\全身立绘.png" --approve --prompt-file "C:\提示词\立绘.txt"
npm run art:officers -- import cao battle "C:\生成目录\战斗横图.png" --approve --prompt-file "C:\提示词\战斗.txt"
npm run art:officers -- gallery
```

`--approve` 表示操作者完成中性神态、自然姿态及身份一致性的目视QA。程序检查PNG、各场景比例、尺寸、立绘实际alpha透明、稳定人物ID和身份哈希，不能自动判断神态及解剖质量。已有同规范的不同素材需明确使用 `--replace`；更换身份参考后引用旧身份哈希的素材停止接入，须重新生成或重新审阅。

当前批次的新头像若在放大审阅时发现冠顶裁切，可使用既有身份参考生成取景修正版，审阅后通过原始导入工具的 `--replace` 接入。保留原身份参考和实际哈希，不因增加画框留白更改其他图像的生成来源。高冠头像须在最高点上方保留可见背景；真正改变人物身份才需要复核全部依赖场景。

## 保存、展示与验证

当前原图在 `assets/officers/generated/v3/<武将ID>/<场景>.png`，运行时清单是 [manifest.json](../assets/officers/manifest.json)，实际提示词与QA记录是 [receipts.json](../assets/officers/receipts.json)。身份参考在 `assets/officers/identity/`，身份摘要在 [identities.json](../assets/officers/identities.json)。[画廊](../assets/officers/gallery.html) 按真实画幅展示，透明立绘显示检查底纹，点击可查看原图。

这些 `assets/...` 路径属于素材工作目录，可通过 `SANGO_ASSET_ROOT` 或 `.local/assets.json` 挂载独立目录；生产工具、审阅页面、服务和打包工具共用该配置，详见 [美术资源接入](美术资源接入.md)。生产记录的虚拟路径由 `asset-workspace.mjs` 解析，生成时使用任务中的 `referenceFile` 读取真实身份文件。主程序只消费公开清单，发布素材包排除身份、提示词、候选和批次。

运行时根据图像元数据选择比例、完整显示或头像填充。全身立绘使用contain并保留双脚；横图保持宽幅，不能裁回竖幅。缺图回退到该人物独立头像、原创详情或本地头像，再显示姓名标识。浏览、图片加载和显示开关不写入规则、日期、任职或存档。

发行包只复制当前清单引用的原创图像；不复制旧批次、身份生产记录、候选图、提示词、任务队列、本机配置和外部试玩素材。原图在实际访问时进入离线缓存，首次安装不预加载全人物的大型图像库。

```powershell
npm run test:officer-art
npm run art:verify-officers
npm run docs:check
npm run build:release
```

界面验证使用项目既有Playwright环境；游戏和规划、导入工具不依赖它。`plan` / `status` 可以恢复批次；已审阅且格式版本、身份哈希和文件哈希一致的任务标记完成，其余明确保留待生成。
