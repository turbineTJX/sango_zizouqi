## 游戏中的使用

点击「武将」打开完整名录：姓名、字、编号搜索；来源筛选；统率、武力、智力、政治、魅力排序；每页 24 人。详情展示资料、适性、关系、生平和可展开的原始字段。

选择 1～6 人，点击「以此阵容开始试炼」。全员 10 级、每队 3000 人，对阵六队陪练；首位任主将、智力最高者任军师、其他人中武力最高者任副将。重开保持所选阵容；存档与战略进度分开。陪练用独立编号，选择袁绍等原敌方武将不会造成编号冲突。

仅将人物加入目录，不自动把 835 人塞进战略军团；原战略阵容保持 15 人，招募系统仍未实现。

## 字段和技能规则

- command → leadership；strength → force；intelligence → intellect；politics → politics。原有 15 人也采用参考库数值。
- glamour → 目录中的 charm；只用于展示／排序，战斗仍使用四维，未增加魅力公式。
- 新人物初始兵种按最高适性选枪／骑／弓，戟并入枪、源弩适性用于弓；相同适性按枪、骑、弓顺序。规则 8 将夏侯渊的新默认兵种改为后排弓兵、沮授改为后排弩兵，其他原有武将沿用既有兵种和阵位。适性本身完整保留。
- 当前游戏的等级从 1 开始、忠诚初始 100；源等级和源忠诚完整保留于 source，资料页显示原值。
- 原 15 人保留现有五技能成长路线、专用战法和军略。其余 **820 人的专属技能、被动成长路线、武将军略全部暂空**，升级不会自动补通用被动。参战可使用兵种通用战法。
- 原库 FeatureList 仅保存，不据其编号移植 Unity 技能，不加入上一轮讨论中的新专属效果。
- 人物关系现用于连携概率；性格、年份、归属等仍为资料，尚不作为外交、登场或战略归属机制执行。

## 人物资料正式字段（数据版本 2）

835 人的以下字段已进入本项目目录、武将实例、战斗实例和存档，后续功能可直接读取，不再依赖解析 source。

| 字段 | 含义 | 来源 |
|---|---|---|
| personality | 性格编号 | personality |
| righteousness | 义理编号 | argumentation |
| compatibility | 相性数值 | compatibility |
| sex | 性别，0 男／1 女 | sex |
| birthYear | 出生年 | yearBorn |
| deathYear | 死亡年 | yearDead |
| relations.fatherId / motherId | 父亲／母亲，游戏武将 ID 或 null | Father / Mother |
| relations.spouseIds | 配偶 ID 数组 | SpouseList |
| relations.swornSiblingIds | 义兄弟 ID 数组 | Brother 结义组及明确的义兄弟列表 |
| relations.likedIds / dislikedIds | 亲爱／厌恶 ID 数组 | LikePersonList / HatePersonList |

性格与义理的中文名称由导入脚本从 Personalities.json、Argumentations.json 生成 data/officer-traits.mjs。仅导入名称，不执行参考项目的忠诚或计略修正。编号 0 显示“未设置”，缺省标量用 null、显示“未载”；相性为 0 时保留实际数值。

Brother 是结义组组长编号：同组人物展开为完整同伴列表，去重、排除自身。例如刘备显示关羽与张飞，关羽显示刘备与张飞；不会把刘备自己显示为自己的义兄弟。亲爱与厌恶保持来源方向，不自动补为双向；关系只按 ID 关联，不合并同名人物。自建人物编号单独处理。

父母关系未记载时用 null，其余未记载关系用空数组；界面显示“未记载”。每个实例拥有独立关系数组，修改某实例不会污染目录或另一实例。未收录引用保留 ID，不擅自补造人物关系。

武将名录的资料页，以及部队属性页折叠的“人物资料与关系”都能查看这些字段；点击关系人物可跳转其资料。关系值现已按类型分档并接入连携概率，可在资料页查看、调整当前关系及分值并保存；初始血缘与关系记录保留，具体关系事件尚未自动绑定；其余仍为只读预留数据，不增加相性修正、性格 AI、义理叛变或生卒年事件。

验证：155 项自动化测试及语法检查通过。新增验证覆盖全库字段映射、零值、完整结义组、实例隔离、缺失字段拒绝、损坏存档拒绝，以及修改预留字段不改变战斗结果。浏览器核验刘备资料和跳转关羽，关系正确、未发现脚本错误。
