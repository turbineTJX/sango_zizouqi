# 敌方出阵择序与验证（规则41）

日期：2026-09-19。固定阵容和学习记录后，敌方现在会在首次出阵及每次出现空位时挑选合适部队，而不再简单取名单里第一支预备队。规则40的随机学习、已学战法顺序、双方战斗数值与军略评分保持不变。

## 选择时点与边界

- 入口为 `engine.mjs / fillSlots`，每方仍最多六队；只有敌方 `side=1` 调用 `rankEnemyReserves`。普通战斗、试炼及战略战斗中敌方均走该入口，战略来援追加进预备队后同样适用。玩家侧包括战略自动托管的我方仍保持原队列。
- 每次只考虑当前已经到达、存活且处于预备状态的部队。每成功补入一队，重新计算在场组合再选择下一队。无合法落位格时尝试其他候选。
- 没有空位就不择序；断援仍有效或全军撤退时不补位。不会换下在场部队，也不会赋予已过行动阶段的部队额外行动。
- 不修改持久化的 `units` 数组顺序，因此不会借出阵排序修改逐步先后手。原军团编制、首发标记、波次身份、到达时刻也不被改写。
- 学习记录与战法列表只读；不重抽、不换装、不重排战法。评分不用随机数，读取同一快照会得到相同选择，存读档后继续确定性运行。
- 如果合法候选不超过空位数，最终仍全部入场，主要收益来自候选多于名额的场合。六队以内的自由对战不会凭空多出首发选择优势。

## 决策依据

先计算在场部队与当前候选的能力。使用真实现役兵力缩放的面板，并在比较时排除已占格部队独有的地形位置加成。

| 指标 | 当前启发式定义 |
| --- | --- |
| 输出潜力 O | `max(攻击×3/普攻间隔, 已学物理进攻战法时的武技威力×0.9, 已学智力进攻战法时的谋略威力×0.9)` |
| 承伤体量 B | `现役兵力×(1+防御/100)` |
| 支援潜力 A | 有已学支援战法及其他队友时取 `max(营务威力, 谋略威力)`，否则为0 |

支援识别来自已经学会的效果，不是兵种名字：救护、策应、鼓舞、净化、幻卫、协阵、阵枢及支援专属等可提供支援价值。修缮要求友方有活建筑；接舷要求同批候选或在场存在其他舰船；协阵要求有其他近战友军。无这些条件不会凭空给出对应支援分。

令 `d=O/本轮最大O`、`b=B/本轮最大B`、`a=A/本轮最大A`，分数越高越优先：

| 项目 | 分数 |
| --- | --- |
| 基础 | `55d + 20b + 5×min(1,智力/100)` |
| 枪戟补前排 | 候选加在场总数至少4时希望有2队枪戟，否则1队；未达到时 `28√b`，已达到后 `4√b` |
| 枪戟克制骑兵 | `16×敌方在场骑兵兵力占比×d` |
| 有非辅兵近战保护的后排 | `10d` |
| 骑兵突击与正面风险 | `(14×敌后排兵力占比−14×敌枪戟兵力占比−地形惩罚)×d`；森林/沼泽惩罚4，其余0 |
| 支援补缺 | 在场无支援时，有非辅兵近战则 `34a`，否则 `12a`；已有支援时，存在低于初始80%兵力的在场队为 `12a`，否则 `4a` |
| 攻城兵器 | 本方为攻城方且敌门仍活时 `28d`；已学冲车再加 `12d` |

同分按武将 ID 稳定排序。对面的克制构成只统计当前在场敌军，不预判未来随机数，也不提前利用未到场敌军作为当前威胁。

这是一套可解释的局部启发式：前排不足时提高枪戟价值，但不会不看兵力就强行把几十人的前排放在数千人的主力之前；有主力后适当补支援，但不会连续塞满辅助。它没有试打搜索最优阵容，也不保证每局优于原名单顺序。

## 初始化时序修正

原关卡流程先填满六队，随后才设置援军波次、城门。若直接在旧位置加入择序，会把尚未标记为未来援军的强队提前选上场。

现在场景通过 `startBattle(..., {deferEnemyDeployment:true})` 暂缓敌方首次入场，在地形、援军时间和城门设置完成后调用 `fillSlots` 与自动布阵，再恢复明确的关卡站位并给真正的守方首发护盾。明确站位只应用于实际在场者。战略战斗也先完成地图地形、补给及城门初始化再选敌方首发。

## 行为与回归

- 新增8项出阵测试：后置主力入首发、缺前排补前排、支援与非均分兵力、攻城兵器、援军/断援/撤退、无合法船位与水陆占位、真实补位后的确定性续战、玩家队列保持不变。
- 原守城测试去掉“第一支预备队一定补位”的旧假设，仍检查实际补入部队没有错误继承首发护盾。
- 全量测试 **523/523通过**，`npm run check` 通过。

## 固定种子的配对对照

冻结本次评分后，用独立的 `841100–841115` 共16个学习/战斗种子，覆盖六种阵容，共96对、192局。两组使用相同武将、兵力、学习结果、战法顺序、布阵器、军略策略和战斗引擎；基线只将 `fillSlots` 的选择表达式替换成原始 FIFO。每局校验六队上限，以及战法、学习记录、部队行动数组顺序未被改写。

双方军略均按同一评分策略执行；我方由脚本在步间下令，敌方由引擎在步末下令。基线与优化版采用完全相同的这一时序。

| 场景 | 基线敌方胜/16 | 择序后敌方胜/16 | 基线平均敌方剩余比例 | 择序后平均敌方剩余比例 |
| --- | ---: | ---: | ---: | ---: |
| 低兵力队排在主力前 | 0 | 2 | 0.06% | 3.76% |
| 六后排在前、枪戟在后 | 0 | 1 | 0% | 1.21% |
| 普通混编 | 0 | 0 | 0% | 0.18% |
| 对方骑兵为主 | 0 | 0 | 0% | 0% |
| 攻城兵器排在预备队 | 7 | 9 | 16.85% | 24.66% |
| 水陆混编 | 0 | 1 | 0.62% | 1.94% |

总敌方胜局从 **7/96增加到13/96**。以胜、和、负排序逐种子比较，10对改善、3对变差、83对胜负等级不变；这些混编场景本身偏向我方获胜，不能据此推导全游戏的总体 AI 胜率。

具体改善示例：低兵力场景基线首发中有3队仅150兵，择序后由6队2600兵组成首发；全后排场景补入了枪、戟；攻城场景让原来在队尾的两队兵器首发。对骑兵的样本仍全部失败，说明克制偏好没有消除阵容、武将与学习差距。保留所有失败与变差样本，不为追逐这批验证胜率追加调参。
