# AI 自主迭代与验证规则

更新日期：2026-10-30。接入状态：已接入战略迭代协议、冻结与证据工具、真实模拟工作进程、独立裁判及本机采用入口。本文描述工具能力，不声明当前游戏 AI 已通过完整可玩验收。战斗领域见[战斗AI循环验证设计](战斗AI循环验证设计.md)：首轮策略工具已接入，完整领域能力与尚未实现部分以该专题状态为准。

## 用户确认的边界

允许改进参数、策略代码与决策架构；公共游戏规则变更另行讨论。默认每轮最多8小时，可跨新一轮继续同一冻结候选的剩余实验，但不能重抽已经登记的样本。允许逐步晋级，并自动采用到本机；不自动推送或发布。优先保证战争持续推进、成本可承担、没有明显可反复利用的弱点。完整前中后期体验与统一收尾分别报告，统一不作为前者的必需前提。

战略候选固定战斗 AI、共同引擎、技能、羁绊、资源和道路规则。旬初每10天使用当时本方人员、物资、视野及带日期报告重评；旬内执行军令与紧急复核，保留仍可行的计划。战略决策不调用战斗 AI 试打、不读取未来随机结果。双方行动与结算共用，AI 不主动规划羁绊，不增加单队微操。

## 工具和编码代理怎样共同工作

2026-10-29 用户澄清：8小时仅为允许自然长局的计算上限，首要目标是优化 AI。优化循环先做针对性复现、相关回归和短窗自然对照；未触发或无实际收益的方向应尽早停止，回到问题诊断。有实际改善证据后再投入完整长局。不得为跑满预算持续等待无信息增量的实验；短诊断仍不等于完整可玩验收，既有封存结果不重新标记。

当前编码代理负责阅读失败、提出可证伪假设、修改候选源码和复核权限边界。命令行负责登记、封存、运行、度量、判定和安全采用。它不调用外部模型生成补丁；用户在聊天中发起“按验证协议运行一轮战略 AI 迭代”后，编码代理按下述步骤连续执行，直到预算、连续无改进上限或本次目标结束。

1. 查看当前工作区，运行 `init`，保留未提交的实际源码作为基线。素材和已有工作不移动、不删除。
2. 从既有报告、自然失败存档或新的诊断提出一个明确问题。先运行 `propose` 登记主目标与假设，再进入返回的 `editRoot` 修改策略。
3. 编码代理复核差异：是否仍使用合法情报和共同执行入口，是否保持旬初重评与有效承诺，是否通过改变资源、战斗、随机或测试获得优势。完成后运行 `seal`，提供具体复核说明。源码复核说明不能替代独立行为测试。
4. 按登记的层级验证：已复现缺陷走修复对照、相关回归与独立短窗；全局策略收益走开发冒烟和完整独立验证。失败先检查真实记录和失败存档，不调整裁判让结果通过。不通过的候选保留，下一假设创建新候选。
5. 验证通过后由命令行自动尝试本机采用。遇到共享工作区变化，保留候选；重新建立真实组合基线并验证后再采用，不能把旧组合的报告继承为新组合通过。
6. 一轮最多8个候选，连续3个完整失败或无改进候选后停止该方向，整理证据。8小时包含编辑时间；不得自动调用 `new-round` 延长当前授权。用户明确继续下一轮后才能开启新预算。

入口：

```powershell
npm run ai:iterate -- init
npm run ai:iterate -- propose --session=<返回目录> --id=prepare-v1 --metric=planCompletion --hypothesis="准备期限遗漏合法运输等待，导致计划无法兑现"
# 仅在返回的 editRoot 内修改策略并复核差异。
npm run ai:iterate -- seal --session=<返回目录> --id=prepare-v1 --review="说明具体改动，以及为何没有改变公共规则、合法情报或战斗依赖"
npm run ai:iterate -- run --session=<返回目录> --id=prepare-v1 --stage=smoke
npm run ai:iterate -- run --session=<返回目录> --id=prepare-v1 --stage=validation
npm run ai:iterate -- status --session=<返回目录>
```

`--seconds=60` 等参数只能缩短本次运行时间，不能突破本轮截止时间。开发冒烟只运行少量机制、双方换边战斗与原始全国短局，永不晋级。`report` 重读封存证据并重新判定，不接受手工填写的总分。`help` 列出全部命令。

## 固定协议与初始判定值

正式机器契约在 [rules.mjs](../scripts/ai-validation/rules.mjs)。这些是首版保守验证初值，不是已确认的游戏平衡数值。协议变更应更新版本并开始新实验；编码代理不能在候选循环中自行放宽。

### 协议2：行为修复层

用户已确认分层采用，优先修复和优化。行为修复通过可自动成为本机稳定版，报告使用 `behavior-repaired`；全局策略收益、完整可玩性和统一收尾均标 `not-assessed`。它证明指定缺陷已修复且在登记的保护检查中未出现不可接受退步，不能声称提高了全局胜率、战争节奏或完整体验。

在编辑候选前，用 `register-repair --session=<目录> --file=<清单JSON>` 登记以下材料：

- `id`、冻结裁判中的 `caseFile`（`scripts/ai-validation/cases/*.mjs`）、基线必须出现的 `expectedFailures`、相关 `tests`。案例导出 `exercise({source,save})` 并返回具名布尔检查。基线必须精确复现预期失败，候选全部检查通过；其他保护项失败不能忽略。
- `reproductionDirectory` 指向带有通过回执、任务、结果与存档字节指纹的原始自然检查点。案例允许定向扰动以检查期限、危局等机制，必须与自然观察分开陈述。
- `windows:[{directory,days}]` 至少两个不同种子，覆盖官渡与赤壁，不能复用复现的剧本和种子组合；每窗至少20天。工具核对原自然来源并复制封存输入。两版从同一字节输入真实续行，验证当前结构与确定性保存；先前版本的自然存档只是共同起点，不继承先前版本的验收结论。

`tests` 至少包含情报、羁绊与道路边界回归，并按改动加入有关行为测试。缺文件、失败、跳过、待办、缺少实际通过用例均不能采用。每个独立短窗分别保护：新增缺粮单位日最多1、结束时真实现役及伤兵不少于基线90%、保有新夺敌城最多减少1；实际整数资源、全AI共同执行及保存续行必须通过。窗口结束前统一或预算耗尽仍保留真实结果，本层不把未完成窗口当作完整保护证据。以上是预登记初值，不能观察结果后放宽。

```powershell
npm run ai:iterate -- register-repair --session=<目录> --file=<清单JSON>
npm run ai:iterate -- propose --session=<目录> --id=arrival-v1 --tier=repair --repair=<登记ID> --metric=planCompletion --hypothesis="真实到齐的集结被旧估值误取消"
# 修改返回的 editRoot，随后 seal。
npm run ai:iterate -- run --session=<目录> --id=arrival-v1 --stage=repair
npm run ai:iterate -- report --session=<目录> --id=arrival-v1 --stage=repair
```

修复层也使用固定源码、受保护裁判、不可改写提案、输入哈希、预算截止、失败留档与原子采用日志。通过后自动尝试采用；工作区变化则保留待采用状态。旧协议1的实验和失败结论保持原样。

### 全局策略收益层

独立验证使用官渡风云、赤壁风云，各8个独立种子，前100战略回合。种子在提案登记时一次生成，排除开发种子，候选和基线配对运行；不同剧本共用一个种子时，统计中归为同一组。每10回合保存一个真实检查点，可在同一冻结输入下续跑。没有抵达的阶段不计通过，提前结束则按真实终局记录，不能补造后期经历。

| 可登记的战略目标 | 最小中位改善 | 每个配对样本允许的最大退步 |
| --- | --- | --- |
| `middleQuietTurns`：完整中期最长无势力战回合 | 缩短1回合；达到12回合后不再奖励继续缩短 | 延长1回合 |
| `hungerExposure`：己方城市与活动军团缺粮单位日／全部暴露单位日 | 减少0.002 | 增加0.002 |
| `planCompletion`：已完成／已结束或已逾期计划 | 增加3个百分点 | 减少3个百分点 |
| `hostileCitiesRetained`：从非中立势力取得、至少保持10天且仍在占领方手中的城市数 | 增加1城 | 减少1城 |

计划没有实际分母时记为未知；不能把没有机会算作满分。取消原因、未完成阶段与输入仍留在存档中，需要按真实局势解释。缺粮并不一律判非法，敌方断粮造成的真实损失保留；同时保护按实际观察天数计算的日均现役兵力，候选低于基线90%则不自动晋级，防止靠大规模裁军伪造后勤收益。逐日耗时95分位不得超过现有桌面8000毫秒预算；测量串行运行，不与本轮其他长局争抢计算。

主目标按种子分组，计算每组不同剧本的配对平均改善，再做单侧精确符号检验；要求中位改善达到上表，且概率值不高于0.05／8。最多8候选的比较额度预先固定，不追加样本跑到显著为止。此保守规则可能返回“证据不足”，不能据此宣布候选没有价值，也不能擅自放宽。每个配对样本的保护指标单独检查，整体平均提高不能抵消局部明显退步。

战斗样本覆盖野战、攻城、关卡、港口、水战，以及远程、骑兵和后备压力阵容。双方使用真实 AI 军议、自动行动与军略并换边，检查合法占位、推进及保存续战。战斗依赖在战略轮内固定，其时长、停滞和胜负仅为接口诊断，不能作为战略主目标或全游戏强度门槛。当前这些固定阵容不是不同版本策略同场的对手联赛。

## 硬约束与五种结论

完整候选必须通过当前每类 AI 决策的具名行为测试，另包含情报、地理、羁绊边界与开场阵法回归。失败、跳过、待办或缺失不能通过。真实模拟使用普通原始剧本、正常迷雾及内政意外，检验整数资源、真实行动、自动军议、保存往返和确定性续行；不注入战争、补给或战果。

报告分别列出：

1. **相对改进**：晋级、淘汰或证据不足。允许旧体验问题仍存在，但不得新增硬失败或超出保护界限。
2. **战略域验收**：完整前中后期、多剧本与独立种子、中期静默目标及有证据的漏洞复核。未覆盖项目仍为缺失。
3. **实际集成**：共同战斗入口、真实自然势力战与战略交接被观察并验证。固定夹具和自然局的结论分开。
4. **整体可玩性**：还需要同一源码组合的战斗领域验收和实际玩家体验证据，不能由自战分数或模型自己的“好玩评分”代替。
5. **自然统一**：只标实际发生的原始自然结局及所属样本；阶段通过不冒充统一，未统一不自动否定前中后期体验。

默认最多100回合，15分钟仅为本次诊断的墙钟上限；第61回合起若已连续300天没有占城且无活动战场，提前停在可检查的存档，标记 `stalled`，不解释为永远不能统一。未完成任务或预算耗尽不会算通过。原始日志和完整输入保留在 `.local/ai-local-campaign/`。这些是构造局部诊断，不能登记为协议2的原始自然窗口、全国统一或全局收益证据；真正策略修复仍按独立验证层采用。

每个候选保存 `report.json`、`report.md`、`failures.json`、逐任务日志、原始结果及适用的失败存档。编码代理按这些失败构造新挑战，先用 `add-case` 登记到本轮问题库，再开始新候选；已登记提案的挑战集不会变化。

挑战 JSON 包含 `id`（以 `challenge-` 开头）、`category`、`reason` 和合法的完整自定义战役 `draft`。工具通过共同 `validateCustomBattle` 检查；输入统一按合成挑战标记，不能算自然战争证据。反复利用的弱点还应保存真实复盘材料。自动发现、缩减反例及多版本策略联赛目前没有实现，不以预留接口声称已具备。

`attest` 可登记战斗领域、漏洞复核和玩家体验的实际外部材料。格式包含 `kind`（`battle`／`challenge`／`player`）、当前候选 `sourceHash`、布尔 `passed`、`reviewer`、具体 `summary` 和 `evidence:[{path,sha256}]`。工具核对每个材料的字节与当前组合，记录追加一次；它不替材料作者作身份认证，也不证明一段自述真实发生过。代理只可登记实际已经执行并有记录的复核，玩家体验必须来自真人反馈，不可自行生成认可。

## 冻结、预算与采用

所有实验产物在忽略的 `.local/ai-iterations/`，不进入发行素材或上传。快照包含当前代码、数据、测试、脚本和文档，不复制素材库、依赖和已有本机输出；测试工作进程沿本机已有依赖解析。候选只能编辑列出的战略文件、对应当前文档或新增 `ai-policy/` 模块；既有测试、裁判、公共规则和战斗依赖受保护。需要扩展实现位置时先修改验证协议的明确边界并重新冻结，不能临时绕过检查。

提案、源码、任务和结果均有指纹；恢复时检查结果及完整检查点字节，不混用版本。工作进程在预算到期后结束，留下未完成状态及已完成检查点；下一轮使用同一提案继续，不能把中断算失败战果或通过。失败任务不靠原地重跑抹掉，需新候选。记录不依赖 Git 干净状态。

采用先核对整个当前代码工作区仍等于候选的真实基线，再逐文件比较并替换明确差异。原始字节保留于基线快照；中断可用 `recover` 恢复，发现新的人为改动则保留冲突，不能覆盖。若进程意外中断留下锁，`unlock` 只允许清理已退出进程的锁；活跃实验不会被清理。没有 Git reset、clean、stash、提交、推送或发布步骤。

指纹和独立子进程防止混用与意外改写，不构成抵抗恶意代码的操作系统沙箱；本机同一账户拥有文件权限。样本分离用于减少调参过拟合，也不声称同账户下的种子绝对保密。发布仍另行运行项目发行验证。
