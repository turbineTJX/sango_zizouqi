# 战役生成器与验证（规则58）

当前共有九种兵种，已删除辅兵，弩兵和兵器使用共享兵科适性。20个预设共用自定义生成器。诊断须针对当前规则重新运行。

## 唯一生成入口

历史战役、演义推演、演武试炼与自定义战役统一使用 `battle-generator.mjs` 的 `generateBattle`。`scenarios.mjs` 只将预设转为自定义草稿，再调用该入口；不再生成虚构武将、超额军团、指定战法或创建后偷偷修改站位。

20 个预设保存在 `data/design/battles.mjs`。历史背景不等于平衡基准；不再依赖旧版自由战法配置的结论。每方一个军团、最多十队，首发至多六队；最低兵力1000，最高服从真实武将带兵上限。后备队按预设的合法增援批次到达。

生成配置包含双方真实武将、兵种、兵力、等级、任职、编制队列、地形、种子、时限、城门耐久、守方首发护盾、敌军援军批次及可选坚守目标。战法按当前学习规则自动生成；双方从零战意和零军略进度开始。

预设和自由编辑使用同一校验器。不以静默截断队数、补虚构身份或放宽带兵上限修复错误配置。援军按敌军草稿第七队起依次分批，不得提前上场，也不额外占用六队上限。配置随当前存档保存，同局重试读取配置快照；非当前版本存档需重新开始。

## 使用方法

战役列表或演武试炼中选择“载入自定义战役”，再通过原有部队编制与军团任命流程调整双方。自定义页面可修改时限、守城条件和援军批次；核阅后进入共用战前会议。

修改预设后运行 `npm run design:check`、`npm run design:export`、`npm run design:verify`、`npm run test:design` 和 `npm run test:battle-generator`。导出的一览表由脚本生成。

## 机制与平衡分开验收

- 机制回归检查合法编制、真实施放、射程、ZOC、补位、援军时间、守城条件、确定性续战与结算。需要固定接敌条件的单元测试自行设置清晰的测试几何，不把几何或必胜要求写回战役预设。
- 平衡诊断使用 `data/design/battle-validation.mjs`，运行 `npm run audit:battle-generator`。当前三组对照为远程集中与骑兵应对、均分与主辅分兵、平地与林地；组内同武将、同等级、同总兵力，每方案固定四个开发种子及四个独立验证种子，并交换双方。
- 双方使用相同的固定军略条件策略。玩家队列与敌方择序机制仍按游戏规则运行，因此交换双方的结果分别报告；不把双方差异简单归为数值失衡。
- 不替换已学战法、不重抽、不注入战意或军略资源、不要求历史方必胜或所有方案五五开。骑兵对照会同时切换该兵种的合法学习池，因此不能当作单个战法的独立因果实验。
- `outputs/battle-generator/results.json` 保存本次全部对局配置、双方剩余兵力、实际战法、伤害和武将贡献；`report.md` 汇总分组结果，失败局完整保留。

本轮建立可复现的诊断入口。更大样本、早中晚等级、名将替换及弱将贡献的专项验收仍应按具体设计问题扩展，不能仅凭基础对照宣称全部游戏平衡完成。
