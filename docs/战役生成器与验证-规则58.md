# 战役生成器与验证

独立战役统一使用自定义编辑器。规则88加入下邳、官渡、赤壁、合肥、夷陵、五丈原六张历史地图及阵容模板，载入后仍可编辑，不恢复旧演武预设。普通模式天下剧本不受影响。当前共有九种兵种，弩兵和兵器使用共享兵科适性。

## 历史地图与阵容（规则105）

地图数据在 `data/design/battle-maps.mjs`，双方阵容在 `data/design/historical-battles.mjs`。每张地图为14×8实际地形格，共用寻路、地形效果、布阵和存档；配置保存mapId，载入时核对地图及地形，重试保留地图。编辑器改选通用地形会解除历史地图选择。

全员10级，按真实兵种适性携带全部合法普通战法及本人专属，满级羁绊按正式分配达到上限；不因历史模板额外赋予S适性、战法、战意或军略资源。阵容可交换、改兵种和改兵力。下邳与合肥从守城方开始，合肥三将守住七天、城门与可战部队仍在可胜；其余为野战。五丈原为长期对峙中的局部交锋改编，不模拟病逝或预设历史胜负。

用户确认按游戏尺度压缩兵力差距，保留数量劣势与历史胜方的武将优势。人物归属参考各战役及战役期间部队编成；人物所带兵种、兵力、援军批次和地形格为游戏尺度改编，并非同一时刻的史料复原。官渡采用相持阶段人物，不加入先前已阵亡的颜良、文丑或当时被囚的田丰。袁军、赤壁曹军、合肥孙军及夷陵刘军拥有更多兵力、部队和援军；预期胜方的阵容整体能力与适性更强，使用现有固定战法和共同引擎。下邳曹刘联军也有兵力及后续援军优势。五丈原双方各54,000兵、14队，其中援军4队，保留均势，不指定胜方。当前逐局验证见[兵力、援军与历史方向](玩家布阵与羁绊强度-下邳.md)。

参照：[下邳](https://zh.wikipedia.org/wiki/下邳之戰)、[官渡](https://zh.wikipedia.org/wiki/官渡之战)、[赤壁教学资料](https://www.edb.gov.hk/attachment/sc/curriculum-development/kla/pshe/references-and-resources/chinese-history/war2_sc.pdf)、[合肥](https://zh.wikipedia.org/wiki/合肥之戰)、[夷陵](https://zh.wikipedia.org/wiki/夷陵之战)、[五丈原](https://zh.wikipedia.org/wiki/五丈原之戰)。

## 生成与编辑

规则106：我方使用固定总预备兵 `ownTroopBudget`，先遣军团及全部我方援军共用额度。编辑器可填写总数，并显示总额、已编制和可用人数；新建自定义战役默认30,000人，历史模板默认以其完整我方名单的总兵力为额度。编制或增加兵力占用额度，减少兵力、解散、移除我方援军后可重新分配。兵力滑条与最大按钮同时受本将带兵上限及其他部队占用约束，剩余不足1000人时不能新增。最终提交、战役生成和存档均核对实际编制及战场开局总兵力；取消不修改来源。预算保存于战役草稿，同局重试及确定性续战保留，战中没有从未编制兵员自动补兵的操作。敌军编辑不占用我方额度。交换双方时按新我方名单重算总额，保留原可用预备兵人数；换回后原预算恢复。

新建部队、选择新主将和新增援军默认使用当前地形允许的最高兵种适性。并列时优先保留武将常用兵种，再按共用兵种顺序选择；水战仍比较全部可用兵种，不强制舰船。已有阵容及手动选择保留。默认选择调用正式适性和兵科映射，与固定战法资格共用；兵器、弩兵按共享兵科适性判断。验证使用 `npm run test:battle-troop-budget`、`npm run verify:battle-troop-budget-ui`。

所有自定义对战使用 battle-generator.mjs 的 generateBattle，统一校验人员、兵力、固定战法、任职、部署及存档。每方有一个先遣军团，可另外编制多支援军军团；每军团一至十队，全场武将唯一，战场后备不受四队限制。每方通常六队同时在场，已抵达的奸雄所属军团可用第七名额；最低兵力1000，最高服从真实武将带兵上限。

战役入口直接打开编辑器，可修改双方先遣及援军编制、援军名称、阵营、到达时间或条件、地形、种子、时限、城门耐久、守军护盾和坚守目标。每支援军共用部队编制、任命和核阅流程；编辑一军不改其它军团。交换双方会同时翻转全部援军归属及守城方向、重指向先遣军团条件，并保留守军坚守目标。原先遣敌军后备到达设置仍可使用，完整新增军团使用 reinforcements 配置。

援军尚未到达时不出场、不提供指挥军略或额外上场名额；抵达时成为真实后备，等待合法空位与入口。玩家侧援军抵达可进入共用军议，只调整后备与撤离，在场部队、地形和战斗意图锁定；敌军按现有 AI 补位。双方从零战意与零军略进度开始。全部军团与到达确认随当前存档保存，支持确定性续战和同局重试，不迁移旧规则存档。

规则104：`reinforcements` 每项保存 side、name、team、roles 及可选 tactic；按时间到达使用 tick（界面按开战后的天数编辑），按条件到达使用 arrivalCondition，两者不能并存。条件为 `{type:'unit-defeated',unitId}`（指定部队被消灭）或 `{type:'army-defeated',armyId}`（指定军团全部部队被消灭，包含后备），目标可来自双方先遣或其它援军。主动撤离不算消灭；目标必须实际兵力归零并溃败。禁止引用本军团、缺失目标或循环等待。移除军团时保留其他条件的原目标，被移除的目标须重新选择。

条件在完整战斗步结算后检查；同军团整批确认到达，仅触发一次，实际到达时刻随存档保存。最后一支先遣队被消灭时，满足条件的援军先抵达，再判断胜负；未满足条件的援军不延续已全军覆灭的战斗，也不计入时限结算的可战兵力。军议仍在合法补位前暂停。生成后每军团有独立 armyId，所有部队可追溯到真实编制。双 AI 诊断使用 aiSides:[0,1]，沿同一到达规则自动继续；手动控制器可显式关闭援军军议暂停，不跳过到达限制。

`npm run test:conditional-reinforcements` 检查真实溃败触发、整团全灭、撤离、胜负边界、换边、隔离编辑和确定性续战；`npm run verify:conditional-reinforcements-ui` 检查时间／条件选择、目标、核阅、桌面与移动端、实际抵达与军议读档。

## 定时战役事件（规则105）

用户要求断粮和伏兵到指定日期后给目标方触发对应负面状态，并限定使用现有游戏机制。自定义配置 `events` 每项保存 kind、side、tick、duration，最多32项。界面按开战后天数编辑，战前核阅显示目标、日期和持续时间，换边同时翻转目标。

火烧乌巢映射为粮道中断。大地图沿用断线停止补给、消耗携粮、逐步缺粮及严重时减员／解散的原有流程。独立战役没有实际粮道，按用户之前要求的日期触发方式抽象为缺粮；战斗惩罚与大地图共用 `army-supply.mjs` 的原有缺粮计算，当前重度档使攻击、武技、谋略、营务威力降低35%，与已有军团缺粮取较强值，无法镇静，期限结束后恢复；生效期间后到援军同受影响。伏兵突袭仅给触发时在场部队施加混乱和失阵，沿用当前免疫及解除，不影响后备、未到援军，不反复补施。两种事件均不直接删兵。当前状态参数在 `data/design/battle-events.mjs`，各战役日程与系列资料参考见[设计表](design-tables/历史战役与援军一览表.md)。

触发只记录一次，当前存档校验日程、触发时刻和状态来源；军议暂停保持已生效状态与余期。`npm run test:battle-events` 检查生效、免疫、解除、到达军议和确定性续战；`npm run verify:battle-events-ui` 检查编辑、交换、核阅、实际日期触发和状态详情。历史典故不新增游戏里不存在的火攻、偷粮、倒戈、渡江或病逝判定。

## 机制与强度诊断

机制回归使用 tests/helpers/battle-drafts.mjs 的独立测试输入，经自定义生成器创建，不进入游戏战役目录。这些输入只保留回归需要的人员与战场参数。

运行 npm run audit:custom-strength，对每个共享羁绊的集中阵容、16名专属战法持有者和九种兵种进行实战筛查。使用1、5、10级，同总兵力，固定开发与独立验证种子，双方交换；不注入战法或资源。完整配置、败局、战法次数、伤害与贡献写入 outputs/custom-strength/results.json，汇总见同目录 report.md。部分样本验证确定性续战。补充后备轮换、八队统军和三种兵器攻城对照；主报告50组、1200场。另运行 npm run audit:short-range 检查短射自然接敌、战意与实际距离，汇总见 outputs/custom-strength/summary.md。

阵容筛查包含武将属性、其他羁绊、军略和兵种差异，不能把整体胜率解释为单个技能的因果收益。实际开场档位单独记录；未触发效果不能判断为无效。内政和行旅特性不属于单场战斗强度。引擎异常先修正再复测，不以五五开为目标。

同武将、同等级、同总兵力的配兵与地形对照仍可运行 npm run audit:battle-generator，独立诊断配置不作为游戏预设。

## 当前机制修正（规则86）

短射范围与井栏4格交战距离一致；24场固定样本自然发动48次，遵守每场两次。未入场后备随全军撤退不领取入场羁绊，也不要求保存入场快照；已入场部队仍必须保存。不可达后排集火不再导致阻挡线前反复脱战，有合法侧路时保持正常脱战流程。双方及两模式共用，旧规则存档需重新开始。
