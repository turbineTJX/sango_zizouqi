# 内政实现与验证

日期：2026-09-19。首版对应内政设计V1.4，已追加[同城同方向多人协作V1.5](内政协作实现与验证.md)，接入普通模式的天下战略。

## 使用方式

在「城池内政」选择己方城市，为商业、农业、技术、军事、人才添加本城待命武将，然后点击「进行」。委任不设任期，行动结束后下一旬继续自行判断。每城每方向可多人，每人一个方向，太守可兼任。添加同方向同僚保留已有委任；改派、调任或编入部队只结束对应人物的旧任务。实际同城同方向即可自动协作，具体事务可以不同。

负责人界面显示当前事务、剩余天数、已付费用及成功把握；城市事件记录开始、成果、失败、暂停和中止。建造区分新建与扩建，结果来自真实规则结算。保留原有直接建设、征募整补入口，玩家可主动安排紧急支出。

**城内大军团不限队数；编制出征仍最多10队；同阵营同时上阵仍为6队。** 超过10队不能直接下达离城行军令，需先拆分。归城并结束整队后默认归并；守城败退的超大军团拆成每支最多10队的行军纵队，兵员和携粮不复制。

## 资源与兵员

- 钱存于全势力府库，城市各自显示钱收入。默认保留500金军费，自动内政不能动用，可在页面修改。
- 粮、粮收入、预备兵、预备兵收入归城市；城市预备兵上限为30000。基础旬产出为钱 `160 + 市场×160`、粮 `600 + 农田×600`、预备兵 `500 + 兵营×500`，再计算太守政治、已解锁内政技能和临时收益。
- 城内士兵数是实际驻城部队的健康兵力总和，伤兵另列；守城时使用战场实时兵力。原固有守军已经转成明确的部队，没有第二份隐形守军。
- 预备兵通过征募直接进入具体部队；没有“已征待编士兵池”。征募与玩家直接整补共享预备兵、预留量和每旬额度 `2000 + 兵营×1000`，真实缺额按带兵上限减健康士兵、伤兵计算。
- 军事负责人开工时预留人力并支付费用，完成时按实际到位人数扣预备兵、粮食，退还未使用的人头费用。接收部队离开本城不远程补人。失败和取消释放预留。
- 医馆每日每级每队额外恢复6名真实伤兵；主动救治只作用于原接收部队仍在本城、未交战且足粮的伤兵。恢复不生成预备兵，也不额外生成健康士兵库存。
- 城防耐久沿用城门耐久。民心暂停使用，原民心产出倍率和赈济入口已移除；武将忠诚独立存储，实际用于劝说与安抚。

## 行动与设施

实现40项行动定义，其中9项建筑动作根据等级区分新建、扩建。设施最高5级，五方向共享每城一个建设队列。

| 方向 | 设施 | 主动事务 |
| --- | --- | --- |
| 商业 | 市场 | 举办集市、招徕商旅、招商合作、出售余粮、整顿税务 |
| 农业 | 农田、粮仓 | 督耕、修整灌溉、购粮、抢收保粮、整理仓储 |
| 技术 | 工坊 | 常规研制、集中攻关、寻访工匠、聘请名匠、仿制改良、试制验证 |
| 军事 | 兵营、医馆、校场、城防工事 | 常规征兵、加急征兵、集中救治、精心疗养、常规修缮、紧急抢修、征集工匠、检查整固、守城操演、战前动员、布置守备 |
| 人才 | 招贤馆 | 探索未知人才、登用在野人才、劝说周边人才、安抚本城人才 |

建筑费用为每级500～700金，普通建筑10天，工坊和城防20天。普通事务多为10天，加急征兵、集中救治、抢修、动员和救灾等为5天。准确参数集中在 `domestic.mjs` 的 `BUILDINGS`、`ACTIONS`，这些是首版调试参数。

自动决策先排除资源不足、队列占用、无目标、冷却、效果尚在生效等无效选项，再依据城市需求、敌情、武将性格等评分，在相近分数的候选中带权选择。执行能力影响成功把握；结果有超额、正常、部分达成和失败。连续失败降低重复事务优先级，不通过文字随机修改属性。

工程失败保留进度并延长5天，不追加费用；执行人离开后工程暂停，接任者继续原付费进度。自动选项共享府库，按委任ID稳定顺序批准。动作完成后下一旬重新选择，不在一个结算点无限连做。

名匠来访、田间灾情和仓储霉变为随机机会；仿制机会只能来自真实战斗获胜且敌方有弩兵或兵器的战果。救灾影响同一次事件的真实损失；贸易检查相邻友城与道路阻断，保留供军粮食，买卖失败不扣未成交货款或粮食。

## 城市技术与战斗衔接

枪兵、弓兵为基础技术，初始驻军已有兵种同步为本城技术。其余按城市研究，达到100进度后还需试制成功才解锁。编制、改编和新增兵员检查当地技术，已有部队的行军、战斗与伤兵恢复不受影响。舰船另限具备水域条件的城市。

校场每级增加3点守城初始战意，建筑部分最多15点；操演或动员提供最高12点额外准备。城防每级提高3000耐久上限和2%开场护盾，沿用基础13%守城护盾；布置守备提供最多10%额外护盾。合计上限分别为30战意、35%护盾。

临时准备有效30天，用于下一场本城守城战。锁定布阵时只发给首发在场守军；援军与后续轮换不补发。委托、接管与保存读取使用同一状态，不能重复领取；消耗记录跟随原准备行动ID，防止重复刷新。

## 人才范围

探索使用现有真实武将库中的未占用人物，不生成重复姓名或复制现役武将；每城初始配置3名未知候选，探索可发现本城或相邻城市的人才。人物位置属于首版世界初始化配置，并非历史地域考证结果。

登用使用已发现候选，关系、接洽记录与招贤馆影响把握。劝说当前作用于本城及相邻城市的其他势力待命人才，排除太守、在途人物与现役部队将领；成功只转移该人物，不夺取城市或军团。失败可动摇忠诚或进入防备期，全局人物冷却防止多城反复接洽。安抚作用于本城本方待命人物和驻军将领的实际忠诚。

首版没有俘虏招降、外交惩罚或敌方自动挖角循环，也未添加商品链、人口阶层、独立民心系统。未配置人才负责人的敌城不会自动执行人才行动。

## 存档与验证

战略存档版本为4、内政数据版本为2，按项目约定不迁移旧档，需要新开战略局。当前版本支持自动保存、刷新恢复和导入导出。内政拥有独立随机数状态，重读同档不会重掷行动或协作；校验每人委任唯一性、多人资源占用、预备兵预留、研究、建设关联、协作与关系成长记录及开场准备范围。

核心回归位于 `tests/domestic.test.mjs`，覆盖持续委任、多旬同种子续行、随机结果差异、预备兵与兵员守恒、改派、工程接续、人才、技术、真实围城暂停、开场加成、城市超10队保存与出征限制，以及真实败退拆分。战略和文官技能原有测试也同步验证资源规则。

验证命令：

```text
npm test
npm run check
npm run verify:domestic-ui
npm run verify:strategy-ui
```

UI脚本使用 Playwright；可通过 `PLAYWRIGHT_MODULE` 指定已安装包，通过 `GAME_URL` 指定本地服务。新内政脚本默认地址为 `http://127.0.0.1:4183`。截图和结果分别位于 `outputs/domestic-ui/`、`outputs/strategic-ui/`；全量测试与语法结果记录在 `outputs/domestic-full-tests.txt`、`outputs/domestic-check.txt`。

V1.4首版结果：全量431项测试通过，0失败；其中新增内政专项17项。语法检查通过，内政及战略两套真实页面验证通过，覆盖桌面、手机、委任、结算、改派、读档、真实遭遇、接管与跨旬。V1.5协作新增测试与最新界面截图见[内政协作实现与验证](内政协作实现与验证.md)。
