# 外交系统设计与实现

**接入状态：已接入运行流程。2026年10月6日，战略存档版本49。** 数据源为 `data/design/diplomacy-rules.mjs`，正式参数见[外交规则与原子动作一览表](design-tables/外交规则与原子动作一览表.md)。

外交沿用[内政](内政系统最终设计.md)的持续委任方式。玩家定大方向、负责人、重点势力和资源底线；武将后台选对象、组合条款、实际出使并谈判。所有结果先进入武将与城市每日记录，战略奏报引用其中的重要节点。

**玩家给方向 → 武将实际出使和交涉 → 玩家批准完整最终方案 → 后台签署和履约。** 钱粮、预备兵、城池、俘虏、停战、同盟和请求出兵共用此流程。界面没有逐项拼装条款的交易篮子。

## 委任与最终批准

| 方向 | 唯一主属性 | 后台事务 |
| --- | --- | --- |
| 交好 | 魅力 | 赠礼修好、互通已有情报 |
| 通商 | 政治 | 购粮、售粮、预备兵、固定额度通商、借款 |
| 交涉 | 智力 | 停战、赎俘与换俘、同盟、援军、换城、续约、撤军与解约 |

允许同方向多人，分别办理项目。每名武将只能承担一项持续委任，不能同时在内政、军团和出使任务中办事。太守须先解除职务，随军和在途人员须实际返城。城内已编部队主将可以出使，但随行者是本人，原城兵员与伤兵不随使臣移动。

正在办理内政的人改任外交，选择「立即执行」或「完成后执行」；等待保存原事务引用，完成前不接下一单。外交人员收到调任、内政或出征安排，同样先中断或完成外交，再沿路返回，实际驻城后执行保存的命令。外交页显示返城后安排并允许取消；取消后续安排不撤回已经发生的召回。没有合法事项则在驻地待命，并显示经费、资源、路线或对象条件。

玩家可指定补粮、补军费、救人才、减少战线、联合抗敌、争取援军、调整边境、维持条约等意图。各方向只选择自身业务的候选。君主城金粮兵底线和每旬行资上限是评估边界，不能替代最终批准。

最终方案列出双方给予的完整条款、确认收支城、真实对象、数量、期限和履约状态。操作为「批准」「继续交涉」「否决」。所有涉及玩家的最终方案均需明确批准，包括小额礼物、预算内交易和对方主动提案。

批准绑定版本及完整条款快照。反报价和继续交涉生成新版本、清空旧批准；君主迁城或对象变化会失去签署资格。版本号不变而内容改变也不能签约。批准只写审核事实，后台下一次实际推进才复核和签署；资源或军事编制不足则停止签署。

查看、关闭和确认奏报只改变已读状态，超期不会自动接受。否决结束项目、安排实际返程，不算毁约。未签方案不付款、不交资源、不改城属、不释放俘虏、不提供情报，也不按外交承诺提前出兵。

## 原子动作与后台组合

原子动作由武将后台选择和组合，统一通过批准、签署和履约处理器，不作为玩家逐项操作菜单。

| 类别 | 原子动作 | 实际作用 |
| --- | --- | --- |
| 资源与人员 | 划付金、交付粮、移交预备兵 | 使用真实资金和君主城库存；粮兵实际运输，金按交付进度结算 |
| 对象交换 | 移交城池、释放俘虏 | 指定唯一对象，完成实际撤离、接收或押送后交接 |
| 情报 | 提供情报 | 引用本方已有记录节点、文本和观察日期 |
| 关系 | 结束战争、互不侵犯、同盟 | 改变权威战争和保护状态；同盟附双方不侵犯 |
| 经贸 | 开放经贸额度 | 明确粮食、固定报价、总量和期限，按实际供需生成批次 |
| 约束与解约 | 限制军事支持、终止约定 | 限制对指定势力的援助；双方批准解约后停止未来义务，已发生债务保留 |
| 人员与物流 | 使臣通行、商队通行 | 保护接洽或实际运输，不夹带军团通行权 |
| 军事路权 | 军团借道、准许驻军 | 可限定路线、地点、人员和兵力，不改变城市归属 |
| 补给 | 准许取用补给 | 指定军团取确认君主城真实预留粮，受累计限额约束 |
| 军事任务 | 宣战、派遣军团、撤出军团 | 使用实际军令、部队、行军和期限；下令不算已经抵达 |
| 战果 | 战果归属 | 实际取得指定目标后再按和平交接办理 |

常见组合为金换粮、粮换军费、金换预备兵、赎金换俘虏、换俘、停战附不侵犯、两城交换、军费与粮支援换出兵、共同敌人同盟附路权和战果归属。没有独立库存的马匹、兵器和宝物不进入交易，已编部队、武将和随军伤兵不作为预备兵出售。科技和设施随实际城市保留。

## 君主城统一收支与预留

**外交金、粮、预备兵按双方君主实际驻城收支。** 使臣的出发和接见地点不改变来源。新报价等待双方君主实际驻扎己方城市，不能创建虚构都城或自动抽取远城库存。

金、粮、预备兵均使用确认君主城的独立库存，不能动用其它己方城市的库存。报价扣除口粮、内政与军事预留、其他有效报价占用和资源底线；内政和补兵也读取同一占用。实际外交委任和出行人员形成行资预留，避免内政花完经费使AI无法出使。

谈判占用不是已付款。签署时在同一节点重验双方对象和资源，将约定金粮兵实际移入契约预留；任一方不满足则双方不签署。装运把预留实物移到真实承运人，在途和原仓数量不重复扣减。接洽费与每日行资由使臣出发城市付款，是办事消耗，否决也不退回已用费用。

签署保存双方收支城。君主迁城不搬走原仓或修改在途货队，原契约、未来付款和经贸框架批次继续使用确认城市；新方案使用新驻城。变更收支城、报价或义务必须另取完整批准。

城市和俘虏按具体对象交换，不要求是君主城。随城库存属于城市本体，独立钱粮对价仍走君主城，不能重复计价和扣减。

## 实际出使与资源交付

使臣从真实驻地沿道路移动，抵达后连续交涉。效率使用方向唯一主属性，达到门槛后仍须双方君主同意，不能把高属性当必定成交。双方接洽有针对该使臣的访问许可，签署的商队和军事许可分别生效，第三方不自动承担许可义务。

出行、接洽、等待批准和返程按实际日历消耗行资；经费不足在当前地点暂停。封路尝试合法改道，不穿越无授权第三方城市；不能改道时停留或返程。军团与城池拦截使用共用实际遭遇检查，合法访问与商队保护在当天移动前生效。第三方截获保留真实损失和人员去向，不扣接见方信用。

原城失守时使臣保留位置，留城兵员与本人分开处理，选择剩余己方城市返程。召回和失败退运保留当前路段进度，不瞬移。

粮与预备兵由真实武将承运，需要取货时先抵达来源君主城，再装运到确认接收城。仓容不足在当地等待，只结算已卸数量；货款按相关实物、人员或城市交付比例划付。契约货款从确认付款城的金库移入契约预留，按实际交付比例入确认接收城金库。普通城际调金沿真实运输路线执行，不使用势力统一府库。

经贸框架在固定报价、额度、期限和确认城市内，按真实缺口和余量生成批次，引用原契约批准并重验库存与资金，仍由真实承运人履行。额度按实际交付累计，不产生固定贸易收入。新增价格、额度、续期或军事义务不能继承旧批准。

借款由当前划款与未来到期划款组合。未来款项形成真实债务，不要求现在已有未来收入，也不凭承诺造钱。到期只从实际可用府库付款，逾期保留余额并影响应付款方信用，补足资金后继续结算，解约不抹债务。

## 城池和俘虏交接

城池交接核验归属、安全及交接后双方都有实际领土，再撤离原方官员、预编部队和军团，安排真实接收人员到场。俘虏另行实际押送到原方保留城市或按明确释放条款交付。两城交换在双方城市都准备完成后同批改属。

和平交接不走攻城胜利、被俘或战死结算。设施、研究、库存与已付费工程进度留在实际城市，太守和原官员任职解除，原方人员不随卖城倒戈。都市圈设施按共用实际地点规则计算。

俘虏使用真实身份、原势力、拘押方和押送位置。签署锁定唯一对象，普通自动赎回不能重复释放或收费；原有押送继续完成，再由真实押送人接手。换俘在全部到交接点后同批释放，赎金随真实交付结算，获释者从真实位置回原势力，不变为付款方新招募武将。

## 停战、同盟和实际援军

无前置条件的保护默认签署次日生效。签于第10天、期限30天的保护覆盖第11至40天，第41天失效。续约另行最终批准，原期限按期结束，合法到期不自动宣战。

停战处理真正位于相反阵营的战场：以停战退兵结束，保留已发生的兵损、伤兵、功绩和时间，不重掷全歼人员结局，不产生占城或胜利奖励。军团从实际位置沿合法退路撤离，退兵许可不能用于重新进攻。

军令、接敌、拦截、节点和粮道从同一条约记录判断敌对。保护期间不能普通下令袭击对方，需要解除保护或新增军事许可时先取新的最终批准。借道不会免费取粮，也不能用通行许可停驻对方城市；驻军许可结束或通行许可在途中到期，军团从实际位置回撤，保留路段进度。

援军选择实际出兵城现役部队，保留守备与口粮，遵守十队上限、编制、携粮、行军和出阵限制。谈判保留拟用人员和兵粮，批准签署后才编组出发；向新敌方参战明确附宣战条款。

军团保留原势力身份、费用和损失。抵达才触发抵达报酬，抵达与完成服务是两个节点。拟案使用军团共用行军算法，按实际兵种、指挥、士气及逐段道路计算预计到达；许可覆盖往返行程、30天服务和20天余量，至少90天、最多360天，无法在上限内履行的不报价。按指定敌方、地点和期限继续任务，实际参战使用共同阵营的预备队与出阵规则，不虚构援军或转移身份。普通军事AI不把履约援军挪作其他扩张；实际断粮、战损或任务结束仍沿路回撤。

直接补给只取契约确认君主城预留粮，指定军团须实际抵达该城，受携粮容量与累计额度约束。服务期满或获准解约后实际撤离，约定战果取得后再和平交接，第三方占领不伪造成果。

## 失败、每日记录与界面

前置条款须引用明确的较早节点，拒绝循环等待。资源、人员、城市和援军分别记录实际进度，不用整份「成功」掩盖未交条款。已经交付的对象不自动回滚，未付资金解除预留，仓内物资解除占用，在途未交资源按实际位置退运；仓容不足保留实物。

普通运输困难与第三方损失不恢复双方战争，独立保护继续到期，已有债务继续结算。否决、正常到期和第三方事故不扣双方信用，实际逾期只影响应付款方。改变义务和提前解约重新提交最终方案。

每日记录显示委任、实际驻地、往返路段、接洽、待批准、返程和押运；事实节点记录反报价、提交、批准、否决、签署、生效、交付、到期、退兵和失败，并关联契约、版本与对象。承运人、押送人、获释武将和援军分别保留行动。

战略奏报引用待批准、签署、生效、重要到期、换城、释俘、援军和异常节点，普通行资和接洽不逐日弹报。待批准奏报可直接核阅，查看保持暂停并返回奏报；已读不删除事实，不写批准。

外交页提供方向、重点势力、预算底线、三方向人员、待批准方案、条约履约、接洽与关系。待批准高亮，正常往来淡色并有文字状态。对象可进入真实详情与每日记录。地图按真实进度显示使臣和押运，不把留城兵员画为随使臣出行的军队。

## AI算法与双方共用规则

AI共用资格、预算、道路、拟案、谈判、签署、交付与保存流程。唯一控制器区别是：AI君主审核自己势力，玩家势力只接受玩家明确批准。AI不能给玩家补批准、造资源或跳过出使。

1. 每旬读取君主城、可用金粮兵、实际边境敌军、俘虏、条约期限和人员。
2. 对三方向生成同一套候选，核验对象、报价、路线和拟用军团；硬约束不能履约的方案先排除。
3. 比较需求优先级、往返时间、接洽费、主属性、内政机会成本和等待时间。粮食缺口、俘虏、敌军压力和续约提高对应优先级，没有真实缺口的框架不购粮。
4. 委任实际可用武将，最多两名负责人；原项目结束后根据变化改方向。等待原内政按真实事务执行，普通评分波动不每天换目标。
5. 抵达后双方君主各评整组利益：钱粮随稀缺性变化，城池按经济与城防估值，俘虏按真实赎回价值，援军按兵力、行程和共同敌人估值。
6. 君主性格影响和平和发展取舍，统率、智力影响稳定有界的研判误差；自己的库存、路线与资格始终精确检查。信用折价未来承诺，不给战斗或资源加成。
7. 不合适的金钱对价最多两轮反报价，每次新版本清空旧批准，仍不能履约则拒绝或取消。涉及玩家等待玩家；AI双方同意后同样复核签署。
8. 条约改变后军事AI撤销冲突的进攻计划，援军与军队继续使用实际兵粮和战场。

一轮评估按驻城复用候选与道路搜索，降低大量武将的重复计算；缓存不保存，也不跨实际状态变化复用。开局沿用原型玩法的敌对关系，不声称史实外交关系。

## 参数与验收

初始参数：10天重评、最终报价20天有效；接洽5至10天、费用100至300金，混合方案取最复杂类别；每日实际行资5金。使臣、粮兵押运和俘虏押送分别为70、100和50行动力。赠礼30天冷却且关系增益递减。

默认粮食报价0.18金／粮、单批上限3000粮，受到实际供需与反报价影响，不作为所有利益的统一汇率。底线500金、2000粮、1000预备兵，每旬行资上限600金。参数已接入机制，属于可校准的初值，不宣称经过长期平衡验证。

`npm run test:diplomacy` 验证实际出使、批准版本、只读奏报、运输、条约期限、停战、分批通商、债务、对象交换、后续命令及AI。`npm run verify:diplomacy` 验证方向委任、审批、对象记录、签署、地图标记和桌面／手机布局。另运行设计表生成校验、文档检查及战略、内政、运输、每日记录与存档回归。
