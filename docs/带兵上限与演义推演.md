# 带兵上限与演义推演

战役首页增加「演义推演」，与四场历史战役并列。五场推演直接进入布阵、配装和实战，采用现行战意、控制、伤兵、援军及军略规则，没有预设胜负或场景伤害加成。阵容与数值为玩法改编，不代表史实兵数或同时期人物关系。

## 带兵数

带兵上限 = `3000 + 统率 × 50 + (等级 − 1) × 200`，向下取整至百人，等级范围 1～10。上限从现有武将属性推导，不额外存储第二份数值。例如 8 级吕布上限 8,700 人，8 级貂蝉上限 4,900 人；本场实际派出多少人由编制决定，可以欠编。

- 征兵受每位武将自己的上限约束，现役与已有伤兵合计占用名额。
- 开战时记录本场初始兵力；战中治疗只恢复本场真实伤兵，不能按带兵上限凭空补人。
- 攻击、武技威力、谋略威力和攻城直接按当前可战人数累加，面板即结算输入，不再附加兵力输出乘数。相同武将与状态下，100 人只有 3000 人的 1/30 面板输出；伤兵不参与输出。
- 简报显示每将实际兵数与带兵上限，属性面板分别显示上限、本场初始兵力、当前士兵与伤兵。

## 均势与验证

规则 23 将兵力直接并入面板，并调整持续伤害与火攻军略。旧规则下的胜率不再代表当前实战。重新调整默认配兵后，128 种子抽样中三英为 67 胜 / 55 负 / 6 平，兖州吕布阵容为 84 胜 / 37 负 / 7 平；抽样条件与全部结果见[实战抽样](tactical-campaigns/实战抽样.md)。

首次启动演义推演生成随机种子；「同局重试」保留种子并恢复预设，「换局再战」使用新种子。试玩共用独立存档，自动保存、导入导出、暂停刷新和确定性续战继续有效。只维护当前规则，旧规则存档提示重新开始。

`tests/troop-capacity.test.mjs` 覆盖带兵上限、超编存档拒绝、五场真实续战、伤亡守恒及坚守目标；`scripts/verify-tactical-ui.mjs` 覆盖五场入口、兵力显示、重新开局、暂停恢复、手机布局与离线加载。运行 `npm run audit:tactical` 可重新生成抽样报告。

`tests/troop-output.test.mjs` 从零战意通过真实普攻击攒，验证 100 名残兵释放名将战法、火矢、火计、疫矢、轰击与舷射，面对 48,000 人目标阵容时不会造成不合理大额杀伤；同时检查火攻不随敌军初始人数膨胀。`scripts/verify-troop-panel-ui.mjs` 核对 100 人存档在浏览器中的面板值与引擎值一致。
