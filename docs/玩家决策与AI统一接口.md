# 玩家决策与 AI 统一接口

2026-10-09。用户确认：每个玩家游戏决策页面都有对应 AI 实现，按照各自势力视角掌握同规则的信息，并通过共同规则执行。

页面负责让玩家提交选择，AI 只在后台自动提出并执行同类操作，不需要弹出界面或模拟点击。候选是否合法、是否付得起、人员是否真实在场、命令何时生效、行动与结果如何结算，由共用处理器决定。AI 的基本启发式和固定默认选择不意味着玩家必须采用同样策略。界面验证只核对玩家操作入口，不作为 AI 的运行方式。

## 当前逐页核对

`player-ai-decisions.mjs` 对当前 43 类页面逐项登记，归为 21 类游戏决策。以下实现均有实际可调用函数；纯浏览、设置、存档与开局编辑另列明确用途。入口检查只验证覆盖声明和函数存在，行为一致性由回归测试另外验证。

| --- | --- | --- |
| 内政委任、解除 | prepareEnemyDomestic：按本城需求补任，保留在办工作 | assignDomestic、dismissDomestic、rankOfficerCandidates |

| 城市预算 | 保存的保留底线及动态城市预算；当前不另行自动调节手动保留数值 | cityBudget、setCityBudget、实际征补和运输校验 |

| 外交方向、预算、人员、批准或否决 | 默认自动方向与保存底线；使臣按合法情报拟案，AI 按共同估值决定批准 | assignDiplomat、setDiplomaticGoal、setDiplomaticBudget、approveDiplomaticProposal；签约另复核实际履约条件 |

| 战场增援、粮路保护 | planStrategicSupport：真实部队、可见威胁、到达期限 | 共同出征、路线、军令与补给处理器 |
| 守城编制、放弃空城 | 同一 siegeDefensePlan；无合法实际守军时接受直接占领 | 共同临时编制与空城处理 |
| 首发、站位、后备补位、援军军议 | planBattleCouncilAI、planEnemyArmy、rankEnemyReserves：后台处理战前与援军，简单布阵与固定择序 | deployUnit、fillSlots、lockDeployment、共同到达和人数限制 |
| 军略、选区、全军撤退 | 固定条件、固定优先序；战略撤退按本方损失与补给 | issueCommand、共用范围与目标资格 |
| 逐队撤离及目的地 | 默认保留已有撤离人数设置，不增加主动逐队保将策略；目的地选本方已知最近可达节点 | configureCouncilRetreat 支持双方，retreatDestinations、configureRetreatDestination 与真实离场处理 |
| 宝物授予、装备、收回 | manageTreasuresAI：合法授予装备，保留已有装备；不主动收回，无合适接收人则保留城库 | grantTreasure、equipTreasure、storeTreasure |
| 俘虏赎回、交换、释放 | 优先已有实际外交赎回或交换；未达成时保留，失去关押条件按公共规则释放 | releaseCaptive、共同外交履约与返城 |

固定默认策略也是明确选择，但不宣称它已优化。例如城市保留底线、外交预算底线、逐队撤离人数及宝物收回，目前均保留已有设置。AI 不为组羁绊调整组合，也不修改固定战法和施放顺序。游戏模式、剧本、君主选择和自定义战役编辑属于给模拟设定初始输入，双方在生成后的世界使用共同规则。

## 本次修补

- 军团拆分、合并、改编、整补、行军方式、城市与外交预算、外交解除和俘虏处置支持显式势力；自动安排只改变提交时机，保留真实资格和费用校验。
- 军团草稿及其提交逻辑从 UI 模块移入不依赖美术的 army-management.mjs。AI 提交前完整预检，再原地执行，保留推进流程持有的 campaign 和 army 引用；不替换整个模拟世界。
- 太守任命与外交批准停止直接写结果；AI 太守候选排除已有等待军令者，外交批准使用提出批准的一方情报，实际签约再检查双方现实履约条件。
- 内政优先顺序改为各势力独立保存，观察势力不会改变其它势力顺序。全 AI 模式下，观察者不能通过这些手动管理入口改令；等待出征军令的 AI 安全复核覆盖观察势力。
- 出征复核不再从目标敌方的视角查询威胁；边境收益、玩家路线预览与撤离节点使用本方情报。可见敌军详情与地图同样隐藏后续目标、路线和粮道。
- 新军团管理 AI 仅对无作战、增援、外交或等待军令承诺的空闲军团重组。策略输入是不可变的独立测量值，无随机状态或敌方秘密计划。

当前战略存档版本 55、内政版本 20。旧档直接提示重新开始，不补旧字段或添加迁移。

## 验证与边界

`npm run audit:player-ai-decisions` 生成 outputs/player-ai-decisions/coverage.json，检查 43 类页面与 21 类决策的声明、共用入口和 AI 入口。新增页面必须明确登记其决策或只读用途。

`npm run test:player-ai-decisions` 验证相同军团草稿在玩家和 AI 势力下的资格、费用与结果；失败或取消不改状态；空闲残部真实合并、资源守恒和存档验证；输入不可变与隐藏敌情变化不改变选择；势力优先级隔离；太守等待军令资格；可见敌军后续军令不泄露。

`npm run test:ai-decisions` 按 ai-decision-tests.mjs 登记的实际行为用例运行各决策单元测试。每类必须登记具体文件和测试名称，并在本次运行中通过；缺类、改名未同步、跳过、待办或失败均不能算作覆盖。完整结果写入 work/ai-decision-tests/unit-tests.json，可用 --out 指定目录。新增决策须同步增加有实际行为断言的用例，不得用入口存在测试代替。

军团管理补充验证含零兵人员的实际编组容量，避免反复提交超过共用草稿十队上限的合并。行军补充返城辎重恢复、敌情变化、在途不可交接、军团长资格、休整、士气和急行实际到达收益；预算、太守、宝物保留和俘虏保留策略均有直接调用 AI 的行为测试。

自然全 AI 模拟还复现了购粮候选使用小数粮仓余量的问题：日常耗粮使库存带小数，购粮提案及行动数量却须为整数，导致合法运行生成无法保存的行动。共同候选和成交处理都按真实可用余量向下取整，保留原费用、退款和结果规则；双方提案、AI 自动开办及逐日存档均有回归。

用户确认所有实际钱、粮、预备兵、现役和伤兵数量使用非负整数。每日口粮按合计需求向上取整一次；实际补给量、军团分粮和轻装容量向下取整，余量留在来源库或原军团，总量不得因取整增加。预算预测复用同一口粮及补给处理器。存档拒绝小数库存和携粮，不通过读取时取整掩盖无效状态；评分、费率、速度和进度等计算参数仍可使用小数。

目标连续性只保护已有具体军事目标。默认发展和恢复不占用具体行动承诺，不能用20分切换门槛否决更高评分的合法候选；已有作战计划仍保持承诺，实际出兵仍重验人员、预算、守备与携粮。对应行为用例已登记在 ai-decision-tests.mjs，验证默认发展／恢复让位、负收益候选不获选，以及已有主攻不会因小幅评分变化反复切换。

`npm run audit:all-ai-decisions -- --scenario=guandu-200 --seed=20261009 --days=120 --out=work/all-ai-decisions` 使用未经增兵、赠送资源、改路或指定战争的全国剧本，所有势力由同一 AI 控制，保留普通迷雾与内政意外。记录真实出征、战果、易主、饥饿原因及保存续行；每30天比较读档后的下一天完整状态。并发开发时可用 --source 指定不可变代码快照；模拟前后核对源文件哈希。自然模拟的缺粮和损失属于诊断证据，不能仅凭未抛异常宣称决策最优、战损预测已校准或年度供养达标。

另运行战略规划、战争迷雾、外交、内政、军团管理、撤离与美术依赖边界回归，并验证当前结构的确定性续战。本次验收针对行为和信息规则，不以函数覆盖或自然胜率作为平衡、经济承载或算法最优性结论。

2026-10-09 专项复测：21 类决策绑定的 330 项行为测试全部通过，无失败、跳过或缺失的必要用例；另 35 项经济、军团草稿与行军机制回归通过。固定当前规则115、战略版本55的代码快照，官渡风云（种子20261009）全4势力 AI 推进120天到第121日，记录5次出征、1支撤退整队军团、1场有守军战斗及3次城池易主，其中2座原为中立空城。实际钱粮、物资和人数始终为整数，无城市或军团缺粮，4次读档后逐日状态对照一致，最终存档也通过现行代码的完整加载及下一日确定性检查。代码、设计表、文档和页面入口检查通过。原始记录为 work/ai-decision-review/units-final/unit-tests.json、campaign-final/campaign-audit.json 及 campaign-final/campaign-save.json。仅1场实际战斗不足以校准战损模型或证明长期高强度战争承载。

## 战斗决策与战后任命（规则116）

副将职位已取消，军团只保存军团长、军师。玩家战前会议与援军军议可任命本军团已到场且仍有现役兵力、未撤离的人员；不能使用其它军团人员、未到援军或零兵跟随者。共同执行入口为 battle-appointments.mjs 的 appointBattleRoles，AI 在自己的到达军议中后台调用同一入口。任命只改变今后的任职与指挥加成，不刷新战意、军略蓄积、独立冷却、每场限次和此前施放的状态。按日期保存任命记录，旧军略继续按当时人物和职位验证，读档不恢复旧职位或重算旧效果。

首发组织在战前任命后确定。奸雄额外名额不因战中伤亡或援军军议改任而撤销、重新授予；军议不得移动在场部队、重选意图或提前引入未到人员。后备补位与合法布阵仍通过双方共同执行。

战后先处理战损、人物去向、撤离交接及军团解散，再检查仍存在的军团。有效职位保留；玩家缺失职位保存为待任命，显示对话框，确认前暂停世界推进，关闭与读档均不能自动批准。AI 用 recommendArmyAppointments 选择本军团合法人员并调用同一 appointArmyRoles 原子校验，后台完成。城内独立部队、已解散军团及没有可任命现役者不弹军团任命。处理与保存校验位于 postbattle-appointments.mjs，战报记录实际变化。

回归覆盖援军实际抵达、本军团范围、零兵和撤离人员资格、玩家缺职读档继续选择、AI 后台任命、真实退却与阵亡结算、旧军略持续效果与确定性续战。界面验证入口为 npm run verify:battle-decisions-ui，包含桌面、手机和保存读取。
