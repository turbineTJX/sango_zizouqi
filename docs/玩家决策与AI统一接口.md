# 玩家决策与 AI 统一接口

2026-10-27。用户确认：每个玩家游戏决策页面都有对应 AI 实现，按照各自势力视角掌握同规则的信息，并通过共同规则执行。

页面负责让玩家提交选择，AI 只在后台自动提出并执行同类操作，不需要弹出界面或模拟点击。候选是否合法、是否付得起、人员是否真实在场、命令何时生效、行动与结果如何结算，由共用处理器决定。AI 的基本启发式和固定默认选择不意味着玩家必须采用同样策略。界面验证只核对玩家操作入口，不作为 AI 的运行方式。

操作页默认呈现必要选择和结果摘要：调任运输显示人员、终点、物资与到达时间；出征确认显示阵容、编制费用、携粮及指挥任命；整军、拆分、合并显示调整前后与费用，取消重复的独立属性核阅步骤；外交把待处理方案放在最前，双方给予的内容和期限保持可见。详细属性、道路序列、外交负责人、预算及履约记录按需展开。折叠、查看、返回和取消只操作界面草稿，不提交命令、不改费用、不改变 AI 策略。界面验证为 `node scripts/verify-compact-decisions-ui.mjs` 和 `node scripts/verify-diplomacy-ui.mjs`。

## 目标选择流程

界面参考《三国志14威力加强版》[出阵流程](https://www.gamecity.com.tw/manual/sangokushi14/wpk/sc/5100.html)中先编组、再地图选择目标并核对到达时间的组织方式，以及《全面战争：罗马2》[战略界面](https://r2encv2.totalwar.com/en/manual/single-player/0015a_enc_page_campaign_play_interface/index.html)中按城市、军队与事务分组的方式。仅采用交互组织，不引入其战法配置、战斗微操或其他游戏规则。

内政提案使用事项标题、负责人和独立的费用／耗时／成功率字段，出售手续费等实际后果保持可见；“暂缓”在左，“同意”在右。“同意本页”只逐项复核并同意当前展示的提案，失败项保留；“后续自动同意”开关只改变后续审批政策，不花费当前提案预算，不撤回或批准当前待批事项。共用处理器保留原有默认行为，界面通过 approvePending:false 明确仅更改政策。选人页保留所选数与必要缺项提示，选路确认使用主按钮。选人、改参数后保留键盘焦点；从人物详情返回原名单时恢复来源控件。Tab 循环只包含实际可见、可用的控件，关闭的详情不截获焦点。

出征、运输及侦察的桌面与手机横屏页面让地图、独立滚动的参数栏和底部操作栏同时可用，缩小窗口保留地图可读比例；地图选择页隐藏金粮与内政岗位标注，保留地点身份与合法目标。窄屏仍可上下浏览，确认按钮固定在底部。页面不增加步骤条、强制教学或新的确认阶段。回归 `npm run verify:player-interaction-ui` 覆盖键盘连续选择、详情返回、草稿往返、取消无写入及 1440×900、1024×600、844×390、740×360 布局；实际派遣、扣费、存档另由既有 compact-decisions、domestic-proposals 与 war-fog 界面回归核对。

战略端和战斗端统一按“行动来源 → 执行人或部队 → 合法目标 → 预览与调整 → 确认”组织。来源可以是城市、军团、参战一方或实际武将；从已选对象进入时带入该上下文，固定来源直接显示，不再要求重复选择。没有可选目标的全军效果、固定对象操作直接核阅其明确作用范围。

更换来源清空依赖它的人员、目标和预览；更换执行人员清空旧目标、路线、中转与不适用的运输设置。返回、查看详情、缩放、定位和重新选择同一人保留草稿。贼寨等由目标详情进入的命令保留玩家已明确选择的目标，改换部队后重新规划道路。所有确认仍调用已有共同处理器，并在生效时重新核对实际资格、位置和资源。选择、预览及取消不得扣费、改变位置、消耗军略、刷新随机结果或写入待执行军令。

| 端与流程 | 来源、执行对象与目标 | 预览与确认 |
| --- | --- | --- |
| 战略：侦察 | 己方城市 → 本城可用执行人 → 周边终点 | 预览道路、拖动改线，派遣后生效 |
| 战略：出征、讨伐、增援 | 来源城市 → 本城实际部队、指挥 → 据点、贼寨或实际战场 | 改线与携粮预览，军令核阅后确认；目标详情可带入已选目标 |
| 战略：军团调动 | 所选己方军团 → 合法终点 | 换军团清空旧路线和地图焦点，预览后确认 |
| 战略：调任、运输、分批与接力 | 来源城市 → 本城人员 → 友城、接力点及物资 | 换人清空目标、接力、批次与物资，按实际行程和容量核阅后下令 |
| 战略：部队编制与装备 | 来源城市 → 主将或已有部队 → 本城可用兵种、装备和兵力 | 本城资格、费用与调整结果核阅后确认 |
| 战略：内政委任、太守 | 所选城市 → 方向或职位 → 本城候选 | 委任页核阅后确认；具体内政事务由实际负责人依规则拟案 |
| 战略：内政提案与工作冲突 | 已保存的城市、执行人、原案或军令 | 原地点、费用与工作进度可见；准奏、暂缓、立即或完成后执行明确确认 |
| 战略：外交委任 | 派出城市 → 本城候选使臣 → 交好、通商或交涉方向 | 显示人员及当前已保存方针，确认后处理工作交接；不把未确认方针当成已下令 |
| 战略：外交方针、条款与预算 | 本势力及实际收支城 → 重点势力或已保存方案 | 地图候选预览、确认；最终方案仍单独批准；使臣拟定具体条款 |
| 战略：宝物 | 原宝物及真实持有者或城库 → 未出征接收人 | 武将详情带入接收人，换人取消“同时装备”，显示授予／替换结果后确认；跨城规则保留 |
| 战略：拆分、合并与整补 | 所选军团 → 本军部队或同地可合并军团 | 未选对象禁止下一步，核阅实际调整前后与费用后确认 |
| 战略：行军方式 | 所选实际军团 → 常行、轻装或急行 | 当前军团的容量、速度、士气及风险核阅后确认 |
| 战略：俘虏与固定对象处理 | 已选的实际俘虏、所属城与势力 | 对象详情中的明确操作按钮确认；赎回、释放仍走原处理器 |
| 战斗：接战与守城准备 | 实际战场 → 本方真实已到部队 → 指挥方式或临时编制 | 情报、整备与控制方式核阅后确认；切战场重置该场草稿 |
| 战斗：军议与战后任命 | 明示的实际军团 → 本军已到、存活、有兵力人员 → 军团长／军师 | 候选限于对应军团，确认调用共同任命；缺职不能关闭代替确认 |
| 战斗：布阵、替换与后备顺序 | 拖动或明确选择本方部队 → 合法格子、本方交换对象或后备位置 | 先显示落点、交换对象或队列位置，允许重选及取消；确认后落位，最后统一确认开战 |
| 战斗：撤离条件与节点 | 当前参战一方／已选部队 → 整数阈值或合法道路节点 | 批量明确“应用”；节点选择先预览距离、再确认，取消保留原军议设置 |
| 战斗：军略选区 | 当前参战方及规则确定的实际提供者 → 军略 → 合法友军或落点 | 名牌、模型与地图共用选目标，显示范围及受益对象，可旋转／改选，确认才消耗军略 |
| 战斗：全军军略、撤退与战斗意图 | 当前参战方 → 明确的全军作用范围或意图 | 范围固定的命令由明确操作按钮确认；战斗意图在开战确认前可调整 |
| 开局编辑与只读查看 | 自定义战役的双方、军团、人员、到达触发对象；查看、筛选与地图导航 | 编辑对象受共同生成器校验，最终预览并开始；只读选择不伪装为游戏下令 |

当前界面不提供手动集火：`issueCommand` 已明确拒绝该旧军令，相应残留界面分支已清除。普攻与固定战法继续自动选敌，AI 不增加目标组合规划。战斗布阵的预览使用隔离副本调用同一 `deployBattleUnit`；后备顺序同样先在副本验证。新草稿只存在于界面，当前游戏存档只保存已确认的布阵结果。

回归：`tests/target-selection-flow.test.mjs` 覆盖跨来源拒绝、换人失效、同人返回保留、外交本城资格、军团选择门槛与布阵预览不改状态。现有选路、侦察、外交、宝物、军议、军略、战后任命与玩家／AI共同接口测试继续运行。实际页面验收使用 `verify-deployment-ui.mjs`、`verify-battle-council-ui.mjs`、`verify-stratagem-area-ui.mjs`、`verify-diplomacy-ui.mjs`、`verify-treasures-ui.mjs` 及地图选路、撤离与城市菜单脚本；验证选择顺序、名牌目标、调整、取消、真实确认、存读档和桌面／手机布局。

`player-ai-decisions.mjs` 对当前 43 类页面逐项登记，归为 21 类游戏决策。以下实现均有实际可调用函数；纯浏览、设置、存档与开局编辑另列明确用途。入口检查只验证覆盖声明和函数存在，行为一致性由回归测试另外验证。

| --- | --- | --- |
| 内政委任、解除 | prepareEnemyDomestic：按本城需求补任，保留在办工作 | assignDomestic、dismissDomestic、rankOfficerCandidates |

| 外交方向、预算、人员、批准或否决 | 默认自动方向与保存底线；使臣按合法情报拟案，AI 按共同估值决定批准 | assignDiplomat、setDiplomaticGoal、setDiplomaticBudget、approveDiplomaticProposal；签约另复核实际履约条件 |

| 战场增援、粮路保护 | planStrategicSupport：真实部队、可见威胁、到达期限 | 共同出征、路线、军令与补给处理器 |
| 守城编制、放弃空城 | 同一 siegeDefensePlan；无合法实际守军时接受直接占领 | 共同临时编制与空城处理 |
| 首发、站位、后备补位、援军军议 | planBattleCouncilAI、planEnemyArmy、rankEnemyReserves、planReserveEntriesAI：后台处理战前与援军，简单布阵、固定择序与基础入场位置 | deployUnit、configureReserveEntry、fillSlots、lockDeployment、共同到达和人数限制 |
| 军略、选区、全军撤退 | 固定条件、固定优先序；战略撤退按本方损失与补给 | issueCommand、共用范围与目标资格 |
| 逐队撤离及目的地 | 默认保留已有撤离人数设置，不增加主动逐队保将策略；目的地选本方已知最近可达节点 | configureCouncilRetreat 支持双方，retreatDestinations、configureRetreatDestination 与真实离场处理 |
| 宝物授予、装备、收回 | manageTreasuresAI：合法授予装备，保留已有装备；不主动收回，无合适接收人则保留城库 | grantTreasure、equipTreasure、storeTreasure |
| 俘虏赎回、交换、释放 | 优先已有实际外交赎回或交换；未达成时保留，失去关押条件按公共规则释放 | releaseCaptive、共同外交履约与返城 |

固定默认策略也是明确选择，但不宣称它已优化。例如城市保留底线、外交预算底线、逐队撤离人数及宝物收回，目前均保留已有设置。AI 不为组羁绊调整组合，也不修改固定战法和施放顺序。游戏模式、剧本、君主选择和自定义战役编辑属于给模拟设定初始输入，双方在生成后的世界使用共同规则。

## 本次修补

- 军团拆分、合并、改编、整补、行军方式、城市与外交预算、外交解除和俘虏处置支持显式势力；自动安排只改变提交时机，保留真实资格和费用校验。
- 军团草稿及其提交逻辑从 UI 模块移入不依赖美术的 army-management.mjs。AI 提交前完整预检，再原地执行，保留推进流程持有的 campaign 和 army 引用；不替换整个模拟世界。
- 太守任命与外交批准停止直接写结果；AI 太守候选排除已有等待军令者，外交批准使用提出批准的一方情报，实际签约再检查双方现实履约条件。
- 内政优先顺序改为各势力独立保存，观察势力不会改变其它势力顺序。全 AI 模式下，观察者不能通过这些手动管理入口改令；等待出征军令的 AI 安全复核覆盖观察势力。
- 出征复核不再从目标敌方的视角查询威胁；边境收益、玩家路线预览与撤离节点使用本方情报。可见敌军详情与地图同样隐藏后续目标、路线和粮道。
- 新军团管理 AI 仅对无作战、增援、外交或等待军令承诺的空闲军团重组。策略输入是不可变的独立测量值，无随机状态或敌方秘密计划。

当前战略存档版本 55、内政版本 20。旧档直接提示重新开始，不补旧字段或添加迁移。

## 验证与边界

`npm run audit:player-ai-decisions` 生成 outputs/player-ai-decisions/coverage.json，检查 43 类页面与 21 类决策的声明、共用入口和 AI 入口。新增页面必须明确登记其决策或只读用途。

`npm run test:player-ai-decisions` 验证相同军团草稿在玩家和 AI 势力下的资格、费用与结果；失败或取消不改状态；空闲残部真实合并、资源守恒和存档验证；输入不可变与隐藏敌情变化不改变选择；势力优先级隔离；太守等待军令资格；可见敌军后续军令不泄露。

`npm run test:ai-decisions` 按 ai-decision-tests.mjs 登记的实际行为用例运行各决策单元测试。每类必须登记具体文件和测试名称，并在本次运行中通过；缺类、改名未同步、跳过、待办或失败均不能算作覆盖。完整结果写入 work/ai-decision-tests/unit-tests.json，可用 --out 指定目录。新增决策须同步增加有实际行为断言的用例，不得用入口存在测试代替。

军团管理补充验证含零兵人员的实际编组容量，避免反复提交超过共用草稿十队上限的合并。行军补充返城辎重恢复、敌情变化、在途不可交接、军团长资格、休整、士气和急行实际到达收益；预算、太守、宝物保留和俘虏保留策略均有直接调用 AI 的行为测试。

自然全 AI 模拟还复现了购粮候选使用小数粮仓余量的问题：日常耗粮使库存带小数，购粮提案及行动数量却须为整数，导致合法运行生成无法保存的行动。共同候选和成交处理都按真实可用余量向下取整，保留原费用、退款和结果规则；双方提案、AI 自动开办及逐日存档均有回归。

用户确认所有实际钱、粮、预备兵、现役和伤兵数量使用非负整数。每日口粮按合计需求向上取整一次；实际补给量、军团分粮和轻装容量向下取整，余量留在来源库或原军团，总量不得因取整增加。预算预测复用同一口粮及补给处理器。存档拒绝小数库存和携粮，不通过读取时取整掩盖无效状态；评分、费率、速度和进度等计算参数仍可使用小数。

目标连续性只保护已有具体军事目标。默认发展和恢复不占用具体行动承诺，不能用20分切换门槛否决更高评分的合法候选；已有作战计划仍保持承诺，实际出兵仍重验人员、预算、守备与携粮。对应行为用例已登记在 ai-decision-tests.mjs，验证默认发展／恢复让位、负收益候选不获选，以及已有主攻不会因小幅评分变化反复切换。

`npm run audit:all-ai-decisions -- --scenario=guandu-200 --seed=20261009 --days=120 --out=work/all-ai-decisions` 使用未经增兵、赠送资源、改路或指定战争的全国剧本，所有势力由同一 AI 控制，保留普通迷雾与内政意外。记录真实出征、战果、易主、饥饿原因及保存续行；每30天比较读档后的下一天完整状态。并发开发时可用 --source 指定不可变代码快照；模拟前后核对源文件哈希。自然模拟的缺粮和损失属于诊断证据，不能仅凭未抛异常宣称决策最优、战损预测已校准或年度供养达标。

另运行战略规划、战争迷雾、外交、内政、军团管理、撤离与美术依赖边界回归，并验证当前结构的确定性续战。本次验收针对行为和信息规则，不以函数覆盖或自然胜率作为平衡、经济承载或算法最优性结论。

当前决策行为检查、源码冻结及自然演进范围见[当前版本验收与体验目标](当前版本验收与体验目标.md)。旧源码的短期对局不作为当前整体验收；各阶段按实际完成窗口统计。

## 战斗决策与战后任命（规则116）

副将职位已取消，军团只保存军团长、军师。玩家战前会议与援军军议可任命本军团已到场且仍有现役兵力、未撤离的人员；不能使用其它军团人员、未到援军或零兵跟随者。共同执行入口为 battle-appointments.mjs 的 appointBattleRoles，AI 在自己的到达军议中后台调用同一入口。任命只改变今后的任职与指挥加成，不刷新战意、军略蓄积、独立冷却、每场限次和此前施放的状态。按日期保存任命记录，旧军略继续按当时人物和职位验证，读档不恢复旧职位或重算旧效果。

首发组织在战前任命后确定。奸雄额外名额不因战中伤亡或援军军议改任而撤销、重新授予；军议不得移动在场部队、重选意图或提前引入未到人员。后备补位与合法布阵仍通过双方共同执行。

战后先处理战损、人物去向、撤离交接及军团解散，再检查仍存在的军团。有效职位保留；玩家缺失职位保存为待任命，显示对话框，确认前暂停世界推进，关闭与读档均不能自动批准。AI 用 recommendArmyAppointments 选择本军团合法人员并调用同一 appointArmyRoles 原子校验，后台完成。城内独立部队、已解散军团及没有可任命现役者不弹军团任命。处理与保存校验位于 postbattle-appointments.mjs，战报记录实际变化。

回归覆盖援军实际抵达、本军团范围、零兵和撤离人员资格、玩家缺职读档继续选择、AI 后台任命、真实退却与阵亡结算、旧军略持续效果与确定性续战。界面验证入口为 npm run verify:battle-decisions-ui，包含桌面、手机和保存读取。

本轮交互细化：已有部队的城市从出征直接进入选队，编制作为可返回的可选入口；能力、兵力、战法、羁绊与对已选成员的友好度在同一张表比较，完整矩阵按需展开，选队与编制往返保留已选阵容。禁用原因共用只读资格校验，分清缺任命、超过队数、人员状态和路线限制，不读取隐藏敌情。运输横屏参数栏独立滚动，物资、抵达时间和风险固定显示，返回核阅保留栏内滚动位置。成功提示显示实际城市、人员、命令及等待状态，辅助文字至少12px、常用表单控件40px，触屏主要控件44px。

交互连续性：运输数量输入时仅更新摘要和资格提示，不替换输入框或下令按钮；输入后可一次点击继续，小数、负数及库存不足立即显示实际原因。运输 ETA 与实际移动共用 `personnelRouteDays`、`personnelSpeed`，计入运粮特性与接力逐段停驻，往返运粮明确显示首批抵达时间。出征已选条可逐项移除，复用原选择处理器清理依赖项，键盘焦点转到相邻已选项。重复选中终点、任命或未修改的编制字段保留路线草稿，主动重置才清除中转点；拖动中按 Esc 只取消本次拖动，再按 Esc 才返回。以上均不自动提交、推进日期或消费资源。回归为 `npm run test:interaction-continuity`、`npm run verify:interaction-continuity-ui` 及既有人员移动、选路和草稿往返验证。
