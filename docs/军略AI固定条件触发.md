# 军略AI固定条件触发

双方AI按固定顺序、固定条件选择首个满足资源、冷却及限次的军略，不比较现场收益、兵力权重、伤害预期或未来接敌。范围军略仅比较有效目标队数和矩形方向；相同覆盖保持稳定顺序。军略选择不读取未来随机数。

用户确认保持简单判断：先检查蓄满、冷却、次数和提供者是否合法，再按下表固定顺序检查“有／没有”目标条件，施放首个满足条件的军略。不因双方强弱或当前局势改变优先序，不等待更佳时机，不组合多项军略规划。治疗不比较伤兵多少，驱散不比较异常严重程度，雷火不估算敌我损失；范围只数合法有效目标，额外出场沿用已有补位规则。

| 顺序 | 效果 | 条件 |
| --- | --- | --- |
| 1 | 驱散 | 有可驱散的战斗异常，缺粮不计 |
| 2 | 救治 | 有本场可救伤兵 |
| 3 | 额外后备 | 存在已经抵达的可用后备 |
| 4 | 战法整备 | 已到存活部队有主动战法次数缺口 |
| 5 | 无敌 | 有尚无无敌保护的合法友军 |
| 6 | 魔免 | 有尚无魔免保护的合法友军 |
| 7 | 眩晕 | 有可合法控制的敌軍 |
| 8 | 八阵 | 有可受阵中异常影响的敌军且本场未使用 |
| 9 | 火攻 | 有未灼烧的合法敌军 |
| 10 | 伏兵 | 有尚未伏兵的合法友军 |
| 11 | 神速 | 有尚未神速的合法友军 |
| 12 | 护盾 | 有护盾未达兵力上限的合法友军 |
| 13 | 封锁 | 有已到敌方后备且封锁未生效 |
| 14 | 雷火 | 有至少两队可见在场敌军且本场未使用 |

额外后备使用双方共同后备排序，遵守实际到达、真实部队、合法空位及首次入场规则，不为凑羁绊挑选队列。玩家保持既定队列。雷火触发不估算敌我伤害收益；风险由共同随机结算承担。整备仅检查实际次数缺口，不预测下一次战法施放。

范围没有有效落点则跳过，八阵允许玩家空地布阵而AI仍按实际可影响敌军落点。前项冷却、耗尽或无目标则检查下一项，没有可用军略时保存进度。自然充能、目标、强度、冷却、次数及保存规则双方共用，见[施放规则](军略资格与施放-规则51.md)。

逐项测试使用正式 createScenario → lockDeployment → stepBattle 自动施放流程，不调用手动军略、不注入进度或战意。合法固定阵容和兵力，冻结无关行动以隔离触发条件；刷新军略所需的战法消耗来自实际交战。四个种子分为开发与独立验证，交换双方；每项8次成功自动施放、2次条件不足保留进度，并检查实际效果、冷却及施放前后的确定性读档。八阵、奇兵、整备、雷火另验证真实再充能后不会突破每场限次。

当前120次自动施放、30次条件不足验证全部通过。修正全军魔免将避战友军计为可用目标的边界，避免反复选择被共同施放器拒绝的空目标军略。逐项原始结果与验证存档见[AI验收表](../outputs/stratagem-ai-every/result.md)及同目录 result.json、saves/；这属于机制验收，不作为战役平衡结论。

回归入口 npm run test:stratagem-ai；复测及生成逐项记录 npm run audit:stratagem-ai。
