# 引擎优先：规则 35 第一批修正

> 本文保留规则 35 的第一批记录。当前规则 36 继续修复军略时序和攻城支援，见《军略时序与攻城支援-规则36.md》；本批原始数据已归档至 `rules35/`。

处理顺序是：先解决配阵与战斗引擎的不合理行为，再评价兵种、战法、军略和武将平衡。规则 33/34 的胜率报告保留作历史定位证据，不能用来指导规则 35 的数值调整。

## 本批已修正

| 原问题 | 修正后的行为 | 验证方式 |
| --- | --- | --- |
| 自定义对战继承曹、袁不同战略姿态 | 双方均衡起步；既有战略/剧本姿态保持原设定 | 同一阵容换到两侧，派生攻防一致 |
| 军师仅按最高智力选择 | 优先补充主将没有的军略，新增数量相同再比智力；无可补军略时按智力选取 | 关羽、马谡、张辽组合两侧都选到张辽，不再遗漏三项军略；无军略组合仍合法 |
| 自动把主要输出骑兵选为医辅 | 用当前兵力对应的派生输出能力识别主力，武力型主力骑兵不被医辅选择覆盖 | 赵云 6000、两队各 500 的真实自定义配置保留突击配装 |
| 高统率少兵队被当主要承伤者 | 枪戟承伤人选综合当前兵力与派生防御 | 100 人高统率队与 3000 人普通枪队对照 |
| 辅兵与实际主力脱节 | 先布置主力，再优先将辅兵放到主力旁或后方，覆盖协阵 | 简雍与赵云开局相邻，真实协阵目标能找到来源 |
| 骑兵固定翼位，不看敌方部署 | 先避开可见枪戟集中方向，再优先接近远程目标；仍使用固定确定性规则 | 将可见枪阵从上翼移动到下翼，骑兵换到相反侧翼；锁定后不重排 |
| 剧本初始化期间AI读到尚未完成的阵位 | 等剧本格位、波次、建筑创建后重排，再恢复明确指定的敌军配装和格位 | 既有剧本、地形、存档与接敌回归通过 |

以上是决策规则修正，不是最优配阵搜索。没有读取未来随机数或模拟未来胜负选阵；敌方仍使用固定规则。自定义界面的说明同步显示军师规则与双方均衡姿态。

## 验收证据

- 全量 `npm test`：**471/471 通过**，见 `outputs/engine-foundations-tests.txt`。
- `npm run audit:engine`：**200 局**，56 局典型情境覆盖双方出生侧，144 局覆盖三类玩家阵容、三种敌阵与四种兵力分配。
- 玩家兵力分配包含均分 1500×6、主核 6000＋600×5、双核 3500×2＋500×4、极薄辅助 4116/2941/1765/60/59/59；敌方均为 9000 总兵力。
- 每局检查配阵重复执行不改变结果、不修改玩家侧或随机数；真实战斗检查格位、配装、有限兵力、合法军略与第 20 步存读档续战。
- **0 局超时结算**。存活单位位置和兵力同时不变的连续步数最多为 3；它是停滞观察指标，不是完整的行动价值证明。
- 不设胜率通过线，胜负留在逐局记录中。记录见 `results.json` 与 `runs.json.gz`，同时保存规则版本、种子与运行时源码 SHA-256。
- 本轮用哈希核对 `unit-stats.mjs`、`tactics.mjs`、`tactic-power.mjs`、`tactic-outcomes.mjs`、`passives.mjs`、`famous-officers.mjs`、`expanded-tactics.mjs`、`data/officers-source.json`，与规则 34 平衡排查结束时完全一致。

旧的骑兵策应回归曾同时要求玩家必胜。本轮保留“真实接敌、专属与策应均施放、非超时结束、确定性续战”，移除不属于行为契约的必胜条件。原控制战法回归固定回原来的接敌阵位，继续验证原胜负样本与物理配装对照；没有为了得到预期胜负重新挑种子。

## 后续仍按引擎阶段推进

本批通过不等于所有引擎机制已经验收。下一步应继续检查目标选择与转火、移动/拦截/脱战、军略决策时机与双方指令时序，以及技能说明、目标选择和最终结算是否一致。发现问题先做行为复现和最小修正，再跑相关机制与典型情境回归。

只有与待评价对象相关的引擎行为通过后，才重建当前版本的平衡基线，依次评价兵种与战法军略、非均分兵力收益、名将与普通将的角色价值。不能用某个阵容胜率提高来替代引擎正确性验收。

规则更新为 35，按项目存档约定旧规则存档需重开。本轮没有浏览器点击验收；新说明文字已同步，但行为证据来自真实战斗引擎的脚本操作。
