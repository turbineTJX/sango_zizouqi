# 引擎第二批修正：军略时序与攻城支援（规则 36）

本轮继续优先处理引擎行为，没有进行兵种、战法或武将数值平衡。

## 1. 电脑使用刚蓄满军略的时机早于玩家

原顺序是：本步充能 → 电脑军略 → 双方部队行动 → 返回玩家操作。电脑能用本步刚蓄满的资源影响本步部队行动，而玩家在真实界面以及逐步模拟中都要等这一步完成后才能下令。

现在保持原来的自然充能公式，改为：本步充能 → 双方部队行动 → 战果判断 → 未结束时电脑军略 → 返回玩家操作。双方在同一个完成步骤的边界使用新资源，其效果从接下来的战斗步骤参与行动与持续结算。

这不是把双方军略改成同时提交。电脑仍自动判断，玩家仍可暂停操作；本次消除的是电脑在玩家无法介入的步骤内部提前使用新充能的差异。没有修改军略阈值、冷却、强度或持续时间。

边界规则同时明确：已经结算战果的步骤不再追加电脑军略。新增测试用真实战斗自然积累资源，在第 32 步截止时恰好蓄满，验证不消耗资源、不补发指令，后续调用也不改变战果。

## 2. 清空守军后，友军支援被错误阻断

部分友军目标战法放在“若没有存活敌军则返回”的判断之后。攻城时可能仍有城门、真实伤兵、已满足的战意与冷却，但义勇兵、救护等支援无法进入自身的友军目标判断。另一些辅兵治疗原本在这条判断之前，行为不一致。

将名将支援、基础救护/振旅/策应、净化的友军目标判断提前。伤兵、距离、护盾、收益判断、战意与冷却规则仍由原函数执行；敌军目标战法继续要求合法敌军目标。

复现使用通过真实场景创建入口和存档校验的攻城夹具：赵云骑兵 6000、刘备枪兵 3000、荀攸弩兵 3000；敌方枪弓弩各 1500；城门 60000 耐久，用于保留守军溃败后的观察时间。全程从零战意开战，不注入战意、冷却或伤兵。守军自然被击溃后，记录义勇兵和救护施放次数，再继续攻城；两者均继续实际施放，并能确定性续战至破城。
