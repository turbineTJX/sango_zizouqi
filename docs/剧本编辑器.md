# 剧本编辑器

入口：普通模式 → 剧本编辑器。七个内置剧本作为模板保留，修改保存为独立作品。

## 内置剧本的参考配置

七个内置剧本共用从参考项目读取的832名公共人物配置，编辑器创建副本时完整带入身份、所属势力、驻地、登场及在野日期。公共人物能力和本机自建人物不由此次剧本导入覆盖。

完整运行来源为参考项目 `Build/Content/Scenario/Scenario.json`，其名称是“测试剧本-英雄集结”，起始日期251年1月1日。另核对 `Data/Export/Scenario/剧本配置.xlsx`、`Scenario1/测试剧本配置.xlsx` 与 `Scenario2/剧本配置.xlsx`：三表都是251年版图或测试地图，832条登场年均与运行剧本一致；表格的势力编号和身份枚举与运行数据不同，归属及身份以完整运行剧本为准，不混用表格旧编号。例如阎圃按运行剧本归张鲁、驻汉中。

| 来源字段 | 本项目处理 |
| --- | --- |
| `BelongForce` | 映射到本项目势力；历史剧本及四势力版按已有年代或区域规则归并 |
| `BelongCity`、`CurrentCity` | 按公共城市编号对应驻地；本势力不拥有原驻城时采用已声明本城 |
| `state` | 区分在职、在野、死亡与空白占位人物；不把在野人物提前编为驻将 |
| `appearance`（表格 `yearAvailable`） | 来源登场年，仍遵守本项目16岁登场下限；只精确到年，使用该年1月1日 |
| `yearBorn`、`yearDead` | 记录来源生卒；历史开局排除已去世者 |

“群雄集结”保留37个独立有城势力及439名来源在职人物。“英雄集结”将这些在职人物归并为四方，来源在野继续在野；两个架空剧本按来源说明不限制人物生卒与登场年代。五个历史剧本使用各自的领地和势力映射，未来在职人物按日期进入预设势力，未来在野人物按日期进入在野。参考项目没有对应年代的完整历史存档，这些历史剧本属于年代适配。

例如司马懿来源登场年为198，诸葛亮208，邓艾216，姜维225；在早期历史剧本中，日期未到者不会提前出现。未来预设驻城失守时，人物在原地点进入在野，不强制离职、不夺城，也不重新抽取地点或日期。

来源快照与校验值保存在 [参考剧本数据](../data/design/reference-scenario.mjs)。更新参考项目后，可运行 `node scripts/import-reference-scenario.mjs <参考项目目录>` 重建，再执行剧本回归及设计表导出；游戏运行不依赖参考项目路径。

## 开局配置

| 页签 | 可设置内容 |
| --- | --- |
| 概要 | 名称、说明、起始年月日、是否限制人物年代、默认等级；同步已保存的武将库 |
| 城池 | 归属、金、粮、预备兵、治安、十二类设施等级、城防完好率、已完成科技 |
| 势力 | 名称、旗色、君主、本城；从公共或自建武将建立新势力，移除已有势力 |
| 武将 | 初始身份、所属势力、驻地／登场地点、等级、功绩余量、忠诚、现役、伤兵、基础兵种、太守或六方向任职、登场日期与在野起始日期 |
| 外交 | 势力双方的交战、和平、互不侵犯或同盟，关系值及期限 |

城池资源及设施等级留空沿用默认，填写0表示空仓或零级。设施上限与本城资质共用现有规则；已完成科技须符合城市资质并包含前置科技。城防完好率作用于既有城门耐久，现役与伤兵按武将带兵上限检查，不混入预备兵。

新势力可选择任意尚未担任君主的公共或自建武将。选择本城后，该城改归新势力；君主会设置为在仕并驻扎本城，原驻将归属需要另行核对。更改已有势力的君主或本城也会调整该君主的开局驻地。君主必须在开局时已登场，不能同时担任两个势力的君主。

“同步武将库”将已保存的人物资料及自建人物合入当前剧本。剧本本身保存人物资料，导入者不必事先安装相同的本机武将库。姓名、能力等资料仍在武将编辑器维护；剧本页负责安排开局身份与时间。

## 人物登场与在野日期

每月按30日计算，日期填写如 `200-05-21`。初始身份包括在仕、在野、被俘、死亡及不登场；未逐人配置者沿普通人才规则登场。

- **登场日期**：控制该人物何时开始出现在世界中。日期未到时，不占用驻军、职位或在仕工资，不能被发现或招揽。
- **在野起始日期**：仅适用于在野身份，控制何时可按正常规则被发现、接洽和招揽；不能早于登场日期。两个日期都到达后才进入在野。例如5月21日登场、5月23日开始在野，则5月22日仍不能招揽。
- **在仕登场**：到日期时进入预设势力的驻城。若该城届时已不属于该势力，则在该地点进入在野，不凭空夺城、搬城或转投新主；未投入世界的预设兵员不交给在野人物。
- **留空日期**：已配置的人物默认随开局登场；未逐人配置者继续按人物年代及现有活动城市配置处理。历史人物的生卒与登场资格也按其配置的登场年份检查。
- **被俘开局**：须选择原势力、不同的俘获势力，以及俘获方拥有的关押城，沿既有赎回、释放和人员返程规则处理。

在野起始日期只控制在野登场，**不安排在仕武将定时离职**。登场和在野结果写入游戏状态，读档不会重抽日期或重复生成同一人物。

逐人等级覆盖概要中的默认等级；功绩填写本级余量，不能越过下一级门槛。太守及六方向任职使用现有资格和岗位容量检查。初始关系不生成势力军师、爵位或都督辖区等新职位。

## 日期、外交与校验

可从任意月日开局。第一旬可以不足十天，例如5月20日开始，执行一天后进入5月21日筹划；后续按1、11、21日的共同旬界推进。初始库存、已完成科技和任职属于开局输入，不伪造已经办理过的事务或收入。

未逐对配置的外交沿用交战状态。初始和平、互不侵犯与同盟直接成为开局条约，期限包含开局当天，并沿既有条约处理器到期；不扣谈判费用，也不发谈判或履约功绩。

正式保存、导入和选择势力时，先校验完整配置，再用相同的新局生成器及存档校验器预检。君主、领土、人物唯一性、任职、兵力、科技、年月日或外交不合法时阻止使用，并保留当前草稿。未完成的人事归属、空名称或越界数值仍可保留为草稿。

## 保存与交换

撤销、重做保留本次打开后的最多60次修改。草稿自动保存在本机；切换模板或导入覆盖未保存草稿前须确认。删除作品也须确认，当前草稿仍可重新保存。

正式作品和草稿使用独立 IndexedDB 数据库 `sango-scenarios-v2`，最多64个剧本。第2版作品库与第一版分开保存，不覆盖旧库。当前导入导出采用 `sango-scenario` 第2版 JSON，文件上限2 MiB；不混读第一版剧本或旧游戏快照。编号重复的导入保留为新副本，检查或写入失败保留已有作品。

每场游戏保存剧本与人物库快照。运行中的势力编号按剧本内容隔离，同名或同原始编号的另一份剧本不会改写既有游戏的君主、颜色、人员、日期或外交。之后改删本机人物、作品，或在另一台设备读取存档，仍使用原开局内容。
