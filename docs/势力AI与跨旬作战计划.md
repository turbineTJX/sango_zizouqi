# 势力 AI 与跨旬作战计划

当前已接入统一全国的最终目标、区域方向、势力战略选择、武将素质与静态战力、来源城资源及后续补兵能力的综合评估、有限准备预测、攻城任务规划、有限准备修复及后期分城协同，战略存档65、AI结构18、战略结构13。战斗规则版本由 combat-rules.mjs 定义。实际命令、资源、内政成败、人员行旅和战斗继续使用共同执行器。旧AI结构直接拒绝，不迁移。

全流程的 AI 环节、输入输出、建模公式、算法接口与模拟评价口径见 [AI架构与决策评价方法](AI架构与决策评价方法.md)。本文侧重势力战略的执行规则与专项验收。

目标军资收益只采用新鲜合法情报中预计可接收的库存：武力占领保留50%金、50%粮、20%预备兵，中立城先按小额地方库存封顶。用于金粮评分时先计算接收量，再按既有35%参考价值折算；实际损失在易主时一次结算并保存交接凭据。中立期间不积累周期产出，接收库存不提前计入出发资金或粮道。具体库存及交接规则见[城市钱粮与预算](城市钱粮与预算.md)。

出征评估在观察驻军外加入临时守军和及时援军。临时动员仅按报告中的本城金、可用预备兵、本旬额度和合法兵种单价估计，最多一支默认目标兵力；不读取隐藏在城人事。及时援军按最长集结、进攻行程和4至8天交战窗口检查道路到达时间：已朝目标行进者完整计入，潜在城市出兵最多一半驻军并留一天响应，可能改派的野战军团取75%；交战中和迟到者排除。同一支援军不重复算作占后反攻。中立目标考虑接触前后两天可见敌对争夺者，独立势力取最强一方；旧报告每一天增加4%风险余量，上限30%。

双方战力采用 `static-v2-no-bonds` 静态模型，共用剔除羁绊收益后的攻击间隔、攻击、防御、军纪和可用固定战法，计入合法任命、兵种克制、公开地形和后备折扣。策略与评估忽略己方及敌方羁绊点数、档位、组合、入场收益和属性增量；实际战斗仍结算偶然形成的羁绊及特性。模型只做特征汇总与闭式计算，不创建或完整推演战斗，不搜索羁绊编组、部署或未来军略。默认战损预测为 `attrition-v3`，依据攻守优势计算非线性伤亡近似，并按实际补兵金、预备兵和携粮复核。

常规进取／均衡／谨慎基础攻守优势为1.5／1.7／1.9。实际库存和征补额度能覆盖战损、回城后两旬的补兵预测也有余力，且目标情报不超过3天时，要求最多降低0.5，最低为1.2；未知和旧情报不获得这项整补余力优惠。君主本旬愿冒险时另按下述有限容忍处理。钱粮与后续产出不增加战场战力。编组不足时继续加入合法真实部队，留守按实际剩余阵容计算；战略摘要、求和压力与出征共用包含武将素质的战力模型。

整补证据版本2逐城保存完整预测期所需的初始资源、各类库存缺口及库存能否修复。持续口粮、补兵金和预备兵分别反馈给候选筹备及执行修复；提高对应的真实库存目标，保留原有工资、携粮、粮路和训练预算。配额、期限或容量限制无法靠加库存解决时不建立虚假筹备。立项与执行均扣除真实拟装运携粮，既有承诺不重复扣；发兵只释放实际装走的粮，整补粮草按整个预测期保留，不只补首次负库存；预测和诊断均不支用或产生真实资源。

### 君主每回合的战争风险偏好

性格1／2／3／4的基础冒险概率为12%／18%／35%／65%，再加 `(50－统智均值)÷100×20%` 与 `(50－政治)÷100×10%`。己方超过3回合没有真实交战，每多一回合加2.5个百分点，最多15个百分点；前20回合整体乘0.35，最终限制在5%至85%。属性取当前实际君主，范围0至100；只统计己方参与的真实战场，空城接收不重置交战间隔。主动意愿不会随等待无限增加。

每旬完整评审由独立选择随机源抽一次，整旬所有目标使用同一偏好。君主、属性、交战间隔、概率和抽签结果保存于势力及评审记录；计划的军事证据复制当时的偏好，下一旬新的谨慎选择不替换原计划的决心。每日、候选查询、浏览与读档不抽签；专用选择状态与战斗、事件随机状态分开，算法回调不接收任何游戏成败随机状态。

愿冒险、预计战损不超过55%且真实补兵可承担时，谨慎／均衡／进取优势要求最多再减0.2／0.35／0.5，最低1.15／1.05／1.0；目标意愿分别增加10／24／40分。允许不确定战果和短期收益较差的选择，原始战力、战损与费用不变；守备、经济人员、实际库存、携粮、条约及共同粮路仍可否决。实现见 [strategic-temperament.mjs](../strategic-temperament.mjs)，机制回归见 tests/strategic-temperament.test.mjs，自然节奏结果独立记录。

补兵能力逐城预测，保留工资、外交和军令承诺，使用当前设施与留守太守的稳定产出、未随军人员已经开始的运营及实际安全在途物资，不假定新设施、新人员、占领库存或未装运粮车。征补额度每旬重置而不累积，模拟补兵在预计回城后才开始，扣真实兵源和按现有兵种、装备计算的金费用；必须在回城后20天内补足，整个预测最多180天。启动成本、部队、携粮和安全粮道仍须实际满足，补兵预测不提前入库。闲置内政任职不计虚构机会成本；已开始事务只按真实剩余时间和已投入费用折算。资源余力对战损、补兵及行程负担的折算最多两倍。

行军中按真实士气、缺粮、新敌情与当前补兵能力复核；常规持续优势门槛比当日常规出征要求低0.2、最低1.1，再应用已承诺计划保存的有限冒险容忍。实际返城补兵据点采用军团当前 homeCity，集结后不继续使用原出兵城。必要时取消并真实回撤。模型编号、输出、承伤、攻守战力、动员、援军、报告日期、预计战损、君主偏好及逐城补兵证据随目标和候选保存。回归 `npm run test:precombat-assessment`、`npm run test:ai-decisions`；自然验证用原始全AI剧本，优势要求不能宣称为精确胜率。

## 战争规模与节奏

新编出征军团的携粮容量共用 armySupplyCapacity：每队至少900粮，按本队实际现役、伤兵口粮的30天量扩大。9000人的一队为2700粮，3000人为900粮。容量是可装载上限，实际出征仍从来源库扣粮，不读取未来收成，也不在途中扩大现有军团库存。已经保存的军团容量和货物仍按实际数值执行；拆分、合并按已有容量与粮守恒。出征计划、排队军令、外交援军、粮路守军、预测与玩家确认界面全部采用同一新编容量，每日耗粮、粮仓与道路吞吐不变。

用户确认的节奏窗口按战略回合数划分：第1–20回合为前期，第21–60回合为中期，第61回合起为后期。每回合为10天，60天只完成6回合，仍属于前期。阶段直接使用 s.turn，天数只用于真实行旅、粮耗、工资和补兵计算。统计按回合窗口分别记录实际战斗、出征、空城占领和参战军团，不能以短期出征次数证明中后期战斗频率。

回合阶段给出可选规模，实际容量继续约束执行。前期最多一项进攻，集结范围一回合；中期可负担城市合计至少三队时，集结范围扩大至两回合，支持持续攻取。预算不足、实际可用部队不足三队或存在严重供给危机时仍采用小规模行动。可负担须逐城满足本旬工资、承诺、储备及口粮；守备、人员资格和兵源仍经正常准入复核，回合到达不强迫宣战或生成部队。

后期拥有至少四座城市、至少两座城市可负担且合计十队合法可用部队时，启用协同规模，来源范围扩大至三回合。超过六队的主攻在各城按最多六队分团，保留真实出发城及整补基地；单座城市也可提供多个军团，城市来源名单不受单军团十队上限限制。全部军团通过情报、预算、守备、人员、工作时机和共同粮路复核后，保存统一预计接敌日，远路先发、近路后发。各团任命自身军团长、军师，正常支付装粮并沿真实道路行军。后来部队按真实援军入口参战，不提前计算抵达或给予协同加成；路线或速度改变导致超过两天接敌偏差时撤销原安排。早中期及小规模行动继续实际集中集结。三种小编组外保留完整合法编组候选；容量不足时采用可承担的规模。

协同阶段最多两项进攻，只有已有主攻都进入进攻阶段且没有严重供给危机时，才在下一次旬初评审选择独立第二路。新计划不重复目标、人员、集结城或原兵源城；路粮吞吐扣除现有军团实际需求。每个计划独立保存真实钱粮兵源需求，继续每日执行安全检查。

出发时保留实际可留存的补兵金及预计返城、补兵期间的固定收支缺口，未开始的可选事务和常规升级不消耗该缓冲。没有提前支付或获得未来收入。本旬已占用征兵额度只扣本旬，新一旬恢复本城实际总额度；额度不跨旬累积。当前库存补兵覆盖按可用金和预备兵计，额度约束在预计回城后的逐日模拟中判断。

前、中、后期的集结上限依次为1／2／3回合，容量不足时缩回一回合；计划在立项时将有限准备预测的等待时间一次计入总期限，再覆盖实际集结、进攻行程、预计攻城及一回合执行余量，不能沿用短期个人耐心把可行远程协同挡在交战前。长期行程的评分负担与战损补兵负担一起按整补余力有界折算，最多两倍；实际粮耗、费用、当前工事、人员及守备条件不折减。

机制回归见 tests/strategic-tempo.test.mjs；阶段能力不等于已证明所有剧本的自然战争曲线，实测窗口见 [AI互战行为与决策审计](AI互战行为与决策审计.md)。

第21回合起，具备中期实际容量而局部进攻不足、且没有就绪进攻时，也可在旬初比较最多三项前沿集中准备。沿共同安全道路调任两旬内可到达的真实现役，保留来源守备及必要经济负责人；不把在途人员计入目的城，实际到达后在下一旬重新检查出征。前20回合不启用此后备路径，后期多军团协同的城市、人数和费用条件不变。

前沿准备保存为独立、有限的集结承诺，每势力最多一项，固定两旬到期。暂时达不到完整进攻优势时，也可选择最多六队真实可调现役，至少弥补当前兵力缺口的10%；该步骤先核对安全调任、目的城钱粮和来源防务，不要求尚未形成的整场攻势提前通过粮路预测。完整集结方案仍核对全程供给。准备不宣战、不建立虚构军团、不改变正式出征门槛。

每项承诺保存选定人员、实际已发令人员、实际抵达人员、地点、目标、预算、兵力需求和原始期限。每天最多通过共同调任入口安排六人，后续发令及等待事务结束后的真正出发再次核对目的城钱粮、安全道路、来源守备和剩余抵达时间。在途及排队人数仅避免重复调动，不提供目的城战力；实际抵达的人员保留给本次准备，至下一旬正常评审才判断本步完成及是否进攻。已有合法就绪进攻优先，可结束准备承诺再使用实际到齐的人员。

无在途或等待任务且十天没有实际进展，或两旬固定期限已过时，结束准备。归属、目标条约、道路、实际防务或人员去向变化也可取消。只清除本次未执行调任，不传送或自动召回正在行旅的人。关闭后已调人员二十天内不参加其他集结地或普通内政调任，仍可在当地工作及合法出征；取消的同一出发城与目标二十天内不重新立项。每日调用和读档均不重置期限。规则与参数见 strategic-concentration.mjs、战略规划表，机制回归见 tests/strategic-concentration.test.mjs；自然观察单独记录 concentrationTrace。

中期来源城已经到齐的部队不再按单军团十队上限截断；完整实际编组进入候选和费用、留守、共享粮路核对，出发时仍按每军团最多十队分开建立。后期仍按六队及保存的接敌窗口协同出发。中后期候选额外保留一次完整阵容比较，不用前三个相近的小编组掩盖已具备的集中兵力。

空城的工期在立项、出发预算和逐日复核中保持一致：合法情报未显示驻军、动员或及时争夺者时，不因为城门仍有耐久而虚构攻城时间。行军中发现实际守军或及时援军后仍重新计算战力、攻城、补给及回城整补，不保证原计划继续执行。

城市告急时，只为该计划自身来源城、集结城的防务，或能在救援期限内出发抵达的真实待出发计划部队解除进攻承诺。无关远方城市受袭不直接召回无法及时救援的进攻军；当地仍检查共同守备、真实可达援军及费用，不减少敌军威胁或提供额外守军。

空城可以用少量实际兵力换取城池和后续产出，应保留高优先级。AI以相对低战损逐步占城、消灭势力和最终统一为目标，不为增加场次降低空城价值或额外奖励交战目标。无战间隔是诊断依据，用于查找预算、人员和执行卡点；合法、划算的空城占领不应因此被否决。原君主性格与风险选择保留，共同战斗规则和真实战争费用不变。

## 决策、评价与预测接口（2026-10-09）

战略算法从真实规则和执行流程拆开。默认实现采用效用、包含统一收益的成本收益、启发式战损和两旬准备预测；准备预测同时考虑实际在办运营的公开预期与已装载的安全运输，军事预算允许尚未开办的可选工程让位。算法接口本身不提供资源或战斗加成。

```mermaid
flowchart LR
 A[合法情报与真实规则] --> B[事实与可执行候选]
 B --> P[预测器]
 B --> E[评分器]
 P --> E
 E --> D[候选选择器]
 D --> G[承诺与资格复核]
 G --> X[共同命令执行器]
 X --> A
```

| 接口 | 默认编号 | 同步输入 | 允许返回 |
| --- | --- | --- | --- |
| selector | utility-v1 | 已评分候选、合法情报、君主特点、当前目标 | 已有候选的id |
| goalEvaluator | utility-v1 | 一个阶段目标候选、合法情报、君主特点、正式参数 | score |
| offensiveEvaluator | cost-benefit-v3 | 出兵事实、统一收益、预计战损与逐城补兵能力、君主特点、正式参数 | score、benefit、cost、workCost |
| battlePredictor | attrition-v3 | 静态输出与承伤、闭式损失占比、工期、耗粮、补兵单价、来源预算与情报日期等事实 | estimatedLosses、consumedGrain、replacementGold、militaryGold、counterPower |
| preparationPredictor | two-turn-v2 | 情报上下文、逐城需求、有限窗口 | feasible、readyDay、reason |

五项可以独立组合。`strategic-algorithms.mjs` 管理注册、版本标识、配置、输入隔离和输出校验；`strategic-algorithm-defaults.mjs` 与 `strategic-predictors.mjs` 只处理数据。`strategic-ai.mjs` 的 `offensiveFacts` 与原有候选生成器负责把真实规则转换成输入，再独立检查守备、人员、实际携粮和来源预算；`strategic-policy.mjs` 负责计划承诺、切换门槛、目标落地和记录。

候选id关联当次具体编组，选择器不能另造人员或命令。评分不能直接准许出兵，预测不能提前入库；已有进攻承诺、小幅变化的持续性及军令生效复核仍由共用流程执行。目标切换门槛保护已存在的具体军事目标；默认发展与恢复没有待保护的具体行动，不用该门槛压住更高评分的合法候选，实际出兵仍须通过守备、预算、人员和携粮复核。评价的分值须采用与正式最低收益及切换门槛一致的尺度。预测输出限制损失范围、整数费用和未来窗口，非有限数值、异步结果、额外字段或伪造候选均拒绝。当前没有插件化内政、外交评分、固定战斗选敌或军略触发规则，它们继续沿用各自现有流程。

回调只收到结构化克隆后递归冻结的值，不收到 `s`、随机种子、预存成败或敌方秘密命令。目标情报明确给出是否已知、是否可见和最后观察日期。回调可以复制数据做有限搜索；新增可执行候选类型或预测所需特征应扩展规则适配器，不绕过迷雾接口。该边界是代码接口隔离，注册模块仍是可信程序代码，并非JavaScript安全沙箱。

注册示例与接口替换测试见 `tests/strategic-algorithms.test.mjs`；可运行的保守选择器示例见 `tests/fixtures/strategic-development-algorithm.mjs`。新实现使用新版本编号，不能覆盖已注册编号。`registerStrategicAlgorithm(kind,{id,run})` 注册同步函数；在筹划期调用 `setStrategicAlgorithms(s,{selector:'my-selector-v1'})` 可替换单项并触发复核。当前五项编号保存在 `campaign.ai.algorithms`，每次候选记录保存当时的整组编号。读取自定义算法存档前必须注册同版本实现，否则拒绝载入；不保存函数或对旧档迁移。

自动模拟支持 `--selector`、`--goal-evaluator`、`--offensive-evaluator`、`--battle-predictor`、`--preparation-predictor`。外部模块须导出 `strategicAlgorithms=[{kind,id,run}]`，以 `--algorithm-module` 加载。结果保存配置、源码哈希及外部模块的入口哈希，模块加载或模拟期间改变源码会失败。按相同剧本、种子和天数分别运行，才可比较算法组合；登记编号的实现与模块依赖也应一同归档。

```sh
npm run test:strategic-algorithms
npm run audit:strategic-planning -- --scenario=guandu-200 --seeds=417 --days=3 --out=work/ai-default
npm run audit:strategic-planning -- --scenario=guandu-200 --seeds=417 --days=3 --selector=development-example-v1 --algorithm-module=tests/fixtures/strategic-development-algorithm.mjs --out=work/ai-development
```

机制回归覆盖算法替换、来源城预算和人员保护、真实运输、战争迷雾及确定性续跑。`tests/strategic-economy-planning.test.mjs` 另复现可选工程挤占军事预算、占城后巩固长期占用主攻、独立势力被累加为反攻联军、运营及运输未进入预测的问题；验证不提前发资源，不读取随机结果，低金开局仍依正常运营恢复。完整机制回归运行 `npm run test:strategic-planning`；通过不代表全年战争承载或胜率已校准。

当前实现的回归与冻结源码自然模拟结果统一见 [AI互战行为与决策审计](AI互战行为与决策审计.md)。短期样本和机制通过不证明全国统一或年度高强度战争承载。

## 势力战略与任务规划

势力先对已知周边势力确定进攻、防守或谋求和平的意向，再选择当前攻占、保境、恢复、和平或发展目标。前中期最多一条主要进攻战线，后期实际容量达标时最多两条；护路与战场增援最多三项，侦察最多两项。和平意向不改变敌对关系；真实条约生效前继续守备。

目标由实际可用兵力、城市独立预算、人员资格、合法路线、战争收益和君主倾向共同评价。最多检查32组集结城与目标，获得8项可准备的候选后停止；截断前保留当前目标、已知空城机会并比较真实路程，不按富庶程度排除可行目标。每组比较三种可行兵力规模，成熟协同阶段另保留一次全部合法部队的候选，达到最低优势后继续检查占后反攻、持续补给和补兵能力，必要时尝试更大编组。仍优先空闲人员，不为羁绊凑档或替补顺序另作战略搜索。

攻城任务保存侦察、补给准备、集结、进攻、巩固的依赖、状态、日期和真实执行引用。三项准备可并行，进攻要求情报、补给和集结均满足；巩固依赖实际占领。等待军令不等于军团已经出发，预测收入不等于实际入库，占领和巩固只由共同引擎的真实结果确认。筹备、集结和进攻保留军事人员承诺；占领后的巩固改为城市守备与恢复任务，释放原出征人员的额外承诺和主攻槽位，仍逐日检查真实守备，不能因建立新主攻而视作巩固成功。经济人员的需求提示不把本人标成不能办理内政。计划来源城分别保留自己的预算和预计战损兵源，不使用势力合计替代实际库存。

资源不足时，可在现有产能与预算支持下保留准备目标，提出各来源城的真实钱粮兵源需求，通过现有委任和运输准备。运输从来源城装载后扣款，抵达后入库；达到实际要求后重新评估出征。内政需求仅调整已有合法候选的优先级，不跳过工期、费用、额度、地点、成败或已批准提案。

第61回合起，局部兵力不足或从远方直接进攻无法维持粮路，且没有已经就绪的进攻时，还可提出前沿集中准备。每旬最多比较三项此类准备：按合法目标及及时援军估算所需兵力，只选择能在两旬内经安全道路调来的真实现役，保留来源守备、太守和经济负责人，并核对目的城集结口粮及后续出征携粮。兵员调任按实际运输速度计算，不按轻装人员速度错判路程。准备继续保存目的城 `defensePower` 需求；在途与待执行调任按完整阵容测量，仅避免重复派兵，不视为已抵达守备或进攻军团。实际抵达后下一旬重新经过完整出征评估；准备不提前宣战、不承诺战果，也不降低既有优势或费用门槛。

资源候选先进入有限预测，当前粮库不足不再提前跳过。已通过出兵研判、只有实际在途粮草尚未到达的方案可建立准备计划；补兵预算尚不足的目标只保留筹备需求，等下旬重新研判。守备缺口只有能经安全道路调来的真实后方兵力足以补齐时才建立筹备目标，保存目的城 `defensePower`，通过共用调任命令执行。来源城保留守备、经济负责人和太守，已有在途及等待调任只避免重复派人，实际到达后再判断目的城资格。前线武备可在正式主攻计划建立前按真实技术和预算购置器械。评审另保存最多32条准入原因及真实队数兵数，没有把未来训练所得兵力算作现役。

补给预测按真实道路成本和每日行程逐日计算去程、攻城停留与返程，携粮可跨越有限无粮道路段；每一天只从当日可连接的己方粮仓取粮，共用道路与粮仓吞吐扣除既有军团需求。出发携粮从来源库存扣出，来源口粮不重复计算已出征部队；消耗超过真实携粮与可达供给则拒绝。没有未来收入、待发粮车或占领敌仓。 路线供给按实际携粮、己方粮仓、本城口粮、道路吞吐和既有军团用粮核对，攻城营地只能是供给端点，不能提前使用敌仓。查询只在当次同步评审中复用。守备估计为敌方城内兵力保留至少一半，仅把真实行程十日内可达的潜在出征计入近期威胁；已经出发的来袭军团完整计算，己方实际驻城军团可补足守备，在途援军不能提前计入。占后反攻也核对抵达时间，远距离的道路邻城不自动形成即时反攻。

人才调任保存拟任岗位，实际到达后共同委任，并保护到首个真实事务尝试完成。普通后勤和可选任务不立即把刚到的人再次调走；真实缺粮救急允许中断并记录。人员离队、目的城失守、改程或已无可办空缺时释放任务，不永久占用闲人。辞官或势力灭亡转为在野时，同步解除本人调任承诺，使离职当日的年末保存仍然合法；这项清理不改钱粮，也不解除其他人员的承诺。回归见 tests/talent.test.mjs。

有限预测逐日检查未来两旬的耗粮、旬末收入、费用、库容和兵源，入库前断粮则拒绝以未来收成为准备依据。在办集市、督耕和预备兵征集按公开成功机会估算完成日的基础成果，共享实际每旬办理额度，不读取预存随机数，不预测连携、意外献赠或未开办事务的成果。只计当前已装载且路线安全、未受阻的运输，按实际剩余路程和运输速度估算到达日；不预测尚未装载的后续批次、中转后未确定的下一程或路线封锁解除。未开始事务、待发运输和债务的单次预算不每旬重复扣除；外交行资等周期费用继续计算。运营可能失败、运输可能被截，所有预测只作准备候选判断，军令生效前仍复核实际库存。当前战损和攻城时间沿用共同规则上的启发式估计；尚未接入经过独立战斗样本校准的模型、完整敌方反应搜索或强化学习。

每旬初（第1、11、21日等）完整评审一次，统一刷新交给战略选择器和目标评分的合法视野、城市情报与本方资源输入。旬内不重建全国战略上下文，也不因新情报或筹备资源就绪提前选择新的阶段目标；未建立作战计划的筹备目标等下一旬复核。实际地图视野、斥候观察和带日期的情报仍随共同模拟更新；每日推进已有计划，并检查实际威胁、供给、人员、路线和期限，不安全的军令可以取消或回撤。小幅评分变化保留可行目标，明确更高价值机会才调整。当前目标、来源需求、最近十二次候选评分和选择原因随存档保存，查看不推进日期、不消费模拟随机数。

正式参数见 [势力战略规划一览表](design-tables/势力战略规划一览表.md)，源码为 `data/design/strategic-planning-rules.mjs`。情报快照剔除真实随机种子、预存结果和敌方秘密军令；外交与内政敌情判断也使用共同情报投影。外国库存只采用当前或最近观察，未知库存使用有上限的交涉请求；请求不证明对方有货，实际接洽和签署重新核实。开局外交联络地点保存，不能随未知君主迁移自动更新。未侦察的外军不按零兵力计算和平机会成本；出使按已知请求出发，外方人员、库存和承诺到实际接洽时才复核，签署及履约仍须通过完整共同校验。

机制回归 `npm run test:strategic-planning`。自然验证 `npm run audit:strategic-planning -- --scenario=guandu-200 --seeds=417,643 --days=30`，使用原始剧本的全AI控制、普通迷雾和正常意外，通过共同逐日引擎记录战略候选、目标与任务变化、真实出征规模、逐城预算缺口和缺粮。结果包含源码哈希、完整存档和事件，源码变化拒绝宣称通过；`--source` 可指定独立基线运行目录，`--out` 指定结果目录。短期完成及机制通过不代表年度战争承载或战略胜率结论。

## 决策与执行

- 势力每旬初统一刷新战略输入并评估目标，旬内执行已有意向和计划，紧急安全检查不触发全国目标重选；并非每旬必须出兵。前中期最多一项主攻，后期容量达标且既有主攻已出发时允许独立第二路，占城后的巩固不占主攻槽位。每日处理紧急守备、补给、计划推进和运输。
- 一项计划就是当前主攻战线的协调记录，记录目标、集结城、出兵城、武将身份、待用粮草、阶段、截止时间与原因。城内仍是独立部队，不保存城市军团。
- 城市分为前线、集结、腹地、人才不足与战后恢复几种当前用途。用途决定内政方向优先级，方向内选人仍使用玩家共用的推荐评分。已有具体事务继续由武将自主办理。
- AI 与玩家共用出征、行军、调任、运输、内政委任和整补执行入口。执行方通过 `faction` 参数指定，不切换玩家身份，不挪用玩家府库。
- 筹划新一旬时先确定军事承诺，再开始新的内政事务。先核实武将实际驻城，再检查其正在办理的具体事务，最后判断出征时机。一般情况下出征优先，走真实中止及退款规则；接近完工或近期已被中断的事务受到保护。

## 计划生命周期

筹备 → 多城集结 → 出征交战 → 巩固守备 → 完成；途中可以取消。

部队按武将身份关联计划，集中集结时抵城撤销行军军团、恢复为城内部队后仍可继续集结。集中主攻要求全员实际到齐，分城协同要求全员分别在各自真实出发城就绪；均须完成工作时机判断、保留粮食、人员与守备，并检查全部编组及军团数量上限。每军团公共上限十队，协同计划最多六队。集中计划在立项前就以集结城作为实际返城整补据点；分城协同逐城核对原基地。拟出征军团的粮路共用同一逐日库存、粮仓与道路吞吐账，不重复承诺容量。

准备期经济负责人缺位、可调兵补齐的留守缺口、补兵预算不足或接近门槛的优势不足，可保留原目标最多两战略回合，期限不超过原计划截止日。真实调任到达和真实人员替代后再出发；小幅优势不足在下一旬评审最多纳入三队已有可用现役，通过正常集结及完整复核。每日不另选目标或补入新参战人员。期限耗尽、实际来袭压过守备、明显失去优势仍取消；分城协同第一批已出发后，不能继续等待缺少条件的后续军团而让先头部队独自交战。计划保存 `repairUntil`、`columns` 及自身最新 `military` 证据；切换主攻时不沿用另一计划的军事记录。

协同发令后，日常军团管理不自动切换急行军或轻装，以免某团提前接敌或改变携粮容量。取消或巩固后恢复正常管理；实际危险仍通过共用安全检查处理。发兵与预测保留本计划以外的等待运输、外交和其它真实粮草承诺，不能让新军团先花掉已经预留给粮车的同一库存。

水陆混合路线按每段实际道路和当段船只或兵种速度计算天数，到节点后不挪用上一段剩余行动力；返城同样逐段计算。不能用陆上兵种速度估整条水路，否则保存的接敌时间可能让军团分批投入。专项用正常出征军团走真实港口水路，核对预计与实际到达日期。

计划不会因为目标商业值的小变化每日改令。集结地或出兵地失守、人员丢失、通道中断、敌方增援使优势消失、断粮或期限耗尽时取消；撤销等待军令，释放预留，行军军团按实际道路回撤。已经交战的军团按现有战场条件判断撤退。

占领后按实际围城、粮储、伤兵比例和周边威胁判断是否巩固完成，不规定最低巩固天数。未完成时保留城市恢复状态，原参战武将回到正常在城资格，不再因原计划身份永久不能办理内政、侦察或其它军令；实际驻军仍受本城守备约束。原占领城市失守时结束当地巩固，不撤销这些武将在新计划中的军令，也不召回已参加新进攻的军团。周边假想反攻按独立势力分别汇总取最大值，不累加成虚构联军；实际来袭军团仍合计。筹备或进攻取消后按真实道路回撤；下一次进攻仍须重新通过价值与兵粮评估。

## 君主倾向与出兵评估

所有 AI 君主的最终目标均为占领全部城市取得胜利，包含中立城；君主性格只影响推进方式和风险取舍。每旬初从本方真实领地、公开省域与道路和已有城市归属情报确定区域方向，记录总城数、己有城数、尚余城数和区域重点。准备、发展、恢复、防守及暂时和平是通向胜利的阶段安排，不替代最终目标。

统一收益计入出兵净价值及有限候选排序：每次占城基础24分，加己有城市占比×24分；同省己有比例×18分；完成该省占领24分；夺取对方已知最后城市35分；每连通一片分散己方领地20分；每打开一个此前不接壤的城市方向6分、最多三项；当前区域方向12分，合计最多140分。区域方向的小幅变化保持原方向，实际可行主攻可调整重点。所有敌方归属判断使用当前或带日期的旧情报，“已知最后城市”不保证该势力真实灭亡；不读取隐藏易主或未来战果。真实空城机会仍优先进入有限候选，避免远期方向挤掉可执行目标。

有效条约仍禁止进攻。没有保护条约的和平邻国可进入进攻比较，计入该国可能来袭与占后反攻；仅选中兵粮、守备、人员及补给均可实际执行的主攻后，AI 君主才调用共同宣战处理器。缺口尚待准备时不提前宣战。自动保护续约在区域统一方向、没有实际来袭、口粮不足或恢复任务时让位；恢复和其它方向的合作仍可保留。对当前主攻对象的新和平方案计入机会成本，最终仍通过共同报价、批准和签约流程处理。

最终目标、区域方向和每个攻城候选的统一收益分解随存档及旬评审记录保存；旬内执行安全复核不能提前重选方向或更新统一进度快照。专项回归 `npm run test:strategic-victory` 覆盖七剧本全部君主、领地连通、区域收尾、中立城、和平再宣战、条约与预算约束、迷雾隔离及确定性续行。

- 不设置开局发展天数或战后等待天数。每旬比较可行目标与继续发展，实际出发前再次评估。优势达标只代表可打，并不代表值得打。
- 君主来自现有势力君主映射，优先读取实际武将数据，未在场时使用正式武将库；本轮不新增君主继承系统。胆小、冷静偏谨慎，刚胆均衡，莽撞偏进取。谨慎者要求更高净价值、保留更多守备并偏重经济方向；进取者更愿扩张并偏重军务、武备。各方向选人仍使用共用评分与单属性规则。
- 军事研判以君主统率50%＋智力50%计算。敌军与反攻战力的估计误差上界为（1－研判/100）×60%；误差方向由君主ID与目标ID稳定确定，日期推进、反复查看和读档不重抽。高能力只缩小该模型的评估误差，不保证战争结果。
- 目标价值考虑据点类型、商业、粮储及消除边境敌军威胁的收益；成本包括实际路程、预计攻城时间、预计兵损、口粮、按实际兵种装备费估算的补兵金及抽调内政人员的机会成本。当前不另收定期军费。政治较高的君主更重视内政机会成本。净价值须超过其倾向门槛，才建立计划。
- 战损为兵力、攻守战力比的启发式估算，不运行隐藏战斗预演，不宣称精确伤亡或胜率。权重与误差参数见 `data/design/economy-rules.mjs` 的 `ai.offensive`；动员、援军和新版战损系数见 `data/design/strategic-planning-rules.mjs` 的 `opposition`。
- 集中计划按实际集结城、分城协同按各真实基地核对预计战损的补兵需求及装备金，立项与出发采用同一返城口径；出发城市同时保留当前工资、费用和实际守备。编制不扣粮，出征仍须真实口粮和可用粮路。目标防御包含观察驻军、可能动员与及时救援；占后反攻排除已计作救援的同一兵力，先扣当地守备，分势力聚合取最高。
- 自有兵粮、真实人员位置、路线、携粮上限和留守不施加误差。伤兵超过现役与伤兵合计20%的部队先救治；集结与出发保留本城十日口粮、最低2500粮，物流同时计算本城口粮、粮道供给外军的用度与计划携粮。正式出发前复核，不沿用早先目标状况。
- 每项主攻独占其参战人员与来源城市；后期满足实际容量及既有主攻已出发的条件时，才可从独立来源建立第二路。其它战事不构成固定禁战期，其占用的人员、资源和守备威胁按实际状态参与判断。紧急守城和救援按到达时限处理。
- 计划超时用于释放长期无法完成的出征承诺，不作为开战许可或战后冷却。占领后的巩固不继续锁住出征承诺，也不因旧出征期限强迫守军回撤。AI结构18、战略结构13，旧结构直接拒绝；不增加固定发展期或战后等待期。

## 出征与内政的优先级

先核实参战武将是否实际在出兵据点。外访、运输和返程中的武将不能因其登记归属本城就被当作可出征人员；实际回城后才进入下一步判断。没有正在办理的事务时直接出征，不把内政任职本身当成忙碌。

在场且有事务时，一般优先出征；以下情况倾向等待：

- 当前事务剩余不超过两天。
- 实际支付至少 500 金、剩余工期不超过原工期 30% 的事务已接近完成。
- 武将近十天的真实事务历史中已有中断记录，避免刚恢复工作又被打断。

只有等待会错过救援到达时限、而立即出发仍赶得上时，紧急增援才覆盖上述保护。等待中的增援也按最新到达时限复核；仍可及时到达的等待援军计入守备，避免重复派兵。

集结后的主攻对全体参战人员先作统一判断，再分军团出发，避免先中断一半人员才发现另一半必须等待。选择等待期间不开始新事务；中断历史本来就随存档保存，因此读档不会清除近旬保护。以上阈值是当前确定性决策规则，不改变内政和战斗收益。

## 守备与估算

先扣守备需求，再选择可外调部队。守备需求参考已知来袭军队、邻城敌军与城防，不再固定留一队或按固定队数限制腹地调动。

2026-09-22 行为复测修正：已有守备缺口的城市不作为新进攻的集结地，避免把全部增援预留给进攻后长期无法出发。推进集结时先复核所有尚未出发人员的来源城；守备需求提高导致计划不再成立时取消并释放人员。等待内政结束的 AI 出征军令，在真正执行前再次检查留守战力，不能沿用等待前的敌情。玩家手动出征沿用原有规则。

救援按每段道路的实际消耗和军团速度计算到达日，每次到达据点的剩余行动力不结转。在路上的剩余距离也计入；已经派往该城但赶不上的军团不算有效救援。

野战估算使用实际兵员、属性、士气与缺粮，并以当前适性和固定战法数量作粗略修正。敌军实际抵城时，先检查临时守城编制，再判定空城。AI即时调用共同默认编制方案，玩家暂停选择手动编制、自动编制或在尚无守军时放弃守城；双方共用实际驻城人员（含太守与内政负责人）、本城金、未预留预备兵、本旬征募额度、技术与伤兵上限，编制不扣粮，守城军携粮单列。只有实际参加守城者打断事务并取消等待命令，保留任职；未参战者按围城暂停。零现役的已编制部队保留在城内，可在开战前整补，不能作为守军或占用携粮。无法合法组建守军或玩家放弃后直接占领，不计城门战力或攻城工期，不产生虚假战果；有实际守军则接入共同攻城与援军真实抵达流程。待编制的玩家军议随当前存档保存，不推进时间、随机或战斗。实现见 `siege-defense.mjs` 与 `strategic-campaign.mjs`，回归 `npm run test:siege-defense`。

有守军时，攻城估算按共用派生攻城属性、攻击间隔、伤害系数与每日战斗步数换算日伤害，最多计入前六队；不再以兵数乘攻城系数当作日伤害，也不把预计工期强制封顶十二日。未保证触发的战法与临时增益不计入持续输出。估算仍不包含完整接敌、守军干扰与伤亡过程，不宣称准确胜率。出征预算覆盖集结、行军、预计攻城和撤回，实际按共用军团携粮规则装载。

势力倾向与研判读取君主数据，只影响目标选择、发展取舍、优势要求和估算精度，不增加收入、兵力、行动或战斗加成。

## 资源与人员

2026-09-22 围城供粮修正：实际围城战的进攻军团可把所在敌城外营地作为粮道最终交付点。中间据点仍必须归己方，敌城不能成为补给中转站；粮道仍遵守 180 距离上限、敌军道路拦截、粮源库存、据点每日发送预算和每条道路每日 360 运力，多军团共享额度。守军、无围城关系的第三方及普通敌境驻军不获得这一终点例外。补给每天先实际扣除粮源库存，再进入军团携粮并结算消耗，运力不够仍需消耗携粮。本次不提高携粮量或降低耗粮。

验证见 `tests/siege-supply.test.mjs`：真实行军产生围城后持续供粮及确定性续战；主路截断后绕路、两路截断后停止补给；敌城不得中转、距离限制；三支真实拆分并赴战的军团共享 360 运力。AI 出征准入仍以携粮覆盖作为保守条件，不把预测运力当成已到账粮食。城市预算与军团断供判断逐日共享同样的发送和路段额度；保持当前位置、兵力与粮道预测，不预知后续战损或敌军行动。

- 同一武将不能被两个活动计划重复承诺；已有等待命令或实际外出的人员不可再次分配。
- 预留只是意向记录，不提前扣除粮草、创建军团或移动人员。待集结军令还在等待内政时，粮草预留继续保留；实际出发后才释放原城预留。
- 征补、粮食出售与其它运输会考虑已承诺的粮草；待发运输的粮草与预备兵也纳入预留。每旬直接征补至少留下本城旬初库存的一半及一旬待用金的较高值，装备和改编同样遵守本城预算；待用金包括未开始事务、债务、外交及待发物资。整补使用与玩家相同的费用、伤兵上限及本城每旬额度。
- 城市金、粮或预备兵不足时，从预算有余量的友城派出真实运输队，先处理当前钱粮缺口与口粮将尽的城市。统计已在途和等待中的货物，避免重复调运。已知有敌军或遭威胁的运输通道不派车；等待中的运输在实际执行前也重新检查路线威胁；出发后遭敌仍由共用运输引擎结算实际损失。
- 每旬按真实缺岗从有余员的友城调任人才，覆盖大小城市及已有三人以上的城市。目的地须有当前可办理的事务及真实岗位名额；农业、商业、军务可补至既有经济用人目标，其余方向先补首名负责人。优先人数较少的城市及必要钱粮岗位，同一城市已有人员赴任承诺时不重复调人，普通货运不代替人员赴任。
- 来源城按未被计划、军令、侦察等占用的实际人员比较余缺，保留太守、必要经济负责人及真实守备，不抽走伤兵或正在办理、待批及当地仍有可办事务的负责人。城内编制本身不算具体任务；无职驻城武将可兼办内政，也可在守备足够且目的城有真实口粮时携原部队调任。使用安全道路、实际人员或运输速度比较两旬内可达的目的地；抵达后共同委任，保护至首个真实事务尝试完成。不为消除空闲数字虚构工作或资源。
- 人才调任另按前后方分工评估：对外道路边境、当前作战集结地及实际巩固目标按前线处理，其余为后方；只用本方领土、公开道路及本方可见敌军位置，不读敌军秘密目标。前线优先军事适性，后方优先政治、智力、魅力所支持的内政适性；两边继续保留必要农业、商业人手。前线来源城保留当前可用人员中军事推荐最高的两人，人才调任后至少保留两支实际驻城部队、合计2000现役；现有不足时保住现有可用人数与现役，不凭空补齐。城墙、伤兵、在途援军及已承诺离城者不代替这份留守。选人时检查，已保存的等待调任在真实出发时再检查；旧巩固计划不继续把原集结城固定为前线。保留军事人才不视作授予具体工作，单纯驻守仍按原空闲口径显示。参数为战略规划表的 `personnel`，实现为 strategic-personnel.mjs。

城市和军团每日评估断供风险；军团在携粮耗尽前尝试沿可达道路回粮仓，城市在无及时粮车、口粮不足三天且未被围城时按守备需求把多余现役完整转回预备兵。必要的最后一名实际农业、商业负责人受到可选调动保护；正常运营优先发展产能和真实运输，已开始付费的事务继续办理。玩家造成的围城、夺仓、封路、运输损失和退路阻断均正常生效，不赠送库存、不免除断粮后果。详细预算与验收见[城市钱粮与预算](城市钱粮与预算.md)。

运输选择按实际道路消耗排序的安全友方通道，保存并执行选定路线，允许绕开可见敌军。道路的护卫使用真实驻点军团，货队仍可遭敌损失。每势力保留一个主攻方向；成熟势力可在主攻已经出发后，从独立兵源城开启第二作战计划，外交沿现有共同流程办理。

## 粮路保护、战场增援与运输

当前战略存档65、AI结构18。每势力最多三项独立护路或战场增援，记录实际目标、战场、参战人员、创建日期、最近需求及期限，不生成额外兵力或新主攻战线。

AI每日先判断正在交战的己方战场是否需要增援，再检查实际粮道、在途和等待运输及城市真实缺口所需通道。只使用共同情报投影中的敌军当前地点、当前行进方向和兵力；已封路时仅移除已观察到的敌军来辨认待恢复的粮路，不改变已知归属、距离或实际通行。路口、港口和关卡可成为护路终点，无独立府库。守军到位后只要敌方仍威胁该通道，就继续驻守。

增援按战场剩余时间和真实行程筛选；已在途但赶不上的部队不计入。各来源城保留守备、经济人员、预算和实际装载携粮，沿共同等待或中断规则出发。兵力不足时，先在只读副本中检查解除某项尚未出发的进攻承诺后，能否以实际可到达、可付费、可供给且足以覆盖缺口的编组完成救援；新编组必须实际使用该计划人员。全部通过才撤销该承诺并重新通过共同军令下达。无路、迟到、缺粮、缺钱或释放后仍不足时保留原进攻，不因无效救援打断它；已有在途人员的计划不因此被召回。战力和行程使用待出发编组的真实军团长、军师，已有援军按保存任命测量。抵达道路交战位置或节点后才通过共同处理器加入战场后备，不提前授予军略或上场。原战场结束、任务超期或威胁解除后取消未执行军令，实际军团沿道路回粮仓。

运输分别安排真实金、粮和预备兵，统计在途、等待、中转和已安排的往返批次，避免重复调运。安全绕路保存为具体道路节点，待执行命令再次检查完整路线，实际运输不另走被封锁的最短路。转漕选择途中的己方中转城，漕运仅用于纯粮且合资格的无部队人员，最多五批；每批返回后从真实城仓重新装载，保留本城及外军供粮预算，归属、路线、可见威胁或库存不满足就停止续运。接粮军团可让真实城际粮车经过驻军节点，先处理敌军拦截，再按实际携粮空额交接，剩余物资仍运到目的城。

正式参数：[护路增援与运输](../data/design/strategic-support-rules.mjs)，一览表：[当前决策参数](design-tables/战略护路增援与运输一览表.md)。机制回归：`npm run test:strategic-support`，覆盖真实护路出征、真实野战加入、隐藏状态不影响决策、能力不足保留守备、安全绕路、中转、逐批扣粮、待执行路线复核、重复承诺拒绝及确定性继续。机制通过不代表最优战略或战争平衡结论。

## 情报、界面与存档

普通模式全国地形已探索，各势力共用城市、军团和斥候视野。AI的进攻、救援、反攻风险及运输路线评估与玩家界面共用 `intelligenceWorld` 情报投影：只读取合法可见军团的位置、当前行进方向和兵力；失去视野的敌城沿用最后情报，未知驻军采用保守估计。不读取隐藏敌军的实时兵损、实际外地易主、内部计划、后续路线或待执行军令。实际执行、己方人员和资源仍由共同模拟规则校验。见[战争迷雾与武将侦察](战争迷雾与武将侦察.md)。

AI每日优先安排侦察，负责人留城工作，模拟斥候沿真实道路每天移动105行程点，点亮与视野期限共用玩家规则。每势力最多同时两项侦察任务，不重复派往同一目标；派出城市至少保留一名实际可办事的人员，内政已有负责人仍正常计算，人手不足时停止低优先级侦察。优先当前主攻目标，其次未知或已满3天的旧边境情报，并按路程与可用负责人的智力择优。优先空闲人手，必要时释放尚未开始的可选事务，保留农业、商业、已开始事务、太守、外交及待执行军令与计划人员。正在负责侦察的武将不被自动任太守、委任其它内政、征补、编入出征或调任，未带兵的负责人也正常累计任职天数。

取得目标情报至少2天且抵达终点后，低优先级驻察可让位给评分至少高40的未知或旧边境情报；主攻目标可在当前任务完成观察后立即优先改派。不会每日反复改令或轮换尚未抵达的任务，主攻的有效驻察不会被普通边境挤占。目标已有城市或军团直接视野、已知变为友方或和平势力、战线转移后停止无用任务。

能够安排斥候的目标，在尚未观察或最后情报已满3天时先等侦察结果，再决定新进攻和最终出发；无合资格负责人时仍可按共同的未知防守保守估计评估，不赠送视野。侦察优先级和名额参数在 `data/design/strategic-scouting-rules.mjs`，主攻、边境、未知情报基础权重为200、80、80；旧情报每天增加20，上限80。执行逻辑在 `strategic-scouting-ai.mjs`。`tests/strategic-ai-scouting.test.mjs` 覆盖上限、目标与人员选择、轮换与持续驻察、真实沿路观察、人员事务保护、隐藏状态改变不影响决策、旧情报及确定性续跑。

敌方内部计划、参与队数、待执行命令与下令原因不向玩家公开；地图和情报只提供当前视野或标明日期的最近情报。内部评分仍不展示为玩家数值。

计划、预算、预留、期限、风格和每日／每旬执行标记随存档保存。验证拒绝重复计划、重复承诺、非法资源数值与旧 AI 结构；同日调用不重复执行。

## 守城与进攻编组

实际参战守城的武将立即中断事务，相关等待军令取消，内政任职保留。未参战者继续使用围城暂停规则。进攻筹划先检查人员实际驻城，再按当前事务状态编组：各可达来源城的空闲武将优先，战力足够即停止抽调；空闲战力不足时才加入忙碌武将，沿用事务剩余时间、投入及近期中断保护决定等待或立即执行。玩家编组列表共用空闲优先推荐并展示忙碌状态。

机制回归入口为 `npm run test:faction-ai`，覆盖同一目标因君主性格而作出不同选择、研判误差随能力收敛、读档不重抽、补兵资源不足、内政机会成本、占后反攻、真实行军和确定性续战。全国自然模拟不要求固定期限内必然爆发AI互战；交战机制使用真实军团抵达敌城验证。选将界面检查见 `scripts/verify-departure-priority-ui.mjs`。

当前自然节奏统一使用 `scripts/audit-all-ai-decisions.mjs` 与 `scripts/audit-validation-matrix.mjs`，以战略回合指定观察长度。完整观察至少覆盖第1–70回合：前期1–20、中期21–60、后期61–70；中期最长连续无真实战斗间隔以不超过约12回合为目标，并记录真实协同参战。旧的六回合审计、保留不下令玩家席位的审计及固定旧存档续行脚本已移除。出征、空城占领、实际战斗、进攻胜负与未结战场分列；测试运行完成不表示节奏目标已经达标。

当前迷雾自然局使用 `npm run audit:war-fog -- --scenario=guandu-200 --seed=417 --days=30` 验证。脚本先保存带源码哈希的独立运行快照，再用原始全国剧本和共同逐日引擎记录侦察派遣、抵达、情报、内政实际资源成果、真实离城军团、进攻计划、战斗、等待原因、缺粮及确定性存档；不会缩短道路、赠送资源、指定进攻或替换战果。结果、逐项事件和每日完整存档写入 `work/war-fog-ai/`，可用 `--out` 指定目录。占领空城单独计出征与占领，不计战斗；一支集结、援军或回撤军团也不等同于一次新进攻。

当前侦察频率与速度的机制验收使用真实派遣与沿路扫描，检查普通未知边境轮换、3天旧情报更新、主攻优先、已开始事务和经济人手保护、玩家与AI相同的105每日行程，以及存档续跑。全国诊断应在当前完整规则的独立源码快照运行，记录侦察、发展和真实出征；不以侦察次数或停战次数单独证明战争平衡或长期承载达标。
