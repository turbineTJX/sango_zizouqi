# 势力 AI 与跨旬作战计划

当前已接入势力战略选择、有限准备预测和攻城任务规划，战略存档53、AI结构7、战略结构3。实际命令、资源、内政成败、人员行旅和战斗继续使用共同执行器。

全流程的 AI 环节、输入输出、建模公式、算法接口与模拟评价口径见 [AI架构与决策评价方法](AI架构与决策评价方法.md)。本文侧重势力战略的执行规则与专项验收。

## 决策、评价与预测接口（2026-10-09）

战略算法从真实规则和执行流程拆开。默认实现采用效用、成本收益、启发式战损和两旬准备预测；准备预测同时考虑实际在办运营的公开预期与已装载的安全运输，军事预算允许尚未开办的可选工程让位。算法接口本身不提供资源或战斗加成。

```mermaid
flowchart LR
 A[合法情报与真实规则] --> B[事实与可执行候选]
 B --> P[预测器]
 B --> E[评分器]
 P --> E
 E --> D[候选选择器]
 D --> G[承诺与资格复核]
 G --> X[共同命令执行器]
 X --> A
```

| 接口 | 默认编号 | 同步输入 | 允许返回 |
| --- | --- | --- | --- |
| selector | utility-v1 | 已评分候选、合法情报、君主特点、当前目标 | 已有候选的id |
| goalEvaluator | utility-v1 | 一个阶段目标候选、合法情报、君主特点、正式参数 | score |
| offensiveEvaluator | cost-benefit-v1 | 出兵事实、所选预测、君主特点、正式参数 | score、benefit、cost、workCost |
| battlePredictor | attrition-v1 | 兵力、能力、工期、耗粮、补兵单价、来源预算与情报日期等事实 | estimatedLosses、consumedGrain、replacementGold、militaryGold、counterPower |
| preparationPredictor | two-turn-v2 | 情报上下文、逐城需求、有限窗口 | feasible、readyDay、reason |

五项可以独立组合。`strategic-algorithms.mjs` 管理注册、版本标识、配置、输入隔离和输出校验；`strategic-algorithm-defaults.mjs` 与 `strategic-predictors.mjs` 只处理数据。`strategic-ai.mjs` 的 `offensiveFacts` 与原有候选生成器负责把真实规则转换成输入，再独立检查守备、人员、实际携粮和来源预算；`strategic-policy.mjs` 负责计划承诺、切换门槛、目标落地和记录。

候选id关联当次具体编组，选择器不能另造人员或命令。评分不能直接准许出兵，预测不能提前入库；已有进攻承诺、小幅变化的持续性及军令生效复核仍由共用流程执行。目标切换门槛保护已存在的具体军事目标；默认发展与恢复没有待保护的具体行动，不用该门槛压住更高评分的合法候选，实际出兵仍须通过守备、预算、人员和携粮复核。评价的分值须采用与正式最低收益及切换门槛一致的尺度。预测输出限制损失范围、整数费用和未来窗口，非有限数值、异步结果、额外字段或伪造候选均拒绝。当前没有插件化内政、外交评分、固定战斗选敌或军略触发规则，它们继续沿用各自现有流程。

回调只收到结构化克隆后递归冻结的值，不收到 `s`、随机种子、预存成败或敌方秘密命令。目标情报明确给出是否已知、是否可见和最后观察日期。回调可以复制数据做有限搜索；新增可执行候选类型或预测所需特征应扩展规则适配器，不绕过迷雾接口。该边界是代码接口隔离，注册模块仍是可信程序代码，并非JavaScript安全沙箱。

注册示例与接口替换测试见 `tests/strategic-algorithms.test.mjs`；可运行的保守选择器示例见 `tests/fixtures/strategic-development-algorithm.mjs`。新实现使用新版本编号，不能覆盖已注册编号。`registerStrategicAlgorithm(kind,{id,run})` 注册同步函数；在筹划期调用 `setStrategicAlgorithms(s,{selector:'my-selector-v1'})` 可替换单项并触发复核。当前五项编号保存在 `campaign.ai.algorithms`，每次候选记录保存当时的整组编号。读取自定义算法存档前必须注册同版本实现，否则拒绝载入；不保存函数或对旧档迁移。

自动模拟支持 `--selector`、`--goal-evaluator`、`--offensive-evaluator`、`--battle-predictor`、`--preparation-predictor`。外部模块须导出 `strategicAlgorithms=[{kind,id,run}]`，以 `--algorithm-module` 加载。结果保存配置、源码哈希及外部模块的入口哈希，模块加载或模拟期间改变源码会失败。按相同剧本、种子和天数分别运行，才可比较算法组合；登记编号的实现与模块依赖也应一同归档。

```sh
npm run test:strategic-algorithms
npm run audit:strategic-planning -- --scenario=guandu-200 --seeds=417 --days=3 --out=work/ai-default
npm run audit:strategic-planning -- --scenario=guandu-200 --seeds=417 --days=3 --selector=development-example-v1 --algorithm-module=tests/fixtures/strategic-development-algorithm.mjs --out=work/ai-development
```

机制回归覆盖算法替换、来源城预算和人员保护、真实运输、战争迷雾及确定性续跑。`tests/strategic-economy-planning.test.mjs` 另复现可选工程挤占军事预算、占城后巩固长期占用主攻、独立势力被累加为反攻联军、运营及运输未进入预测的问题；验证不提前发资源，不读取随机结果，低金开局仍依正常运营恢复。完整机制回归运行 `npm run test:strategic-planning`；通过不代表全年战争承载或胜率已校准。

## 势力战略与任务规划

势力先对已知周边势力确定进攻、防守或谋求和平的意向，再选择当前攻占、保境、恢复、和平或发展目标。最多一条主要进攻战线，护路与战场增援仍最多三项，侦察仍最多两项。和平意向不改变敌对关系；真实条约生效前继续守备。

目标由实际可用兵力、城市独立预算、人员资格、合法路线、战争收益和君主倾向共同评价。候选最多八组，截断前保留当前目标、已知空城机会并比较真实路程，不按富庶程度排除可行目标；每组最多比较三种兵力规模；达到最低优势后继续检查占后反攻、携粮和补兵能力，必要时尝试更大编组。仍优先空闲人员，不为羁绊凑档或替补顺序另作战略搜索。

攻城任务保存侦察、补给准备、集结、进攻、巩固的依赖、状态、日期和真实执行引用。三项准备可并行，进攻要求情报、补给和集结均满足；巩固依赖实际占领。等待军令不等于军团已经出发，预测收入不等于实际入库，占领和巩固只由共同引擎的真实结果确认。筹备、集结和进攻保留军事人员承诺；占领后的巩固改为城市守备与恢复任务，释放原出征人员的额外承诺和主攻槽位，仍逐日检查真实守备，不能因建立新主攻而视作巩固成功。经济人员的需求提示不把本人标成不能办理内政。计划来源城分别保留自己的预算和预计战损兵源，不使用势力合计替代实际库存。

资源不足时，可在现有产能与预算支持下保留准备目标，提出各来源城的真实钱粮兵源需求，通过现有委任和运输准备。运输从来源城装载后扣款，抵达后入库；达到实际要求后重新评估出征。内政需求仅调整已有合法候选的优先级，不跳过工期、费用、额度、地点、成败或已批准提案。

有限预测逐日检查未来两旬的耗粮、旬末收入、费用、库容和兵源，入库前断粮则拒绝以未来收成为准备依据。在办集市、督耕和预备兵征集按公开成功机会估算完成日的基础成果，共享实际每旬办理额度，不读取预存随机数，不预测连携、意外献赠或未开办事务的成果。只计当前已装载且路线安全、未受阻的运输，按实际剩余路程和运输速度估算到达日；不预测尚未装载的后续批次、中转后未确定的下一程或路线封锁解除。未开始事务、待发运输和债务的单次预算不每旬重复扣除；外交行资等周期费用继续计算。运营可能失败、运输可能被截，所有预测只作准备候选判断，军令生效前仍复核实际库存。当前战损和攻城时间沿用共同规则上的启发式估计；尚未接入经过独立战斗样本校准的模型、完整敌方反应搜索或强化学习。

每旬初（第1、11、21日等）完整评审一次，统一刷新交给战略选择器和目标评分的合法视野、城市情报与本方资源输入。旬内不重建全国战略上下文，也不因新情报或筹备资源就绪提前选择新的阶段目标；未建立作战计划的筹备目标等下一旬复核。实际地图视野、斥候观察和带日期的情报仍随共同模拟更新；每日推进已有计划，并检查实际威胁、供给、人员、路线和期限，不安全的军令可以取消或回撤。小幅评分变化保留可行目标，明确更高价值机会才调整。当前目标、来源需求、最近十二次候选评分和选择原因随存档保存，查看不推进日期、不消费模拟随机数。

正式参数见 [势力战略规划一览表](design-tables/势力战略规划一览表.md)，源码为 `data/design/strategic-planning-rules.mjs`。情报快照剔除真实随机种子、预存结果和敌方秘密军令；外交与内政敌情判断也使用共同情报投影。外国库存只采用当前或最近观察，未知库存使用有上限的交涉请求；请求不证明对方有货，实际接洽和签署重新核实。开局外交联络地点保存，不能随未知君主迁移自动更新。未侦察的外军不按零兵力计算和平机会成本；出使按已知请求出发，外方人员、库存和承诺到实际接洽时才复核，签署及履约仍须通过完整共同校验。

机制回归 `npm run test:strategic-planning`。自然验证 `npm run audit:strategic-planning -- --scenario=guandu-200 --seeds=417,643 --days=30`，使用原始剧本的全AI控制、普通迷雾和正常意外，通过共同逐日引擎记录战略候选、目标与任务变化、真实出征规模、逐城预算缺口和缺粮。结果包含源码哈希、完整存档和事件，源码变化拒绝宣称通过；`--source` 可指定独立基线运行目录，`--out` 指定结果目录。短期完成及机制通过不代表年度战争承载或战略胜率结论。

### 首轮自然模拟（2026-10-09）

以下为算法拆分前首版的验收记录（存档52、AI结构5）。官渡原始剧本，全 AI、普通战争迷雾、正常内政意外，固定开发种子417与独立种子643，各运行三十个实际战略日。保留源码快照、哈希、完整存档、候选、逐日预算与出征队数，结果目录为 `work/strategic-planning-current/verified-audit/`；同种子旧代码快照在 `work/strategic-planning-baseline/audit/`。两个快照还包含工作区同期的其他改动，哈希清单可核对；该对照是整版行为观察，不是隔离战略 AI 改动的效果试验。

## 决策与执行

- 势力每旬初统一刷新战略输入并评估目标，旬内执行已有意向和计划，紧急安全检查不触发全国目标重选；并非每旬必须出兵。一个势力同时最多一项处于筹备、集结或进攻的主攻计划，占城后的巩固不占主攻槽位。每日处理紧急守备、补给、计划推进和运输。
- 一项计划就是当前主攻战线的协调记录，记录目标、集结城、出兵城、武将身份、待用粮草、阶段、截止时间与原因。城内仍是独立部队，不保存城市军团。
- 城市分为前线、集结、腹地、人才不足与战后恢复几种当前用途。用途决定内政方向优先级，方向内选人仍使用玩家共用的推荐评分。已有具体事务继续由武将自主办理。
- AI 与玩家共用出征、行军、调任、运输、内政委任和整补执行入口。执行方通过 `faction` 参数指定，不切换玩家身份，不挪用玩家府库。
- 筹划新一旬时先确定军事承诺，再开始新的内政事务。先核实武将实际驻城，再检查其正在办理的具体事务，最后判断出征时机。一般情况下出征优先，走真实中止及退款规则；接近完工或近期已被中断的事务受到保护。

## 计划生命周期

筹备 → 多城集结 → 出征交战 → 巩固守备 → 完成；途中可以取消。

部队按武将身份关联计划，抵城撤销行军军团、恢复为城内部队后仍能继续集结。主攻出发前要求全部参战人员到齐、当前工作的等待或立即执行决策完成、粮食充足并保留守备能力。每个军团最多十队，战场首发规则仍是六队；多军团出发前先检查全部编组和军团数量限制。

计划不会因为目标商业值的小变化每日改令。集结地或出兵地失守、人员丢失、通道中断、敌方增援使优势消失、断粮或期限耗尽时取消；撤销等待军令，释放预留，行军军团按实际道路回撤。已经交战的军团按现有战场条件判断撤退。

占领后按实际围城、粮储、伤兵比例和周边威胁判断是否巩固完成，不规定最低巩固天数。未完成时保留城市恢复状态，原参战武将回到正常在城资格，不再因原计划身份永久不能办理内政、侦察或其它军令；实际驻军仍受本城守备约束。原占领城市失守时结束当地巩固，不撤销这些武将在新计划中的军令，也不召回已参加新进攻的军团。周边假想反攻按独立势力分别汇总取最大值，不累加成虚构联军；实际来袭军团仍合计。筹备或进攻取消后按真实道路回撤；下一次进攻仍须重新通过价值与兵粮评估。

## 君主倾向与出兵评估

- 不设置开局发展天数或战后等待天数。每旬比较可行目标与继续发展，实际出发前再次评估。优势达标只代表可打，并不代表值得打。
- 君主来自现有势力君主映射，优先读取实际武将数据，未在场时使用正式武将库；本轮不新增君主继承系统。胆小、冷静偏谨慎，刚胆均衡，莽撞偏进取。谨慎者要求更高净价值、保留更多守备并偏重经济方向；进取者更愿扩张并偏重军务、武备。各方向选人仍使用共用评分与单属性规则。
- 军事研判以君主统率50%＋智力50%计算。敌军与反攻战力的估计误差上界为（1－研判/100）×60%；误差方向由君主ID与目标ID稳定确定，日期推进、反复查看和读档不重抽。高能力只缩小该模型的评估误差，不保证战争结果。
- 目标价值考虑据点类型、商业、粮储及消除边境敌军威胁的收益；成本包括实际路程、预计攻城时间、预计兵损、口粮、按实际兵种装备费估算的补兵金及抽调内政人员的机会成本。当前不另收定期军费。政治较高的君主更重视内政机会成本。净价值须超过其倾向门槛，才建立计划。
- 战损为兵力、攻守战力比的启发式估算，不运行隐藏战斗预演，不宣称精确伤亡或胜率。权重与误差参数均在 `data/design/economy-rules.mjs` 的 `ai.offensive` 中维护。
- 各来源城的储备兵和本城金须分别覆盖预计战损的补兵需求及装备金；编制不扣粮，出征仍须真实口粮和可用粮路，来源城须保留实际守备。观察目标已有守军和可及时到达的可见援军，另估计占领后的邻城反攻；反攻兵力先扣当地守备，分势力聚合取最高，不把诸侯当成一支协同联军。
- 自有兵粮、真实人员位置、路线、携粮上限和留守不施加误差。伤兵超过现役与伤兵合计20%的部队先救治；集结与出发保留本城十日口粮、最低2500粮，物流同时计算本城口粮、粮道供给外军的用度与计划携粮。正式出发前复核，不沿用早先目标状况。
- 现有主攻计划独占该势力的进攻承诺；其它战事不构成固定禁战期，其占用的人员、资源和守备威胁按实际状态参与判断。紧急守城和救援按到达时限处理。
- 计划超时用于释放长期无法完成的出征承诺，不作为开战许可或战后冷却。占领后的巩固不继续锁住出征承诺，也不因旧出征期限强迫守军回撤。AI结构版本为7、战略结构为3，旧结构直接拒绝并提示重新开始；不增加固定发展期或战后等待期。

## 出征与内政的优先级

先核实参战武将是否实际在出兵据点。外访、运输和返程中的武将不能因其登记归属本城就被当作可出征人员；实际回城后才进入下一步判断。没有正在办理的事务时直接出征，不把内政任职本身当成忙碌。

在场且有事务时，一般优先出征；以下情况倾向等待：

- 当前事务剩余不超过两天。
- 实际支付至少 500 金、剩余工期不超过原工期 30% 的事务已接近完成。
- 武将近十天的真实事务历史中已有中断记录，避免刚恢复工作又被打断。

只有等待会错过救援到达时限、而立即出发仍赶得上时，紧急增援才覆盖上述保护。等待中的增援也按最新到达时限复核；仍可及时到达的等待援军计入守备，避免重复派兵。

集结后的主攻对全体参战人员先作统一判断，再分军团出发，避免先中断一半人员才发现另一半必须等待。选择等待期间不开始新事务；中断历史本来就随存档保存，因此读档不会清除近旬保护。以上阈值是当前确定性决策规则，不改变内政和战斗收益。

## 守备与估算

先扣守备需求，再选择可外调部队。守备需求参考已知来袭军队、邻城敌军与城防，不再固定留一队或按固定队数限制腹地调动。

2026-09-22 行为复测修正：已有守备缺口的城市不作为新进攻的集结地，避免把全部增援预留给进攻后长期无法出发。推进集结时先复核所有尚未出发人员的来源城；守备需求提高导致计划不再成立时取消并释放人员。等待内政结束的 AI 出征军令，在真正执行前再次检查留守战力，不能沿用等待前的敌情。玩家手动出征沿用原有规则。

救援按每段道路的实际消耗和军团速度计算到达日，每次到达据点的剩余行动力不结转。在路上的剩余距离也计入；已经派往该城但赶不上的军团不算有效救援。

野战估算使用实际兵员、属性、士气与缺粮，并以当前适性和固定战法数量作粗略修正。敌军实际抵城时，先检查临时守城编制，再判定空城。AI即时调用共同默认编制方案，玩家暂停选择手动编制、自动编制或在尚无守军时放弃守城；双方共用实际驻城人员（含太守与内政负责人）、本城金、未预留预备兵、本旬征募额度、技术与伤兵上限，编制不扣粮，守城军携粮单列。只有实际参加守城者打断事务并取消等待命令，保留任职；未参战者按围城暂停。零现役的已编制部队保留在城内，可在开战前整补，不能作为守军或占用携粮。无法合法组建守军或玩家放弃后直接占领，不计城门战力或攻城工期，不产生虚假战果；有实际守军则接入共同攻城与援军真实抵达流程。待编制的玩家军议随当前存档保存，不推进时间、随机或战斗。实现见 `siege-defense.mjs` 与 `strategic-campaign.mjs`，回归 `npm run test:siege-defense`。

有守军时，攻城估算按共用派生攻城属性、攻击间隔、伤害系数与每日战斗步数换算日伤害，最多计入前六队；不再以兵数乘攻城系数当作日伤害，也不把预计工期强制封顶十二日。未保证触发的战法与临时增益不计入持续输出。估算仍不包含完整接敌、守军干扰与伤亡过程，不宣称准确胜率。出征预算覆盖集结、行军、预计攻城和撤回，实际按共用军团携粮规则装载。

势力倾向与研判读取君主数据，只影响目标选择、发展取舍、优势要求和估算精度，不增加收入、兵力、行动或战斗加成。

## 资源与人员

2026-09-22 围城供粮修正：实际围城战的进攻军团可把所在敌城外营地作为粮道最终交付点。中间据点仍必须归己方，敌城不能成为补给中转站；粮道仍遵守 180 距离上限、敌军道路拦截、粮源库存、据点每日发送预算和每条道路每日 360 运力，多军团共享额度。守军、无围城关系的第三方及普通敌境驻军不获得这一终点例外。补给每天先实际扣除粮源库存，再进入军团携粮并结算消耗，运力不够仍需消耗携粮。本次不提高携粮量或降低耗粮。

验证见 `tests/siege-supply.test.mjs`：真实行军产生围城后持续供粮及确定性续战；主路截断后绕路、两路截断后停止补给；敌城不得中转、距离限制；三支真实拆分并赴战的军团共享 360 运力。AI 出征准入仍以携粮覆盖作为保守条件，不把预测运力当成已到账粮食。城市预算与军团断供判断逐日共享同样的发送和路段额度；保持当前位置、兵力与粮道预测，不预知后续战损或敌军行动。

- 同一武将不能被两个活动计划重复承诺；已有等待命令或实际外出的人员不可再次分配。
- 预留只是意向记录，不提前扣除粮草、创建军团或移动人员。待集结军令还在等待内政时，粮草预留继续保留；实际出发后才释放原城预留。
- 征补、粮食出售与其它运输会考虑已承诺的粮草；待发运输的粮草与预备兵也纳入预留。每旬直接征补至少留下本城旬初库存的一半及一旬待用金的较高值，装备和改编同样遵守本城预算；待用金包括未开始事务、债务、外交及待发物资。整补使用与玩家相同的费用、伤兵上限及本城每旬额度。
- 城市金、粮或预备兵不足时，从预算有余量的友城派出真实运输队，先处理当前钱粮缺口与口粮将尽的城市。统计已在途和等待中的货物，避免重复调运。已知有敌军或遭威胁的运输通道不派车；等待中的运输在实际执行前也重新检查路线威胁；出发后遭敌仍由共用运输引擎结算实际损失。
- 人员不足的城市从有余员的友城调任人才。比较目的地任务推荐、原岗位收益、路程和当前事务；保留原城太守与有兵部队。调任实际行走，抵达后才参加当地内政。

城市和军团每日评估断供风险；军团在携粮耗尽前尝试沿可达道路回粮仓，城市在无及时粮车、口粮不足三天且未被围城时按守备需求把多余现役完整转回预备兵。必要的最后一名实际农业、商业负责人受到可选调动保护；正常运营优先发展产能和真实运输，已开始付费的事务继续办理。玩家造成的围城、夺仓、封路、运输损失和退路阻断均正常生效，不赠送库存、不免除断粮后果。详细预算与验收见[城市钱粮与预算](城市钱粮与预算.md)。

运输选择按实际道路消耗排序的安全友方通道，保存并执行选定路线，允许绕开可见敌军。道路的护卫使用真实驻点军团，货队仍可遭敌损失。每势力保留一个主攻计划，外交沿现有共同流程办理。

## 粮路保护、战场增援与运输

当前战略存档53、AI结构7。每势力最多三项独立护路或战场增援，记录实际目标、战场、参战人员、创建日期、最近需求及期限，不生成额外兵力或新主攻战线。

AI每日先判断正在交战的己方战场是否需要增援，再检查实际粮道、在途和等待运输及城市真实缺口所需通道。只使用共同情报投影中的敌军当前地点、当前行进方向和兵力；已封路时仅移除已观察到的敌军来辨认待恢复的粮路，不改变已知归属、距离或实际通行。路口、港口和关卡可成为护路终点，无独立府库。守军到位后只要敌方仍威胁该通道，就继续驻守。

增援按战场剩余时间和真实行程筛选；已在途但赶不上的部队不计入。各来源城保留守备、经济人员、预算和实际装载携粮，沿共同等待或中断规则出发。兵力不足以基本覆盖缺口时先释放尚未出发的可选进攻承诺；仍不足则保留本城守备。抵达道路交战位置或节点后才通过共同处理器加入战场后备，不提前授予军略或上场。原战场结束、任务超期或威胁解除后取消未执行军令，实际军团沿道路回粮仓。

运输分别安排真实金、粮和预备兵，统计在途、等待、中转和已安排的往返批次，避免重复调运。安全绕路保存为具体道路节点，待执行命令再次检查完整路线，实际运输不另走被封锁的最短路。转漕选择途中的己方中转城，漕运仅用于纯粮且合资格的无部队人员，最多五批；每批返回后从真实城仓重新装载，保留本城及外军供粮预算，归属、路线、可见威胁或库存不满足就停止续运。接粮军团可让真实城际粮车经过驻军节点，先处理敌军拦截，再按实际携粮空额交接，剩余物资仍运到目的城。

正式参数：[护路增援与运输](../data/design/strategic-support-rules.mjs)，一览表：[当前决策参数](design-tables/战略护路增援与运输一览表.md)。机制回归：`npm run test:strategic-support`，覆盖真实护路出征、真实野战加入、隐藏状态不影响决策、能力不足保留守备、安全绕路、中转、逐批扣粮、待执行路线复核、重复承诺拒绝及确定性继续。机制通过不代表最优战略或战争平衡结论。

## 情报、界面与存档

普通模式全国地形已探索，各势力共用城市、军团和斥候视野。AI的进攻、救援、反攻风险及运输路线评估与玩家界面共用 `intelligenceWorld` 情报投影：只读取合法可见军团的位置、当前行进方向和兵力；失去视野的敌城沿用最后情报，未知驻军采用保守估计。不读取隐藏敌军的实时兵损、实际外地易主、内部计划、后续路线或待执行军令。实际执行、己方人员和资源仍由共同模拟规则校验。见[战争迷雾与武将侦察](战争迷雾与武将侦察.md)。

AI每日优先安排侦察，负责人留城工作，模拟斥候沿真实道路每天移动105行程点，点亮与视野期限共用玩家规则。每势力最多同时两项侦察任务，不重复派往同一目标；派出城市至少保留一名实际可办事的人员，内政已有负责人仍正常计算，人手不足时停止低优先级侦察。优先当前主攻目标，其次未知或已满3天的旧边境情报，并按路程与可用负责人的智力择优。优先空闲人手，必要时释放尚未开始的可选事务，保留农业、商业、已开始事务、太守、外交及待执行军令与计划人员。正在负责侦察的武将不被自动任太守、委任其它内政、征补、编入出征或调任，未带兵的负责人也正常累计任职天数。

取得目标情报至少2天且抵达终点后，低优先级驻察可让位给评分至少高40的未知或旧边境情报；主攻目标可在当前任务完成观察后立即优先改派。不会每日反复改令或轮换尚未抵达的任务，主攻的有效驻察不会被普通边境挤占。目标已有城市或军团直接视野、已知变为友方或和平势力、战线转移后停止无用任务。

能够安排斥候的目标，在尚未观察或最后情报已满3天时先等侦察结果，再决定新进攻和最终出发；无合资格负责人时仍可按共同的未知防守保守估计评估，不赠送视野。侦察优先级和名额参数在 `data/design/strategic-scouting-rules.mjs`，主攻、边境、未知情报基础权重为200、80、80；旧情报每天增加20，上限80。执行逻辑在 `strategic-scouting-ai.mjs`。`tests/strategic-ai-scouting.test.mjs` 覆盖上限、目标与人员选择、轮换与持续驻察、真实沿路观察、人员事务保护、隐藏状态改变不影响决策、旧情报及确定性续跑。

敌方内部计划、参与队数、待执行命令与下令原因不向玩家公开；地图和情报只提供当前视野或标明日期的最近情报。内部评分仍不展示为玩家数值。

计划、预算、预留、期限、风格和每日／每旬执行标记随存档保存。验证拒绝重复计划、重复承诺、非法资源数值与旧 AI 结构；同日调用不重复执行。

## 守城与进攻编组

实际参战守城的武将立即中断事务，相关等待军令取消，内政任职保留。未参战者继续使用围城暂停规则。进攻筹划先检查人员实际驻城，再按当前事务状态编组：各可达来源城的空闲武将优先，战力足够即停止抽调；空闲战力不足时才加入忙碌武将，沿用事务剩余时间、投入及近期中断保护决定等待或立即执行。玩家编组列表共用空闲优先推荐并展示忙碌状态。

机制回归入口为 `npm run test:faction-ai`，覆盖同一目标因君主性格而作出不同选择、研判误差随能力收敛、读档不重抽、补兵资源不足、内政机会成本、占后反攻、真实行军和确定性续战。全国自然模拟不要求固定期限内必然爆发AI互战；交战机制使用真实军团抵达敌城验证。选将界面检查见 `scripts/verify-departure-priority-ui.mjs`。

`scripts/audit-strategic-pacing.mjs` 用两剧本及417、643种子通过真实战略流程记录进攻、战斗和出征队数。战斗次数仅用于诊断；验收依据为同局势对照的决策原因，不以场次下降或全面停战证明AI正确，也不据此声称经济承载达标。

当前迷雾自然局使用 `npm run audit:war-fog -- --scenario=guandu-200 --seed=417 --days=30` 验证。脚本先保存带源码哈希的独立运行快照，再用原始全国剧本和共同逐日引擎记录侦察派遣、抵达、情报、内政实际资源成果、真实离城军团、进攻计划、战斗、等待原因、缺粮及确定性存档；不会缩短道路、赠送资源、指定进攻或替换战果。结果、逐项事件和每日完整存档写入 `work/war-fog-ai/`，可用 `--out` 指定目录。占领空城单独计出征与占领，不计战斗；一支集结、援军或回撤军团也不等同于一次新进攻。

当前侦察频率与速度的机制验收使用真实派遣与沿路扫描，检查普通未知边境轮换、3天旧情报更新、主攻优先、已开始事务和经济人手保护、玩家与AI相同的105每日行程，以及存档续跑。全国诊断应在当前完整规则的独立源码快照运行，记录侦察、发展和真实出征；不以侦察次数或停战次数单独证明战争平衡或长期承载达标。
