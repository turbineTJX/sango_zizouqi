# 特技、军略与专属战法设计指南

当前内容数值从[设计表目录](design-tables/README.md)查询；机制从[战斗规则](战法规则.md)和[内政规则](内政系统最终设计.md)查询。以下用于逐项讨论和实现新能力。

名将加强以历史合作班底的实际机制衔接为优先方向。参考吕布、貂蝉的削战意与勇武配合，让一人制造条件、另一人利用条件；保留单队强者与全军支援者的定位。使用公共状态和现有羁绊，不加绑定姓名的同队倍率，AI不规划羁绊组合。当前实现与验证见[名将历史协作与战斗定位](名将历史协作与战斗定位.md)。

## 普通与强力战法的设计方向（2026-11-02）

用户确认：普通战法名称尽量使用两个字，尽量覆盖现有正面状态、异常状态及基础战斗行为，例如魔免、眩晕、位移和群体伤害；强力战法以普通战法的组合与加强为基础，例如群体伤害加眩晕，也可以包含特殊机制。

分层设计使用基础效果、组合强化和特殊机制三个观察层面；“强力”与是否为人物专属分别登记，通用高级战法也可以采用组合效果。具体拟名、组合、时长、费用、适性及兵种／人物分配见[战法分层与状态覆盖草案](战法分层与状态覆盖草案.md)，草案条目不表示已经接入。当前固定携带配置及运行效果仍以正式数据源为准。

规则141已接入一个可试玩子集：普通枪兵、青州兵近距眩晕；白毦保留远距挑衅作为护卫分支；青龙偃月可利用施放前已有眩晕。均占既有固定战法位置，不扩增携带数量。详见[短控联动试玩](短控联动试玩.md)；其余覆盖项继续按候选处理。

覆盖审查逐项核对状态目录、公共处理器、实际施放来源及固定分配。位移、群伤、恢复战意等属于战斗行为，另列覆盖；来源绑定的免伤、羁绊衍生状态及内部间隔标记单列，不直接复制为独立普通战法。自动战斗中的目标、路线和触发规则应可预期，继续使用双方共用资格、范围、资源、控制保护及结果结算。

## 军略命名、强度与覆盖方向（2026-11-02）

用户确认：军略名称、效果和持有者须相互对应。多人共用时，可采用适合各持有者的通用统军、谋划名称；采用个人典故或宗教、演义意象时，须核对实际分配依据。军略仍使用四字名称，不机械套用统一后缀；整军肃阵、抚军安众、临敌不乱等通用名称及对应固定分配现已接入。

防御类军略在数值上应强于进攻类。设计时在相近施放者属性、消耗、覆盖人数和作用时窗下，比较实际保护、救治、解控与进攻收益；护盾、救治量、控制和保护时长等分别使用可比指标，不直接把不同单位的数字相加，也不以仅降低冷却代替防御数值优势。本轮实现基准护盾45%、救治上限40%、坚定8回合、无敌6回合及范围魔免12回合；常规军略冷却20～56回合。整军肃阵也给尚无异常的选区友军坚定，AI仍有实际异常才触发。具体比较边界见军略强度说明；这些是实现初值。

军略持有人数应增加。按各剧本真实开局人员与归属，尽量让中等势力有1～2名持有者，小势力有0～1名。此为覆盖目标，不是大势力的两名上限，也不是给每个小势力强配一人。规模判断须结合实际领地、人员与军力，具体分档阈值待定；不能把在野、未登场、已去世或其他势力的人计入开局覆盖。新增名单保持人物资格、个人固定分配和真实剧本人事，转投或势力扩张不重抽军略。当前分布与后续覆盖审查见[军略名单与任职](军略池与任职-规则45.md)。

本节方向已接入：21种军略、91名持有者，新增22人；群雄集结31／37势力、讨董与割据各16／17势力、赤壁8／8势力开局拥有持有者。当前名单与各剧本覆盖见军略名单与任职，双方共用结算、简单固定AI触发及存档确定性继续验证。

## 三类能力边界

| 项目 | 特技 | 专属战法 | 军略 |
| --- | --- | --- | --- |
| 名称 | 固定两个字 | 两个字或四个字 | 固定四个字 |
| 获取 | 身份固定、开局可用，全部正面 | 16名确认武将固定持有，所有等级可用 | 统一21种；限定统帅、谋士与宗教领袖名单，取消统一智力门槛；通常1项，诸葛亮2项 |
| 生效 | 本队、军团、本人事务、太守职责或行旅，必须明确范围 | 固定携带和施放，所有兵种可用；遵守目标、门槛、冷却、次数和调息 | 合资格军团长或军师提供；按实际统智计算；零兵不提供 |
| 操作 | 自动触发或持续生效 | 不提供配装及施放顺序操作 | 玩家从完整可用列表选取；AI固定条件与优先序 |
| 主要约束 | 同名不叠加，内政按实际职责生效 | 普通补次不影响专属；补次能力不能恢复自身或相互恢复 | 同名合并取较强来源；独立冷却，奇阵、奇兵、重整与雷火每场一次 |

战斗特性使用兵科、战术与稀有共享羁绊池，种类与个人上限逐人配置，各羁绊可使用不同档位；个人上限以1级为主，2级少见，每种低级羁绊最多一名3级代表；低级最高档至少六人在场，稀有强机制须由指定多人合作到达最高档，内政及任职特性独立保留。

人物战斗特色通过羁绊组合、个人成长上限及专属战法体现。独立特性只分普通、专属，须改变规则或具有明确事件触发，不允许纯常驻属性、收益、成功率、速度或恢复倍率加减项；规则80允许实际投入兵员的屯田、卸下辎重的轻装和消耗士气的急行等有成本机制；不强制人物拥有独立特性。当前名单见[独立特性规则](武将正面特性-规则49.md)。

## 独立特性收益下限

内政、行军、外交等独立特性必须明显改变实际办事或用人的价值。对于能用主属性衡量的能力，在所绑定的事务或生效方向中，收益至少相当于增加50点对应主属性。商业、农业对照政治，军务对照统率，武备对照武力，技术对照智力，人才对照魅力；外交按该方向实际使用的属性对照。具体机制和命令范围继续由正式设计源声明，50点用作收益对照，人物真实属性保持原值。

内政玩家只能委任方向和负责人，具体命令由后台选择。随机触发、施工受阻、应对灾情、名匠机会和被动荐才可以作为特性条件，不要求每项特性稳定生效或首次任命必定兑现。应避免苛刻且没有操作入口的条件，例如安排特性交接、同时指定科技项目与研究方式、刻意保持其他负责人待命；需要玩家投入的人员、部队、运输或行军条件，应能通过现有任命与调度安排，后台自动完成具体办理。施工与研究保留真实进度及已付费用是公共规则，不作为独立特性的核心价值。验收应区分随机事件型与可安排投入型：后者使用普通任命、多个合法候选验证，不能靠锁定命令或伪造交接来证明可用性。

基础验收为相同条件、预算和日历时间下，主属性50且持有适用特性的人员，成果至少达到主属性100但无该特性的人员。还须比较正式持有者与高属性人员，保证成功率、个人属性上限和本人其他能力不会消除特性作用。专属达到该下限后，还应保留明显的额外用途或协同价值。

当前公共公式下，50至100主属性的未受限参考增量如下。成功率、部分成果及大成功按现有规则计算，实际结算仍使用整数库存和真实容量。

| 事务或机制 | 50点主属性的参考作用 |
| --- | --- |
| 集市、督耕、预备兵征募 | 预期成果约增加63.9%，包含成功率及主属性产量系数 |
| 常规研制 | 预期每日进度约增加54.9%，包含成功率及研究速率 |
| 临时产出增益、修缮耐久、安抚忠诚 | 预期成果约增加23.9%，这些事务没有相同的主属性产量系数 |
| 购粮 | 预期成交量约增加23.7%；新增成交仍须支付对应货款 |
| 10日建设 | 无协作时预期完工时间约由12.35天降至10.68天，完工效率增加15.6% |
| 外交办理进度 | 属性50至100使每日进度由1变2；另计道路、行资和审批时间 |
| 军团行军 | 同兵种、士气、缺粮条件下，统率50至100使连续行动点增加15%；逐段按天取整及携粮代价另计 |

这些比例是对照值。具体特性可通过提高本次成果、节省真实费用、缩短人员占用、扩大真实受益目标或改变办理资格达到下限，仍须计入触发覆盖和投入成本。资格型、运输型能力以明确且常见的合资格场景比较实际任务完成量或日历时间；不能只凭“拥有一种资格”认定达标。

若产能或容量使强化几乎全部被截断，须调整兑现机制后重新验收。成功率已封顶时，改以进度、成果保底或其他适用机制提供增量。增加办理额度须有固定上限且同名不叠加，不随负责人数量无限扩张；库存、真实兵源、伤兵和付款边界仍须成立。关停事务、频繁换人或免费资源不得作为特性的收益证明。

## 每项能力填写

| 字段 | 需要回答的问题 |
| --- | --- |
| 持有者与定位 | 谁持有？体现哪种实际贡献？史实还是演义依据？ |
| 范围与资格 | 本队、友军、敌军、预备队还是本人内政？要求何种任职、兵种、驻城或状态？ |
| 触发与目标 | 何时触发？合法目标怎样选择？无目标、免疫、失败时如何处理？ |
| 效果与属性 | 基础值多少？用哪种属性或威力？是否受兵力、抗性或概率影响？ |
| 时间与资源 | 持续多少模拟步？门槛、消耗、冷却、调息、每场次数分别是什么？不要混用战略天数。 |
| 叠加与边界 | 同名、同类、跨来源如何合并？净化、保护、退场、预备、死亡、避战如何处理？ |
| 真实预算 | 治疗来自哪些伤兵？征募与增产受哪些资源、容量、目标或额度限制？ |
| 存档与结算 | 保存哪些来源、强度、次数与标记？怎样避免重抽或重复奖励？ |
| 验收 | 如何证明触发正确、有实际贡献，并与同预算替代能力比较？ |

内政必须沿用六方向单属性：商业／农业政治、军务统率、武备武力、技术智力、人才魅力。军略只用统率与智力；部队战法的威力分类见[部队属性](部队属性规则.md)。不要把这些属性口径相互套用。

军略必须让施放者属性改变实际主要效果，不能只在来源资料中记录无作用的强度系数。强度类改变护盾、救疗或火势，状态类改变持续时间；预览、结算与存档共用同一折算。综合属性80为基准，每20点约翻倍，具体权重、上下限及当前逐人效果见[军略强度](军略强度与持有者-规则46.md)。

## 设计与验证流程

1. 先查[状态表](design-tables/战斗状态与效果一览表.md)与已有能力，优先复用公共处理器；新机制明确记录需要新增的处理器。
2. 修改 `traits.mjs`、`tactics.mjs` 或 `stratagems.mjs`；持有人和固定配置修改 `assignments.mjs`。稀有度、定位及史实理由写入 `notes.mjs`，不放进玩家效果文案。
3. 实现引擎并验证行为：双方共用规则，使用固定配置、战意、目标及限次流程；覆盖非均分兵力、控制／免疫边界与确定性续战。
4. 执行 `npm run design:check`、`npm run design:export`、`npm run design:verify`、`npm run test:design` 和受影响机制测试。
5. 行为通过后做同预算、开发种子与独立验证种子对照，保留失败局及换边结果。先修引擎异常，再评估强度；不为保住旧胜率回改机制，也不把全部武将胜率拉平。


## 触发频率与效果预算（规则69）

同类效果须按实际触发频率、覆盖率、人数、触发成本及每场次数分配强度，不共用一套幅度与时长。高频普攻附着采用较低幅度、短持续；有兵力门槛或明确间隔的被动可适当提高单次效果；每场一次的效果应提供更强爆发或更长有效窗口。常驻机制不机械套用持续时长，硬控制不因一次性而无限延长。持续刷新的减益只刷新、不叠层，弱效果不能覆盖或延长已有强效果。


## 状态名称与描述（规则75）

战法、军略、特性的状态名称统一取 `data/design/battle-statuses.mjs`。施加、解除、免疫或利用状态时写出正式名称，再注明效果、范围和时长；不以“破防”“奇门”“免控”等词代替破甲、穿阵、坚定。减伤状态覆盖直接伤害，统一名为“减伤”。固定属性加成和军略阵营效果不冒充单队状态。战斗时间统一写“回合”，等于一个模拟步，不是战略天数；频率、次数、免疫与真实伤兵预算仍按各自规则。

天覆按阵位首次入场快照生效，破军按真实击溃累积并限时乘胜；与桃园伤害分担与溃败强化、勇武按双方当前战意判定增伤与免疫、护卫残血邻军护盾与破盾免伤保持不同触发条件。完整规则见[羁绊特性与成长](羁绊特性与成长-规则76.md)。

入场装备同时标明来源羁绊、受益者是否必须持有、允许兵种及次数；不能将“贡献羁绊点数”混为“获得入场装备资格”。弓将、深谋、先登分别示范兵种限制、持有者限制、两者同时限制。法球单槽与限次重击规则见[羁绊特性与成长](羁绊特性与成长-规则76.md)。

桃园的伤害分配必须守恒：原目标抗性只算一次，各份额分别消耗护盾和兵力，残血容量不足的份额继续分配。无敌与奋战在整个伤害批次结束后授予幸存者，不能回滚致命伤害。蓄锐采用开战锁定的后备名额，不通过等待时间积累，不追加个人成长额度。


## 组合军略与可化解代价

规则142已接入六项带代价军略，全部持续时间随实际提供者统智计算，分别支持保护、站位、兵种分工、冷却窗口、战意支援及由施放者承担代价。增益和战斗异常分别结算，实际资源消耗不能由免疫免除，双方共用固定资格及结算；当前实现初值、名单、AI与保存规则见[军略组合与代价](军略组合与代价.md)。
