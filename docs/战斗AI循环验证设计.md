# 战斗 AI、技能与羁绊循环验证设计

更新日期：2026-10-29。接入状态：已接入第11节的战斗策略协议2，包括冻结、诊断、提案、封存、固定对手配对、兵力优势与固定玩家布阵收益验证、独立判定及接口检查。完整能力档案、自动挑战搜索、玩家全部操作与技能羁绊自动调参仍为设计。列出测试入口不表示当前候选已通过；游戏规则与效果自动编辑权限保持。

本次用户要求先与“制定策略与战斗AI可玩性验证方案”聊天约定分工，再设计战斗循环。该聊天已确认负责战略循环和通用验证框架，本聊天负责战斗循环设计，文档入口由战略侧串行登记。两套循环各自冻结依赖、登记实验和评价，不要求同步优化。

通用工具和已接入的战略循环见 [AI自主迭代与验证规则](AI自主迭代与验证规则.md)。其中的战斗样本用于接口和合法性检查，不能代替本文的战斗领域循环。

## 1. 与战略循环的约定

用户确认的运行关系是：战略 AI 在每个战略回合（10 天）的旬初，根据本方真实情况、当前视野和带日期情报重新评估；战斗 AI 在期间独立执行。战场实际进展和战果进入下一旬的合法观察。旬内仍逐日执行军令并处理真实断粮、路线失效和防务紧急情况；普通目标不因战斗每步变化而重选，仍可行的承诺继续执行。

| 边界 | 战略循环 | 战斗循环 |
| --- | --- | --- |
| 决策范围 | 目标、准备、集结、调度、资源、恢复及独立军事预测 | 合法首发与补位选择、布阵、现有军略条件的执行，以及另行授权的战斗效果调整 |
| 单轮固定依赖 | 战斗 AI、共同战斗引擎、技能与羁绊规则 | 战略策略、经济、道路、真实行军与战争准入规则 |
| 主要评价 | 当前局势下的计划合理性、兑现、成本及恢复 | 执行正确、战术决策质量、角色贡献和玩家组合收益 |
| 不代改的问题 | 不修改战斗规则或战斗 AI 提高战略成绩 | 不修改出兵门槛、资源、行军或敌方战略制造好看的对局 |
| 结果交换 | 读取本方实际情况及合法敌情，使用共同执行入口 | 返回实际在场状态、伤亡、撤离、俘虏和地点结果；由共同战略结算处理 |

战略判断不调用战斗 AI 试打来预知结果，不读取未来随机或敌方隐藏实时状态，不依赖某种精确布阵和施法。动态重评不等于每旬在线训练预测器。军事预测器归战略侧维护；战斗循环可以交付配对输入和实际损耗证据，不自行修改预测系数。

不为此新增抽象战斗结算器。独立战斗测试由正式战役生成器提供输入；全国运行继续真实行军、交战和结算。战斗结果变化会改变下一旬的决策输入，双方仍分别遵守各自接口和规则。

通用框架只共用冻结、实验登记、预算、证据、检查点和安全采用能力。战略候选的自动编辑范围排除战斗策略和规则；固定战斗依赖的合法性与接口回归可以保留。战斗时长或胜率不作为战略候选的改进目标。

## 2. 三类战斗实验

先检查相关执行机制，再优化策略或评价强度。每个候选登记唯一主类型，通常只处理一个可证伪的问题。

| 类型 | 可提出的改动 | 必须固定或保护的内容 |
| --- | --- | --- |
| 执行修复 | 修复违反现有规则的占位、接敌、补位、目标和结算行为 | 修复依据必须来自已确认规则；不得将新目标筛选或新行动能力包装成修复 |
| 战斗策略 | 调整合法首发与后备选择、基础布阵和已有规则下的范围落点 | 固定双方阵容、兵种、兵力、等级、学习记录、技能效果和场景输入 |
| 效果平衡 | 在明确授权范围内调整技能、特性或羁绊参数 | 固定策略与输入；双方共享效果；保留真实门槛、名额、来源、费用和限次 |

固定规则见[战斗 AI 边界](固定阵容AI决策边界-规则40.md)、[军略固定条件](军略AI固定条件触发.md)和[平衡目标](战斗平衡优化目标.md)。本设计不扩大这些范围：

- 游戏 AI 忽略双方羁绊点数、档位、组合、入场收益及其属性增量，不主动占阵法格或规划后备保档。偶然激活的羁绊正常结算。
- 战法固定携带和顺序，部队移动、普攻和战法自动执行；不增加玩家单队微操。
- 军略保持固定条件和优先序；范围内按已有合法有效目标规则选点，不自动升级为收益搜索或未来时机规划。
- 不为提高成绩给 AI 额外兵粮、技能、次数或行动，不强制胜负，不削弱指定对手。
- 双 AI 军议从同一中性战前状态分别提案，单方 AI 不覆盖玩家部署；援军须真实抵达，人员与任命资格共用。

效果平衡的自动编辑清单初始为空。后续授权应登记具体字段、范围、方向与禁止改变的机制。提出技能迭代需求不等于授权任意改规则；没有相应授权时仍可完成测量、归因和候选建议。现有规则内的执行修复、策略改进与规则变更分别登记。

文件归属不足以证明改动边界。`engine.mjs`、共同属性/战法模块及数据表可能影响两域；涉及这些共享模块时，登记具体符号、实际行为和依赖影响，按受影响范围验证。不得因为文件名属于战斗就默认允许改变公共规则，也不复制一套只供 AI 使用的战斗结算。

## 3. 每轮工作流程

1. **登记问题。** 保存原始失败、合法输入、观察范围和复现条件；区分机制错误、策略失误、效果不足、受克制及证据不足。
2. **冻结基线。** 记录源码、依赖、规则与数据版本、裁判版本、测试清单、生成器和控制器。运行必要前置检查，未通过相关机制检查时不以胜率决定平衡改动。
3. **登记实验。** 在候选结果产生前固定假设、改动范围、主要指标、保护指标、样本矩阵、统计方法、停止条件和预算。
4. **产生少量候选。** 先做最小机制复现和开发样本配对。明显无效、越界或破坏资格的候选立即淘汰，并保留证据。
5. **检查泛化。** 使用多种对手、地形、兵力分配、援军与后备情况，检查收益是否依赖一个阵容或一张地图。
6. **独立验证。** 冻结入围候选及模拟玩家方案，再使用独立种子和留出的阵容、地图条件；禁止看到结果后重选样本。
7. **独立判定。** 给出领域改善、淘汰、证据不足或需要设计判断；领域改善不自动代表整个游戏可玩。
8. **组合检查与采用。** 对当前战略版本和候选战斗版本运行必要真实集成，检查并行改动后才能采用为本机组合。未通过或未完成则保留候选。
9. **积累问题。** 将有价值的失败归入回归库，扩展相邻合法条件；旧的验收样本进入开发库后补充新的独立样本。

参考另一循环已确认的单轮 8 小时上限，不创建定时任务，也不因预算耗尽降低证据要求或自行续开预算。先测实际运行成本，再登记候选数、样本数及各阶段预算。连续无效、需要超范围改规则或预算不足时停止该方向并报告原因；用户发起下一轮后，检查点仅续接相同冻结版本和实验协议。

## 4. 实验登记与证据格式

战斗域使用独立协议并复用通用快照、工作进程和安全采用能力。下表是完整目标字段；首版 CLI 实际覆盖范围见第11节，未登记部分不能据此声称已经验收。

| 字段组 | 必须记录 |
| --- | --- |
| 身份 | `experimentId`、`domain=battle`、`changeKind`、基线与候选编号 |
| 假设与权限 | 问题、预期行为链、允许修改的文件/符号/参数、授权依据、禁止改动 |
| 冻结 | 运行源码及依赖指纹、规则/人物/地图版本、裁判与输入生成器指纹、战略依赖标识 |
| 目标 | 主指标、合格机会定义、最小有效改善量、保护指标及允许退步范围 |
| 输入 | 完整生成器输入、预算口径、地图、阵容、兵力、等级、学习、任命、后备、援军、出生侧 |
| 控制器 | 双方采用的 AI 或模拟玩家版本、开发与验证分组、有限观察权限 |
| 统计 | 独立样本单位、配对方式、样本数、置信标准、多候选处理和停止规则 |
| 运行 | 实际耗时、已完成/未完成/无效案例、失败原因、开始/结束状态、关键过程、续战检查 |
| 结论 | 硬约束、局部改善、领域覆盖、组合集成、真人体验、全国观察分别记录 |

结果由裁判从实际事件和状态计算，不接受候选程序自报“通过”。逐局保存所有胜、负、平、超时和失败；失败不能被删除以改善均值。冻结前后都验证源码和测试清单，输出目录每次独立且不覆盖完成的实验。

过程记录使用稳定事件身份或明确的状态增量边界，不能把跨帧保留的同一效果重复累计。确定性续战副本只用于核对，不作为第二场独立比赛。快照覆盖实际加载的传递依赖；冻结期间文件变化则重新冻结，不混用一半新一半旧的模块。

候选不得编辑裁判、测试、指标、输入清单或历史证据。正式实现应将裁判和私有验收数据置于候选不可写的执行边界；单纯哈希和文字约定只能发现部分改动，不能宣称已构成操作系统隔离。受保护内容有变化时整份受影响证据失效，不继续晋级。

## 5. 局面库与覆盖登记

案例分为机制局、合法对照局、自然战斗样本、真人问题样本，分别保存来源。固定接敌或消融只用于明确标注的实验，不能冒充自然全 AI 结果。

同结构的真实战斗检查点可在冻结版本上分叉对照。规则或存档结构改变后，旧样本只能在原快照复现，或从保存的战役输入经当前生成器重新校验创建；不能补字段迁移成当前存档。重新生成的对照须保留来源和重建标记，不继承原自然局的发生次数或验证结论；无法合法重建的样本报告输入失效。

| 维度 | 基础覆盖与扩展方式 |
| --- | --- |
| 用途 | 野战、攻城、关卡、港口、水战，覆盖开放地形、狭路、遮挡与水陆限制 |
| 名单 | 普通将协同、名将带辅助、名将散搭、同职责替换及有明确克制的对手 |
| 分兵 | 均分、单核、双核、低兵力辅助；遵守实际带兵上限与整数预算 |
| 时序 | 无后备、有后备、真实多军团援军、不同抵达时间、伤亡后任命与撤离 |
| 状态 | 正常接敌、受控与免疫、残兵、已有消耗、门被破、合法入口被占或受阻 |
| 对手 | 当前基线、多种合法基础策略、针对已知弱点的压力策略、冻结的模拟玩家 |
| 对称性 | 交换双方身份和出生侧；对称地形另做 14×8 六角格正确旋转的机制检查 |

首次不穷举全排列。每项正式能力先登记定位、适用条件、至少一个生效与条件不足的机制案例、可观察结果和同成本替代对照；按公共机制选代表组合，再优先覆盖本轮改动的关联能力。新增能力或改动后缺登记时报告覆盖缺口。

覆盖状态明确区分：未测试、输入无效、未遇到合格机会、机制通过、平衡证据不足、观察到改善、观察到退步。没有发动机会不能填成零收益或“没有问题”。

同兵力不等于同成本。登记等级、训练费用、兵种、装备、将领可得性、名额及援军等待成本；只有配对的相应项目实际相同才称同预算。普通将可以持有高级羁绊，美女辅助不因倾国而自动排除。历史战役保留合法不对称预算，不要求五五开。

## 6. 指标与归因

| 观察项 | 计算与解释 | 防止的误判 |
| --- | --- | --- |
| 合法执行 | 非法占位、资格、资源、限次、重复结算、存取分歧 | 不用胜利掩盖规则错误 |
| 接敌与行动 | 记录存在合法可达行动的时间、实际行动、阻塞/冷却/控制/固守等原因 | 合法等待和真实拥堵不一律记成 AI 发呆 |
| 战法使用 | 合格机会、实际施放、覆盖、命中、落空、消耗和中断 | 施放多不必然更好；合法落空、对免疫目标施放不自行判违规 |
| 输出与突破 | 实际有效伤害、双方剩余兵力、关键目标失守或溃败的时机 | 不以伤害刷量或低价值目标代替目标收益 |
| 支援与承伤 | 实际救治、护盾吸收、有效驱散、存活时间；控制重叠不重复累计 | 发盾总量、溢出治疗或演出次数不当成有效贡献 |
| 协同 | 提供者→受益者→实际效果链；是否跨过真实施法门槛、保住主核或形成突破 | “带着辅助也赢了”不能证明辅助有贡献 |
| 代价与风险 | 名额、兵力、训练和装备成本、核心生存、后备等待与克制条件 | 满档收益脱离凑档成本，或极低成本套路通吃 |
| 结束质量 | 胜负、实际目标、时长分布、停止原因、无进展尾段 | 固守有效、势均力敌和程序卡死分开；不奖励强制结束 |
| 性能 | 决策耗时、模拟吞吐、内存和存档体积 | 在有限样本上变强却失去实际运行能力 |

每项技能、特性和羁绊有定位档案：作用、合格机会、真实贡献、门槛成本、适用场景、克制与替代者。输出、支援、承伤分别评价，不合成为一个万能战力分数。

机会定义由裁判固定，不能由候选缩小分母。比率必须同时报告机会数、实际在场时长、总收益和总损失；通过少出阵、主动早退或让目标条件不再发生得到的漂亮比率，不自动视为改善。新旧行为造成机会不同，需要解释实际目标和代价的变化。

归因优先使用合法干预：同名单更换站位或顺序，同预算替换搭档，保持其余条件。四组整队替换可计算“都有 − 只有 A − 只有 B + 都没有”的交互差，但它包括整套人物能力、任命和阈值变化，不能声称隔离了某一羁绊的纯贡献。关闭单技能等离线消融必须单列，最终收益仍回到合法完整阵容确认。

## 7. 模拟玩家与对手

模拟玩家是实验控制器，不并入游戏 AI。它可使用玩家实际已有的选将、兵种、分兵、首发、部署、后备、意图和军略入口，只看玩家合法可见信息，不读取随机种子或未来战况，不直接写效果。

开发阶段可以搜索组合；独立验证前固定方案或固定可见状态的应对策略。其搜索预算、决策频率和控制器版本均保存，禁止验证后改成针对该种子的最佳操作。静态布阵方案和战中军略应对分别比较，不能把无限搜索或读档重试算作真人操作价值。

主要比较默认方案与合理方案、合理方案与错配方案，以及同预算替换。保护普通将协同、名将带辅助、强弱混搭的可行空间，保留六种高级羁绊的真实门槛和各自作用。不要求所有人有相同胜率、所有组合都强或所有局面可翻盘。

挑战者寻找低成本重复控制、异常叠加、出入口利用、目标追逐和后备等方面可反复利用的合法弱点。新挑战固定输入并留出相邻变体；挑战发现先判断规则允许的克制还是缺陷，不因候选输了就修改对手。真人试玩用于校准体验，不能由模拟玩家成绩替代。

## 8. 配对、统计与晋级

策略实验保持规则不变；效果实验保持策略不变。若一个候选确实同时改变二者，必须补做旧策略/旧效果、新策略/旧效果、旧策略/新效果、新策略/新效果四组归因；每场双方始终共享同一套效果规则。跨版本 AI 只有在可加载到同一公共引擎且通过接口验证时才交叉对战，否则使用相同输入和固定对手分别运行，不伪称直接交叉对战。

同案例配对相同初始种子及生成器输入，保留双方交换。相同种子不保证分歧后的随机调用一一对应，结论依靠多独立样本。非对称地图换边不要求成绩一致；阵容质量不同也不要求平局。

在登记时固定主要改进量 `delta`、每项保护容差 `epsilon`、所需独立样本数 `n` 和置信标准 `alpha`。先测基线波动再制定，缺少这些约定不得自动晋级；不能把本文的局部诊断升级为统一胜率或固定时长门槛。

一个种子下的多次续战、镜像、同阵容变体不重复当成完全独立证据。按预登记的种子与场景族聚合或分层配对统计，同时报告各用途和阵容族的退步。开发搜索与最终验收分开；多候选择优采用预登记的错误控制或额外独立确认样本。不能看到有利结果就提前停止。

| 判定 | 条件与后续 |
| --- | --- |
| 领域改善 | 本次必需硬约束全通过；配对覆盖完整；主要目标达到预登记改善且统计支持；保护项无不可接受退步；权限与源码检查通过 |
| 淘汰 | 新增硬约束失败、越权、证据失真、确定性破坏或确认不可接受退步 |
| 证据不足 | 预算/样本不足、机会未发生、输入失效、波动过大、必要检查缺失或未能复现主要改善 |
| 需要设计判断 | 改善伴随未授权的体验取舍，或需要改变现有产品边界 |

允许逐步改善，但相关机制失败不能带入平衡结论，既有未解决问题必须列明。领域改善、全部登记领域覆盖、组合集成、真人体验、全国前中后期及自然统一各自记录状态，不互相冒充。局部样本不作为发行通过依据。

## 9. 组合采用与战略交接

每个结果绑定一个明确组合：战略策略、独立军事评估、战斗策略、共同战斗引擎、技能/羁绊数据、地图/人物数据及验证协议的指纹。版本号只是标签，实际以文件和输入指纹为准。

战斗候选通过领域验证后，可以成为战斗域已验证候选。采用到共享本机前，核对当前战略与公共依赖，并针对影响范围运行真实集成：

- 真实军团抵达、军议、战斗推进、援军、退出及结果交接保持合法。
- 伤亡、伤兵、俘虏、人员去向、物资和地点结果真实且只结算一次，人数和库存为整数。
- 战后任命和存档续行按当前版本处理；跨旬后战略读取实际变化，不在旬内重选普通目标。
- 当前视野与旧情报边界、AI 羁绊盲区、计划保护及紧急复核继续生效。
- 影响共同战斗效果、战损判断或战略接口时，在原始全国剧本中观察相应真实行为；纯策略候选不逐轮强制全国长局。短局未遇到所需情况标记未覆盖，不通过免费资源、指定战争或强制战果补齐。

接口机制可以用合法固定条件覆盖，必须与自然观察分开。小候选不必等待整个全国长局或自然统一；影响战略战损判断、恢复与节奏的较大效果变更，应登记扩大集成范围，交付预测与实际偏差给战略侧。不得因战略长局指标不好而自动改出兵门槛，反之也不得改战斗效果来满足战争频率。

若两域均有新版本，分别验证各自候选后，对拟采用的组合补做集成。未验组合不能继承另一个组合的通过状态。运行中的游戏不热换规则；新规则使用当前合法新开局，旧结构直接提示重新开始，不增加存档迁移。

采用沿用已确认的本机自动采用方向，不自动提交、推送或发布。共享采用过程须串行，比较冻结基线和当前文件指纹，保留并行改动；有冲突则候选待采用。只应用明确变更并保留可回退记录，不重置整个工作区。实验登记与快照沿用通用框架的本机 `.local/ai-iterations/`；大型战斗记录也可存入登记过的 `work/` 或 `outputs/`，均不进入 Git。正文与实现代码按项目约定同步。

战斗协议目录为 `scripts/battle-validation/`，不与战略协议互相覆盖。完整能力分期实现，每一步有可检查的产物：

1. **协议与登记器：** 战斗范围、权限、案例、指标、版本组合及判定状态；接通通用冻结/预算/证据能力。执行器与裁判的保护边界落实后才允许无人值守自动晋级。
2. **统一执行适配：** 通过正式生成器和 `stepBattle` 运行既有案例，统一记录机会、实际贡献、退出原因及确定性续战，保留所有失败。
3. **对照与独立裁判：** 基线/候选配对、多对手、有限模拟玩家、统计与分组保护，输出领域结论。
4. **组合交接：** 注册受影响的真实集成用例、当前组合指纹、安全采用及回退；共享文档和采用入口串行修改。
5. **小范围试运行：** 先从首发/补位/基础布阵中选一个证据明确的问题完成闭环，再扩展到已授权的技能/羁绊参数。不直接启动全目录自动调参。

初次测量优先回答：合法后备是否得到合理入场机会，主辅站位是否产生实际支援，名将专属是否在适用场景发挥作用，普通将协同与名将带辅助是否保留可复现收益。这些是待测问题，不预先宣称当前实现失败。

系统自身的验收需覆盖：拒绝越权候选；拒绝缺样本/零机会/无效输入；拒绝修改裁判或混用版本；续行不重复计数；保留败局；拒绝未验组合；采用遇并行修改或中断可恢复。最终先展示一次真实基线、候选、独立结论和回退链，再开展无人值守迭代。

## 11. 当前循环协议：基本判断可信，玩家决策有价值

2026-10-29 用户确认的总目标：AI 能打明白基本仗，AI 互战不因明显基础失误而失真；玩家通过组合、分兵、布阵、出阵顺序和军略决策获得优势。允许有限退步，但不能形成明显、可反复利用的失能问题。正常兵种克制与玩家组合获益属于设计空间，不当作必须消除的漏洞。提高 AI 胜率不是唯一目标。

协议2以正式自定义战役生成器和真实战斗引擎执行。共同引擎、人物、地图、技能羁绊、战略与经济全部冻结；只切换受测一方的 AI，对方维持冻结策略。实验控制器在独立 Node 工作进程内路由策略函数，两个版本共用同一引擎和数据模块，不重写战斗结算。路由前后基线真实战斗须完全一致。当前可编辑文件仅为 `battle-ai.mjs`；出阵与基础部署可以调整，军略条件与优先序的函数和常量须与基线相同。将来扩展其它策略文件须升级协议并补控制器隔离验证。

### 样本与评价

| 检查 | 具体对照 | 判定含义 |
| --- | --- | --- |
| AI 基本战斗 | 五类用途、不同阵容/等级/分兵、后备和固定分散对手 | 比较任务成功率和双方剩余兵力差；技能次数、时长、停滞记录只作诊断 |
| 明确优势兑现 | 同一名单、等级、装备、对手与地图，真实兵力从每队3000增至4500 | 测量兵力优势总体是否改善结果；这是明确不等预算的校准，不是同预算强度结论 |
| 玩家决策收益 | 普通将组合、关羽混搭和周瑜混搭，相同名单、兵种、等级、兵力与训练预算，默认布阵对合法阵法占位 | 玩家一侧的其它自动决策固定，敌方才切换新旧 AI；按普通将与混搭两族检查收益是否仍存在 |
| 规则与基本执行 | 合法军议、部署、补位、军略、AI 羁绊盲区、整数兵力、双方共用规则、存档续战 | 失败、跳过、缺失或证据变化均不得晋级 |
| 已知薄弱场景 | 上轮发现的攻城、关卡加入开发局，另有分散对手与相邻地图 | 观察反复退步，正常克制不作为违规；不能凭有限样本声称不存在所有可利用问题 |

任务成功率使用真实胜负归属，未完成目标不计胜利。战损主指标为“本方余兵/本方初始兵力 − 对方余兵/对方初始兵力”，统计全体真实名单，包括后备，避免少出阵获得虚假的低损耗。任务成功率先受保护，再检验登记的战损改善；单纯多施法、打得快或造成更多伤害不算策略改善。

本协议的实现初值在实验前固定，属于可复核的局部验收参数，不声明用户逐项确认或升级为全游戏平衡标准：

- 每轮最多3个候选、总预算8小时（含实现和编辑）。开发种子2个；独立种子8个，开发与验证不重复。候选改动前登记主指标 `missionRate` 或 `remainingMargin` 及最小改善量；按独立种子聚合，单侧符号检验阈值0.05/3。战损目标首轮建议登记0.04，即双方余兵比例差改善4个百分点。
- 总体任务成功率允许下降最多3个百分点；单场输赢不一票否决。单个场景平均任务成功率下降超过12.5个百分点、或双方余兵比例差下降超过10个百分点，且至少75%的独立种子方向变差，视为反复退步，不能由其它场景平均提升掩盖。
- 兵力优势样本的平均双方余兵比例差须提高至少2个百分点，任务成功率下降不超过5个百分点。仅代表登记的兵力优势校准，武将质量、兵种与地形的全面校准仍需扩展。
- 玩家普通将、混搭两族分别须观察到布阵的平均余兵比例差收益至少5个百分点或成功率收益至少12.5个百分点，并在至少2个独立种子上观察到合理方案获胜。已有达到该量级的布阵收益，新版须至少保留一半。只保护有限合法方案的可复现空间，不要求任意组合必胜，也不代表真人操作已验收。

当前开发阶段每版本每种子30场，基线诊断60场；候选开发对照120场。独立阶段每版本每种子56场，合计896场。换边与同种子的变体不当作额外独立种子。所有胜、负、超时与失败保存；约定24回合断点续战副本仅用于一致性检查，不计为新增比赛。批量任务串行运行，工作进程使用低 CPU 优先级；并行其它任务时不把墙钟耗时直接解释为策略性能。

### 执行与采用

入口为 `npm run battle:iterate -- ...`，工具回归为 `npm run test:battle-validation`。

```powershell
npm run battle:iterate -- init --started-at=<本轮实际开始UTC时间>
npm run battle:iterate -- probe --session=<返回目录>
npm run battle:iterate -- propose --session=<目录> --id=<候选名> --metric=remainingMargin --delta=0.04 --hypothesis="可证伪的问题"
# 仅在返回的 editRoot 中修改允许的策略。
npm run battle:iterate -- seal --session=<目录> --id=<候选名> --review="具体规则边界与源码复核"
npm run battle:iterate -- run --session=<目录> --id=<候选名> --stage=development
npm run battle:iterate -- run --session=<目录> --id=<候选名> --stage=validation
npm run battle:iterate -- integrate --session=<目录> --id=<候选名>
npm run battle:iterate -- adopt --session=<目录> --id=<候选名>
```

“候选值得采用”要求登记改善成立、任务结果与玩家空间保护通过、相关机制和接口回归通过。“战斗 AI 整体达标”另外报告覆盖范围；候选连续失败或预算耗尽不能解释为整体已经达标。当前固定玩家方案只覆盖阵法部署，尚未覆盖玩家选将、军略时机、全部能力贡献与真人体验。

纯策略候选的组合检查运行指定军团/战斗/战略接口回归，全国自然长局不再作为每次战斗优化的必跑门槛。改变共同战斗效果、战损模型或战略接口时，另行登记所需自然集成；这些内容不在当前自动编辑范围。采用前仍须核对实际共享工作区与冻结基线，遇到其它改动则保留待采用候选，不覆盖并行工作。

每次读取实验还核对执行入口的战斗与共享验证工具目录指纹，禁止用改变了实现的新裁判重判旧实验。旧实验通过其 `baseline/scripts/battle-validation/cli.mjs` 冻结入口读取。哈希、源码复核与独立测试不构成操作系统权限隔离；没有常驻生成代码程序，也不自动续开预算。
