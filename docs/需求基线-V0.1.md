# 三国君主策略手游：需求基线 V0.1

本文依据用户提供的《三国君主策略手游总体需求说明 V0.1》整理。已确认需求与待确认规则分开记录；建议不视为已确认需求。

## 1. 游戏定位

离线单机三国策略手游。玩家扮演一方势力君主，通过经营势力、管理武将、组建军团、制定战略和指挥战争方向，最终统一天下或达成剧本目标。

核心理念：玩家是君主，负责战略方向、武将任命培养、军团调配、战争目标与关键军令；程序 AI 负责带兵执行和自动战斗。玩家创造历史，而不是操作每一次战斗动作。

已确认的技能设计参考：技能、战法、军略等的名称与效果可以参考《三国志11～14》《三国志8 REMAKE》，机制必须适配本项目。采用被动技能、局部自动战法、全局军略三层结构；具体参考来源与已落地条目见[系列参考与机制适配](系列参考与机制适配.md)。

用户补充确认：武将技能优先参考《三国志11》的枪将、飞将、米道、富豪等特技，允许服务于内政、外交而非仅战斗；专属战法重点参考《三国志12》《14》，军略可重新设计。当前按[规则31](武将特技与军略-规则31.md)实现战斗与内政技能，并明确预留未开放的外交技能。

最新设计顺序：先确定[内政、外交、战斗基础技能池](基础技能池-设计草案.md)。技能可多人共用，不是每个武将都要设计专属技能或强力技能；既有及试配路线不代表最终人物分配，基础池尚未定稿前不继续逐人扩写。

## 2. 整体循环

战略层决策 → 军团行动 → 事件处理与战斗触发 → 独立战场自动战斗 → 战果返回战略层 → 下一回合。

- 战略层采用类似《三国志11》的大地图与回合制时间。
- 时间尺度（月、旬等）由后续玩法测试确定。
- 战斗层采用自动战棋 / 自走棋式战斗；战斗采用实时、固定步进还是回合制尚未指定。

## 3. 战略层

地图包含城池、关隘、道路、资源点与特殊地点。

战略层基本军事单位是军团，包含主将、副将、军师、武将、士兵、兵种、粮草和当前任务，并具有驻地或行军位置。

军团管理支持创建、合并、拆分、任命主将、调整武将与兵种配置。

军团行动支持移动、出征、驻守、攻城、援军与撤退。战略地图处理行军路线、行军时间、粮草消耗与遭遇判断。

军团遭遇或攻击据点时触发战斗。

## 4. 战斗层

### 单位与容量

- 战斗单位为“武将 + 部队”。
- 同一武将可统帅不同兵种；兵种影响移动力、攻防属性、战斗方式与战法效果。
- 双方各自最多同时存在 6 个战斗单位。
- 军团全部武将均属于战斗序列，未进入第一梯队者作为预备队。例如 15 名武将分为 6 名前线、9 名预备队。
- 预备队入场条件包括前线被击破、部队损失达到阈值、出现空位或特定军令；具体入场和轮换规则待设计。

### 战前决策

- 选择第一梯队与预备队。
- 安排前排、中排、后排和两翼布局。
- 设置激进、稳健或防守等整体倾向，影响 AI 行为。

### 单位 AI

不使用自然语言理解，全部行为由程序规则决定。目标是行为稳定、可解释、符合武将特点，并能被玩家预测和利用。

单位自动检测状态、选择目标、判断攻击条件、移动或攻击、判断战法并执行动作，循环直到战斗结束。

### 战法

战法属于武将 / 部队，根据士气、冷却、战斗状态、目标条件与武将特性自动释放。玩家不能手动控制单个武将施放。

示例：关羽“威震华夏”、张飞“咆哮”、赵云“龙胆”。示例名称不代表战法参数已确定。

### 玩家军令

玩家不能控制单个单位移动、直接指定攻击目标或操作单个单位；只能实施战略级干预。

| 军令示例 | 需求中的效果 |
| --- | --- |
| 鼓舞 | 提升全军士气，加快战法释放 |
| 集中目标 | 提高指定敌军的目标选择权重 |
| 全军撤退 | 改变全军行为，尝试脱离战斗 |
| 投入预备队 | 让后备武将进入战场 |

“集中目标”影响 AI 选择倾向，不等于强制每个单位攻击该目标。军令次数、消耗、冷却与可用条件尚未确定。

## 5. 武将系统

- 基础属性：统率、武力、智力、政治、魅力。
- 战斗能力：影响部队属性、战法与 AI 行为倾向。
- 人物关系：影响忠诚、招募、联合作战与特殊事件。

武将的差异不应仅体现为数值高低。

## 6. 战果回写

战斗结束后返回战略层，处理胜负、武将状态、部队损失、伤兵、俘虏、士气与据点归属，然后继续战略流程。

## 7. 开发优先级

第一阶段优先验证：战略地图 + 军团移动 + 遭遇战 + 6V6 自动战斗 + 武将 / 兵种系统。

后续逐步增加城池经营、外交、人才系统、历史事件、武将成长与更复杂的战役 AI。总体需求中的全部功能不等于第一阶段必须一次性完成。

## 8. 待确认的关键规则

以下是实现缺口，不是对用户需求的变更。

| 问题 | 需要明确的规则 |
| --- | --- |
| 交付形态 | 先做玩法原型、正式手游工程，还是详细设计；引擎与首发平台 |
| 战斗时间 | 实时或回合推进、是否暂停、速度档位 |
| 预备队 | 满员时军令如何生效；伤损触发是等待空位还是主动轮换；入场位置与延迟 |
| 兵力编制 | 军团总兵力如何分配至武将部队；预备队是否预先持有兵力 |
| 遭遇与援军 | 敌军路线交叉如何判定；多军团参战如何共享每方 6 个席位 |
| 胜负与撤退 | 预备队尚存时能否判负；撤退所需时间、损失与回到战略层的位置 |
| 战果映射 | 战斗损伤如何转化为阵亡、伤兵与俘虏；攻城和野战如何分别处理归属 |
| 离线存档 | 自动存档时机、手动存档、战斗中退出后恢复方式 |

## 9. 首个可玩切片建议（尚未确认）

采用小地图、少量城池与两方势力，验证下列完整路径：

1. 查看己方军团，调整武将、兵种、首发、预备队与阵型。
2. 选择目的地并推进战略回合，看到行军位置和粮草变化。
3. 遭遇敌军后进入独立战场，按预设策略自动战斗。
4. 使用战略军令，观察目标倾向、士气、撤退或预备队的变化。
5. 查看战果并回到战略地图，继续下一个回合。

建议验收标准：

- 所有时刻每方在场单位均不超过 6 个，预备队入场遵守容量限制。
- 玩家不下达战中军令时，战斗也能自行结束；僵持处理规则需先确定。
- 玩家无法直接操作单个单位；军令通过规则影响 AI。
- 战果只结算一次；军团兵力与各部队兵力、伤亡数据一致。
- 关键 AI 决策有简短可读记录，便于理解与调试。
- 核心游戏运行不依赖网络；存档恢复后能继续推进。
