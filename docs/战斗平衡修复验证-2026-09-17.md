# 战斗平衡修复验证：规则 4

> 历史验证记录：以下数据对应 110 战意上限的规则 4。后续按用户要求将上限改为 100（规则 5），八百破阵、十胜奇谋门槛同步改为 100，并兼容规则 3、4 存档。下列胜率不是规则 5 的重新测量结果；当前规则以 README 和战法规则文档为准。

## 已实施

1. **战意上限 110。** 引擎、战法选目标、界面共用 `combat-rules.mjs`。全部战法门槛不超过上限；普通减战意使满条降到 65，让低门槛技能继续工作、中高门槛技能暂时受限。攻击、受击、鼓舞、入场被动均遵守上限。仍不消耗施放战意。
2. **低战意叠层技能。** 新增步步进逼（枪／骑，20 战意，武力）和扰阵轻射（弓／弩，25 战意，智力），均为 8 步冷却、0.45 倍直接伤害。前者每层降低 4% 防御，后者每层降低 4% 攻击；分别上限 3 层，基础持续 10 步，多队共享层数，命中刷新持续时间。可净化，支持存档，面板显示当前层数与降幅。
3. **配装有门槛梯度。** 试炼双方及“按属性推荐”使用低门槛技能搭配中高门槛技能，后者在条件满足时优先。保留玩家手动槽位顺序；高智力弓弩将改用谋略伤害和支援。
4. **修复方阵与索敌。** 敌人必须在普攻范围内才自动开方阵。普攻可用时优先选择范围内目标，避免为追残血白白丢掉本步攻击；显式合围保留目标优先权。
5. **守城阵线。** 守方普通移动与冲锋路径限制在城门侧阵线，目标评分优先威胁城门的敌军。阵线外无合法接敌位置时保持守备，而非开局冲到对面。
6. **兵力影响直接伤害。** 系数改为 `sqrt(clamp(当前兵力 / 3000, 0, 1))`。1800 人的系数约 77.5%，3000 人为 100%，1 人约 1.83%；避免残兵保持半数直接火力。护盾与治疗仍按自己的规则结算。
7. **试炼配置重调。** 白马加入荀攸并解锁急救；陈留、许昌任命于禁为主将、荀攸为军师，解锁持续恢复、急救与接防盾。调整兵力使机制有展示空间，不靠无限护盾补偿人数差。

| 战役 | 新我军 | 新敌军 | 主要改变 |

| 白马 | 4 × 3000 | 12 × 1050 | 敌军每队由 1800 降到 1050；曹操、张辽、郭嘉、荀攸 |

保留每方最多六队、预备队顺序、波次到达步数、城门耐久、20% 默认守城护盾及各战役时限。白马仍为以少队击败多队的困难关，但不再要求原先几乎没有输出补偿的四队承受 21600 人。

## 同种子对照

每个战役使用其默认种子起连续 100 个种子。挂机组不发军略；军略组只用一个可复现的简单策略：伤兵足够时优先持续恢复／急救，否则按可用项依次选择火攻、强攻、防御、鼓舞。不是最优布阵或真人操作。

| 战役 | 修复前挂机胜率 | 新版挂机胜率 | 新版军略组胜率 | 新版挂机平均时长 |
|---|---:|---:|---:|---:|
| 官渡 | 0% | 39% | 99% | 121 秒 |
| 白马 | 0% | 12% | 48% | 99 秒 |
| 界桥 | 0% | 35% | 100% | 152 秒 |
| 邺城 | 41% | 21% | 77% | 125 秒 |
| 许昌 | 0% | 13% | 41% | 190 秒 |
| 陈留 | 0% | 47% | 100% | 129 秒 |

- 前后比较包含规则、阵容与兵力共同变化，不能把全部胜率提升归因于单个 AI 修复。
- 新版官渡挂机有 2 场平局，军略组 1 场；许昌挂机 2 场平局，军略组 4 场。表中其余未获胜样本为负。
- 邺城挂机胜率降低，但使用军略明显改善；守方 AI 现在不会开局主动离开城门阵线，所以不能只用“胜率上涨”评价修复。
- 低门槛技能首次发动平均在第 3 步（野战）、第 4 步（邺城）、第 5 步（许昌）。这约为 2.1～3.5 秒，能在中高门槛战法之前参与交战。
- 界桥第三波在挂机组、军略组各 100 场中均至少有一队实际入场；此前默认挂机 100 场中有 96 场第三波完全未出场。
- 许昌仍是偏难的守城试炼，军略组有 15 场进入日暮比例判定，不能把其胜率理解为全都歼灭攻城军。敌方仍只有单位层的自动战法，未加入完整的敌方军略决策系统。

## 验证

- `npm test`：**141 项全部通过**。新增 9 项回归覆盖战意上限、减战意门槛作用、旧档迁移与非法数据、方阵接敌、近目标攻击机会、实际兵力伤害、跨单位叠层／封顶／到期／净化／保存、高低门槛调度、试炼军略与守城阵线。

- `npm run audit:balance`：**3210 场完整模拟、79 个实验组**。包含上述 1200 场主对照，以及单项军略、配装、策略、等级、护盾和集火城门实验。逐步检查战意范围、六队上限与占格唯一性；结算检查兵力守恒。全部完成，没有断言失败。
- 浏览器独立端口 **4185**：核对六个试炼卡片的新人数／说明；配置中可选 20 战意的步步进逼，冷却与叠层描述正确；官渡推进至第 10 步，曹操显示 **110/110 战意、破势 3/3（−12%）、扰阵 2/3（−8%）**。刷新后步数、双方兵力、战意及状态标记保留，仍为暂停。未捕获页面脚本错误。未访问原 4173 存档。

## 存档与复现

规则版本从 3 升至 4。读取规则 3 存档时仅将超额战意压至 110，保留既有军团、战斗和配装；继续战斗采用新规则，结果可能与旧版本不同。规则 4 存档仍严格拒绝超上限战意或非法层数。**已有试炼需重开才能应用新兵力和推荐配装。**

```powershell
npm test
npm run check
npm run audit:balance
node scripts/balance-probes.mjs
```

- 修改前数据保留于 `docs/balance-audit/`，不会被新版脚本覆盖。
- 修改后数据位于 `docs/balance-audit-v4/`：`summary.json`、`runs.json.gz`、`default-seeds.json`、`probes.json`。
- `scripts/calibrate-trials.mjs --sweep` 可运行候选兵力扫描，仅修改进程内配置；`commandTrial` 是军略对照策略，不会在游戏中替玩家自动使用军略。

以上是固定种子抽样验证，不代表已经穷尽兵种、配装、布阵与操作空间。下一轮应重点观察高低门槛配装比例、守城日暮判定频率，以及治疗军略在多场战斗中的收益。
