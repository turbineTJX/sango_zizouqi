# 内政系统最终设计

版本：V1.5  
日期：2026-09-19  
状态：设计定稿；首版已接入战略模式，基础范围见[内政实现与验证](内政实现与验证.md)。V1.5的同城同方向多人委任与自动协作已实现，当前数值与验证见[内政协作实现与验证](内政协作实现与验证.md)。

## 1. 设计目标与范围

玩家指定城市、内政大方向和执行人，执行人持续自主行动，直到玩家给他新的命令。同城同方向可委任多名武将，各自处理事务，并有机会自动协作提高成效。玩家负责战略取舍，武将负责选择具体事务。

内政固定为五个方向：**商业、农业、技术、军事、人才**。军事包含原有城防，以及征兵、伤兵恢复和守城准备。

核心原则：

1. 持续委任，无固定任期。具体行动有起止时间，委任不会因为完成一个行动而结束。
2. 行动必须经过规则执行才能改变状态，文字描述来自真实结算结果。
3. 行动种类足够丰富，不同动作有不同适用条件、投入、时间和风险。
4. 内政行为不保证全部成功，允许正常成功、超额成果、部分达成和失败。
5. 随机性来自合理选项中的选择、偶发机会和行动结果；武将会根据成败调整下一步。
6. 围绕钱、粮、预备兵、已编入部队的士兵、伤兵、城防和现有战斗规则，不模拟完整商品经济。
7. 每项行动开始前发出开始事件，结束后记录实际花费、成果或损失。
8. 五个方向都具有新建、扩建建筑的动作。建筑提供长期能力，主动事务提供当期成果或有期限的准备效果。

本文确定玩法结构与边界。具体金额、收益、工期、概率、冷却期和技术解锁清单列入待调参项，不将对话中的示例数字作为正式数值。

## 2. 城市资源与军事能力

### 2.1 资源定义

| 项目 | 定义 | 与战斗的联系 |
| --- | --- | --- |
| 钱 | 势力共用府库，可用于建设、研究、征募、修缮及人才事务 | 决定扩军和后方建设的支付能力 |
| 钱收入 | 各城市每旬产生的常规金钱收入，汇入府库 | 支撑持续战争投入 |
| 粮 | 各城市独立粮仓的实际库存，有容量上限 | 经现有粮道供应军团 |
| 粮收入 | 本城每旬产生的粮食 | 决定长期供粮能力 |
| 预备兵 | 本城尚未正式征募的可动员人力库存 | 征兵的唯一人力来源，须经过征募结算才能进入部队 |
| 预备兵收入 | 本城每旬新增的可动员人力，进入预备兵库存 | 决定持续征兵能力，受城市基础产出和兵营等级影响 |
| 城防耐久 | 当前耐久与耐久上限，沿用现有城门耐久结算 | 决定城市抵抗攻城的能力 |
| 城内士兵数 | 本城所有已编入部队的健康士兵总和，即城内大军团总兵力 | 从部队实时汇总，不是独立士兵库存，不包含预备兵和伤兵 |
| 伤兵数 | 本城大军团各部队伤兵之和，保留所属部队 | 按现有休整规则恢复，不计为健康兵力 |

城市面板显示本城收入；府库属于全势力，不为每个城市另建一套金钱库存和拨款操作。

钱收入、粮收入、预备兵收入都是每旬产出能力，不是库存。一次商贸活动收益、售粮收入、购粮所得等单独入账，不冒充永久产出增长。粮食面板另显示当前供粮消耗估算。

### 2.2 城内大军团、兵员与伤兵守恒

同一城市内的本方部队默认组成**一个城内大军团，部队数量不设上限**。每支部队仍保留武将、兵种、健康兵力、伤兵、战法等独立状态。

“城内士兵数”是这个大军团各部队健康兵力的汇总值，不再设一份“已征待编士兵”库存。城内伤兵同样按部队汇总。每名士兵始终属于某支具体部队，预备兵才是尚未进入部队的人力库存。

示例：本城三支部队分别有2,000、3,000、1,500名健康士兵，城内士兵数就是6,500；三支部队合计600名伤兵，另显示伤兵600，不重复加入6,500。

```text
每旬预备兵收入 → 城市预备兵库存
城市预备兵 + 征募钱粮 + 时间 → 城内大军团的具体部队健康兵力
部队战斗负伤 → 该部队伤兵 → 康复 → 该部队健康兵力
城内士兵数 = 本城大军团所有部队的健康兵力之和
```

- 征兵成功500人：本城预备兵减少500，按已批准方案向本城具体部队补入合计500名健康士兵，扣除本次征募费用；城内士兵汇总随之增加500。没有预备兵时无法征兵，不能用更多钱或“超额成功”凭空造人。
- 征兵与补入部队是同一次原子结算，不再设置先征到城市库存、再扣城市士兵补入军团的两阶段流程。玩家直接补兵与军事负责人自动征兵必须共用规则、额度及预备兵预留，不能形成两个可重复收费或领奖的入口。
- 某部队100名伤兵康复：该部队伤兵减少100，健康兵力增加100，城市汇总据此刷新；不增减预备兵，不再额外生成一份城市士兵。
- 部队离城时带走自身健康士兵和伤兵，城市汇总随之减少；返回时汇总增加，不视为征兵或预备兵收入。
- 征兵纳入军事方向，优先补充玩家已编制部队的合法缺额；新建部队的武将、兵种和出征编组由玩家的编制命令决定。没有合法接收部队或全部满编时待命，不生成无人归属的士兵池。
- 兵营建设纳入军事方向。自然产出只进入预备兵，不能直接增加部队兵力；预备兵库存、部队缺额、征兵及整补额度分别核验并记账。
- 预备兵不按现役军人标准消耗军粮；已编入部队的健康士兵和伤兵统一按军团既有规则耗粮，城市汇总不另外扣一次粮。
- 伤兵恢复纳入军事方向：医馆提供日常恢复加成，主动救治提供额外康复机会，均只能转换真实存在且符合休整条件的伤兵。
- 城市固有守军如继续存在，必须作为明确的守备部队纳入城内大军团和汇总，不能在城外另保留一份隐形守军兵力；其缺额和补充同样受真实人力约束。

组织与战斗边界：

- 同城本方部队默认合入同一城内大军团，归并保留部队ID、武将、兵种、伤兵与成长。其他势力或盟军不自动混编进本方军团。
- 玩家可选择其中部分部队组成出征军团，**每支出征军团最多10队，保持原有限制**。剩余部队留在城内；归城并结束交战后默认重新归入城内大军团。
- 处于交战或增援流程的部队按现有战役处理，先维护战场引用，不能在战斗中强制合并并重置状态。
- “不限部队数”指城内大军团的组织容量，不代表单支部队带兵人数无限。每名武将带兵上限仍有效，健康士兵与伤兵合计不得超限。
- 战场同阵营同时上阵六队的现有规则保留，其余作为预备队；守城首发战意与护盾只给首发在场单位，不因城内有更多部队而重复发放。
- 十队的容量限制仅用于出征编组，不得应用于城内大军团；合并、拆分、存档和UI分别核验两种容量。超过十队的城内大军团不能直接行军，败退时拆为每支最多十队的行军纵队。大军团仍只有一套指挥任命，不因归并部队而叠加多套主副将加成。
- 城市汇总按部队实际驻城状态统计，不按武将归属地统计；行军部队不计入。发生本城守城战时，使用战场权威状态统计本城参战守军，避免战场副本与军团记录重复计数。

### 2.3 民心与武将忠诚

首版暂不启用城市民心。没有明确作用闭环前，不加入单纯增加维护负担的安民事务。

现有代码中的民心产出倍率、赈济和占城民心变化，在实现本方案时一并移除或替换为明确的基础产出规则，不能只隐藏界面、保留后台惩罚。

人才方向使用的是**武将忠诚**，与城市民心无关。忠诚影响被其他势力劝说的难度；安抚用于恢复忠诚。低忠诚增加被争取的风险，不等于每旬自动随机离开。

### 2.4 城市技术

技术是城市的长期能力，不是可消耗资源。

- 每城独立保存已掌握技术和当前研究进度。
- 技术首版只负责解锁兵种，不额外叠加攻击、防御、战法威力等属性。
- 新编部队、转换兵种、补充该兵种的新兵，需要所在城市掌握相应技术。
- 已有部队的行军、驻守、作战不受当地技术限制；伤兵康复也不需要当地技术。
- 失去原编制城市不使现有部队退化。
- 具有水域等地理要求的兵种，还需满足对应编制条件。
- 城市被占领时保留已掌握技术；未完成研究保留进度但暂停，由新归属重新委任后推进。
- 首版不做技术自动向其他城市传播。

基础兵种默认可用；弩兵、骑兵、攻城兵器、舰船等技术条目及准确解锁对应关系，在实现时对照现有兵种目录定表。上述名称是类别示例，不代表已经确定的完整科技树。

### 2.5 五个方向的建筑

| 方向 | 建筑或设施 | 长期作用 | 配套主动事务 |
| --- | --- | --- | --- |
| 商业 | 市场 | 增加每旬钱收入 | 集市、商旅、招商合作、税务 |
| 农业 | 农田、粮仓 | 增加粮产、库容及发送能力 | 督耕、灌溉、购粮、保粮 |
| 技术 | 工坊 | 提高本城研究效率及试制成功把握 | 研制、攻关、仿制、试制 |
| 军事 | 兵营 | 提高每旬预备兵收入、征兵能力和军团整补额度 | 从预备兵中常规征兵、加急征兵 |
| 军事 | 医馆 | 提高符合休整条件的驻城伤兵恢复速度 | 集中救治、精心疗养 |
| 军事 | 校场 | 提供本城守城初始战意加成 | 守城操演、战前动员 |
| 军事 | 城防工事 | 提高城防耐久上限及本城守城初始护盾 | 修缮、抢修、布置守备 |
| 人才 | 招贤馆 | 提高探索、登用成功把握及本城接洽条件 | 探索、登用、劝说、安抚 |

农田通过“开垦”建立，其余建筑使用“新建”；每种均有扩建或加固升级动作。每城每类设施一个等级，不做建筑摆放或重复建造同名建筑。建筑本身不新增资源货币，不自动保证主动事务成功。

工坊和招贤馆提供加成，不把没有建筑的城市完全锁死：基础研究、基础人才事务仍可进行。校场与城防的战斗加成仅用于本城守城，不能随部队带去其他战场。建筑与具体效果的上限由统一规则管理。

## 3. 持续委任与三级动作

### 3.1 玩家命令

命令示例：

> 荀彧，在许昌负责商业。

只要求城市、方向、执行人三个输入。默认沿用势力内政支出限制，不要求玩家为每项委任反复设置任期和预算。

约束：

- 一名武将同时承担一项内政委任、执行一个具体行动。
- 每城每个方向可委任多名负责人，每人保留独立委任和具体行动；同方向、不同方向均可并行处理合法事务。
- 同属本方、实际同城且负责同一大方向的武将有机会自动协作；无需另下协作命令，不要求执行同一具体动作或面对同一对象。
- 受命者须在本城、属于本方且未处于行军或其他占用状态。
- 太守可兼任本城一个方向；执行人的职责与太守被动效果分别结算，不能重复应用同一加成。
- 玩家给执行人新命令时，旧委任解除，当前动作按中止规则处理。
- 目标满级、无合适对象、钱粮不足或风险不值得承担时可以待命。待命不取消委任。

### 3.2 三级结构

| 层级 | 含义 | 示例 |
| --- | --- | --- |
| 第一级：行为 | 做什么 | 新建、扩建、研究、探索、登用、劝说、安抚 |
| 第二级：对象 | 对什么做 | 市场、农田、具体技术、具体武将 |
| 第三级：成效 | 最终实际发生什么 | 设施建成、收入增加、亏损、研究受阻、人才加入、安抚失败 |

“实施”必须带有具体行为名称，例如“实施·举办集市”。三级结构不是要求玩家手工选择每个步骤，而是执行人的动作定义和事件记录结构。

### 3.3 运行循环

```text
持续委任
  → 检查城市、人物、资源与战争状态
  → 筛选合法行动及对象
  → 评价收益、需求、成本、风险和后续价值
  → 在合理候选中选择行动
  → 扣除已批准费用，记录开始事件
  → 按世界时间推进
  → 结算成败与真实状态变化
  → 记录结束事件
  → 根据新状态重新判断
```

### 3.4 同城同方向自动协作

- 商业、农业、技术、军事、人才五个方向均适用。例如市场扩建与集市经营同属商业，征兵与救治同属军事，都可相互帮助。
- 同城同方向是进入候选的条件，不要求高关系或专门技能；相性与当前关系影响触发机会，协助者相关能力影响增益幅度。相性差、关系差的组合仍有较低机会。
- 至少有一个实际推进或结算的合法行动承接效果；同方向待命者可帮助正在执行的同僚，全部待命时不产生空协作。出征、调离、暂停执行或围城期间不能参与。
- 协作是现有事务中的轻量帮助，协助者仍可继续本方向原行动，不占第二个行动槽、不重复收取整份行动费用。
- 每次改善一项真实行动的进度、成果数量或成功把握，由动作目录指定一种出口；人才仍只对原目标结算一次，不额外掷一次登用判定。
- 协作额外收益设每城每方向的频次和单次幅度上限；人数增加提供更多搭配和正常事务处理能力，不按所有两两组合无限叠加收益。
- 征兵、救治、修缮和守城准备继续受真实预备兵、批准钱粮、伤兵、缺额及统一上限约束；一次协作不永久放大建筑基础产出。
- 记录参与人、行动ID、日期与实际增益；有效合作才产生关系成长，仅同城挂名不增长关系。首轮参数与结算细则见[人物机制草案第4.3节](人物性格相性义理-设计草案.md#43-内政同城同方向自动协作)。

## 4. 商业行动库

目标：发展持续钱收入，并在需要时筹集当期资金。首版以市场为主要设施，不加入商户人口、商品种类、金属原料或造币生产链。

| 第一级：行为 | 第二级：对象 | 条件与用途 | 第三级：成效 |
| --- | --- | --- | --- |
| 新建 | 市场 | 本城没有市场，建设队列空闲 | 建成一级市场、提高每旬钱收入；也可能延期或施工失败 |
| 扩建 | 市场 | 市场未满级，资金允许 | 提升市场等级与每旬钱收入；可能节支、延期或本期失败 |
| 实施·举办集市 | 本城市场 | 适合争取近期收益 | 支付筹办费，结算冷清、正常或兴旺的活动收入，可能盈利或亏损 |
| 实施·招徕商旅 | 本城市场 | 适合改善未来若干旬收入 | 成功获得有期限的收入加成；部分成功加成较低；失败损失本次费用 |
| 实施·招商合作 | 市场扩建项目 | 存在可扩建空间 | 获得下次扩建的一次性折扣，或合作失败；不是立即完成扩建 |
| 实施·出售余粮 | 本城粮仓 | 扣除供军保留量后仍有余粮，并有可用买方机会 | 按成交条件粮换钱；未成交则不扣除未交付粮食，可损失联络费用 |
| 实施·整顿税务 | 本城税收 | 无同类有效治理收益或处于相应事件条件 | 获得有期限的税收改善；部分达成或失败，不另设腐败资源条 |

规则：

- 市场基础产出自动结算，执行人离开后仍然存在。
- 主动活动收益与基础收入分开入账，同一活动每城每旬至多结算一次。
- 临时增益、折扣有明确期限和上限，同类不无限叠加。
- 售粮不得耗尽供军保留粮，不能从被封锁城市虚构对外交易。

## 5. 农业行动库

目标：提高产粮、存粮和现有补给体系的发送能力。使用农田、粮仓，不新增独立种子、肥力、水量等资源。

| 第一级：行为 | 第二级：对象 | 条件与用途 | 第三级：成效 |
| --- | --- | --- | --- |
| 开垦 | 农田 | 对应设施未建立 | 建立一级农田、提高粮收入；可能发现良田、延期或开垦失败 |
| 扩建 | 农田 | 未满级，适合长期增加供粮 | 提高等级与每旬粮收入，结算费用和工期变化 |
| 实施·督耕 | 农田 | 需要近期增加粮产 | 提高本旬粮产；可能增产明显、低于预期或没有额外成果 |
| 实施·修整灌溉 | 农田 | 适合改善未来若干旬收成 | 花费金钱，获得有期限的粮产加成；可能部分完成或失败 |
| 新建 | 粮仓 | 无对应粮仓设施 | 增加库容及每日发送能力；可能延期或施工失败 |
| 扩建 | 粮仓 | 库容紧张或本城发送能力不足 | 提高库容和发送能力，结算费用与工期变化 |
| 实施·购粮 | 本城粮仓 | 有库容、资金及可达卖方机会 | 钱换粮；成交量或报价可能变化；未成交不凭空扣除货款 |
| 实施·抢收保粮 | 受灾农田 | 仅在真实灾情事件发生时可用 | 消耗费用，减少本次产粮损失；可能部分挽回或未能挽回 |
| 实施·整理仓储 | 有霉变隐患的粮仓 | 仅在相应事件发生时可用 | 消耗费用，减少受影响批次粮食损失；可能清理不彻底 |

规则：

- 农业增加的粮食按时点入仓，受库容约束；溢出部分如有损失必须记录。
- 督耕的额外粮食旬末到账，不能用于偿付此前已经发生的断粮。
- 粮仓只提高自身能力，不能绕过道路共享运量、距离限制或敌军封锁。
- 买卖粮食共用报价口径和价差，禁止同一时段低买高卖的无风险循环。
- 购粮和售粮是城市对外交易事件，不取代军团既有粮道；必须验证可达性，首版无需实体商队。
- 灾害事件低频、有损失上限，不把持续微操救灾作为正常经营的必要条件。

## 6. 技术行动库

目标：为本城解锁兵种，并通过工坊建设提高研发能力。执行人可以先改善设施，也可以选择研究目标及推进方法；一座城市同时只有一个研究目标。

| 第一级：行为 | 第二级：对象 | 条件与用途 | 第三级：成效 |
| --- | --- | --- | --- |
| 新建 | 工坊 | 本城无工坊，资金与建设队列允许 | 建成后提高研究效率及试制成功把握；可能延期或施工失败 |
| 扩建 | 工坊 | 工坊未满级，持续研发需求较高 | 提高工坊等级及研发加成；可能节支、延期或本期失败 |
| 实施·常规研制 | 当前兵种技术 | 默认研究方式，风险较低 | 正常推进、进度较少或本期未取得进展 |
| 实施·集中攻关 | 当前兵种技术 | 愿意投入较高费用争取速度 | 获得较多进度、突破，或投入后仍遇到瓶颈 |
| 实施·寻访工匠 | 当前技术相关人才线索 | 需要外部技术帮助 | 获得技术启发和进度，或无功而返 |
| 实施·聘请名匠 | 有效来访机会 | 仅在对应工匠事件出现时可用 | 支付费用，争取较高研究进度；可能效果低于预期 |
| 实施·仿制改良 | 真实缴获的相关器械机会 | 有对应战果记录与未消耗机会 | 消耗机会和费用推进研究；可能仿制受阻 |
| 实施·试制验证 | 接近完成的兵种技术 | 达到试制门槛 | 验证成功并解锁，或验证失败、保留已积累进度 |

规则：

- 只维护一条研究进度，不新增知识点、工匠人口或材料生产链。
- 工坊加成作用于本城动作的实际进度与试制规则，不自动解锁技术、不直接强化战斗属性；自身建设期间同一执行人不能同时研发。
- 工匠寻访属于研究辅助事件，不自动生成可编军武将；武将获取统一走人才方向。
- 缴获器械必须来自真实战果，在相关来源实现前不开放该动作，不能独立随机生成战果。
- 研究失败不清空全部历史进度；达到门槛后，试制成功才正式解锁，不重复发放收益。
- 技术全部掌握或暂时无法推进时允许待命。

## 7. 军事行动库

目标：从预备兵中征募城市士兵、恢复真实伤兵、提高城防，并为下一场守城战准备初始战意与护盾。军事负责人处理后方军务，军团出征、编制和战场指挥仍由玩家的军事命令负责。

### 7.1 建筑动作

| 第一级：行为 | 第二级：对象 | 条件与用途 | 第三级：成效 |
| --- | --- | --- | --- |
| 新建／扩建 | 兵营 | 无设施或未满级，存在扩军需求 | 增加每旬预备兵收入、主动征兵能力及整补额度；不直接生成部队兵力；可能延期或施工失败 |
| 新建／扩建 | 医馆 | 无设施或未满级，城内有持续休整需求 | 提高驻城伤兵日常恢复速度及主动救治能力；可能延期或施工失败 |
| 新建／扩建 | 校场 | 无设施或未满级，需要加强守城准备 | 提高本城守城初始战意及操演效果上限；可能延期或施工失败 |
| 新建／加固 | 城防工事 | 对应设施尚未建立或未满级 | 增加耐久上限、新增部分的当前耐久及守城初始护盾能力；不自动补满旧损伤 |

### 7.2 征兵与救治

| 第一级：行为 | 第二级：对象 | 条件与用途 | 第三级：成效 |
| --- | --- | --- | --- |
| 实施·常规征兵 | 本城兵营、预备兵及接收部队 | 有可用预备兵、钱粮、合法部队缺额及本旬征兵与整补额度 | 将实际征得的预备兵直接补入已批准的部队；可能达到预期、人数不足或失败 |
| 实施·加急征兵 | 本城兵营、预备兵及接收部队 | 战争需求紧迫，有预备兵、合法缺额并接受较高费用 | 在更短时间内转化预备兵并补入部队，或征募不及预期；与常规征兵共享人力、额度及接收缺额 |
| 实施·集中救治 | 本城医馆及符合条件的驻军伤兵 | 有真实伤兵、钱粮和休整条件 | 较快恢复一批伤兵，或只恢复部分、未取得额外康复成果 |
| 实施·精心疗养 | 本城医馆及符合条件的驻军伤兵 | 不急于返回战场，希望节省费用、提高把握 | 用较长时间争取较稳定的康复成果；仍可能低于预期 |

征兵消耗预备兵、钱粮和时间，不再额外新增人口、装备、药材资源条。自然预备兵收入与征兵转化分别记账；普通与加急方式有费用、时间和成功把握差异，不能让加急征兵在所有方面都更优。

开工时记录接收部队ID、分配人数并预留本次人力与相应额度，预留仍属于预备兵库存但不能被其他征兵动作使用。完成时重新检查接收部队仍在本城、未交战、兵种技术满足且有合法缺额，只按实际成功补入人数扣除预备兵并增加该部队健康兵力，其余预留释放。不能向已经离城的部队远程补兵；失效的分配不自动转给未经批准的新部队。征募失败不能让没有入伍的预备兵凭空消失；已发生组织费用可以损失，未使用的按人成本按规则退回。部分成功、取消和失城必须同步清理预留，不能残留重复征募机会。

本次成功人数不超过已预留人力、已批准人数、费用可支付人数、本旬剩余额度和接收部队实际缺额。部队缺额按带兵上限减去健康士兵与伤兵之和计算；同期补兵、康复或改编后必须重新核验。超额成功只能相对于通常预期，在开工已批准范围内取较好结果；不能透支未来几旬的预备兵收入。预备兵按旬末产出到账，在到账前不能参加本次征兵。没有单独的城市已征士兵库存上限，城内总兵力由实际部队及其带兵上限构成。

医馆不取代所有基础休整：原有合法伤兵恢复继续存在，医馆提高恢复能力，主动救治提供额外成果。每日自然康复先处理，当天到期的主动救治再基于剩余伤兵结算；不能重复治疗同一个人。

救治开始时记录涉及部队ID，结束时重新检查这些部队是否仍在城、未交战、足额供粮且仍有伤兵，不能只依赖可能在归城合并时改变的军团ID。恢复量受真实剩余伤兵与既有带兵上限约束；离城或参战的对象不获得远程治疗。失败只表示本次额外治疗无效，不凭空制造死亡或倒扣已经恢复的兵力。

### 7.3 城防与守城准备

| 第一级：行为 | 第二级：对象 | 条件与用途 | 第三级：成效 |
| --- | --- | --- | --- |
| 实施·常规修缮 | 受损城防 | 正常费用与工期 | 恢复预期、较少或零耐久，按结果记录支出 |
| 实施·紧急抢修 | 受损城防 | 较高费用，争取较短工期 | 较快恢复耐久，也可能效果低于预期 |
| 实施·征集工匠 | 下一项军事建筑工程 | 存在具体待建或待修工程 | 获得一次性工期或费用优惠，或征集失败 |
| 实施·检查整固 | 城防薄弱处 | 有实际损伤或可检查问题，受冷却约束 | 修复少量耐久或获得下次修缮优惠；也可能没有额外成果 |
| 实施·守城操演 | 本城校场 | 有守城准备需求且未被围城 | 成功后提高下一场本城守城战的初始战意；部分成功加成较低，失败不获得加成 |
| 实施·战前动员 | 本城校场与守军 | 敌军接近，愿意支付较高费用争取速度 | 较快取得有期限的开场战意准备；可能不及预期或失败，与操演共用一个准备槽 |
| 实施·布置守备 | 本城城防工事 | 有守城准备需求且未被围城 | 增强下一场本城守城战的初始护盾；可能准备不足或失败 |

修缮只恢复当前耐久；新建、加固才能提高永久上限。原有被动城门恢复若保留，必须与主动修缮共同受上限约束并分别记账。

### 7.4 初始战意与初始护盾的边界

- **生效范围：**只对本城攻守战的守方首发在场单位生效，包括按现有规则生成的守军；不作用于攻方、野战、其他城池或城门本体。
- **首发认定：**遭遇建立时记录本城已完成的设施与准备快照，首次锁定布阵、正式开战时确定受益单位。后续援军、预备队首次上场或单位重新上场不再次获得该开场奖励。
- **战意：**由基础初始战意、校场加成、有效准备加成及既有合法来源共同计算，受既有战意总上限及专门的守城内政加成上限约束。不会绕过战法门槛、施放流程与冷却；允许在规则范围内更早获得施放机会。
- **护盾：**由统一守城开场规则计算，使用现有护盾伤害吸收机制。按照首发单位实际初始健康兵力确定数额和比例上限，不按城市总兵数或伤兵生成护盾。
- **现有规则整合：**当前代码已有守方首发护盾（初始兵力的15%）。新方案需要将这部分与城防设施、布置守备合并为一个明确公式，不能先发旧护盾再重复叠加同名新护盾；基准数值与总上限待平衡测试确定。
- **永久与临时：**校场、城防等级为每场新的本城守城战提供建筑基础加成；操演／动员提供一个战意准备状态，布置守备提供一个护盾准备状态。各状态有期限、上限，不累加刷层，新的成果只替换更优值或按规则刷新期限。
- **消费：**有效主动准备在正式开战时绑定战役并消费一次；未正式开战的取消不消费。已消费后即使战役很快结束也不退回，必须重新准备下一战。
- **续战：**战役内暂停、委托、接管、跨旬、读档、预备轮换均不重新发放。存档保存准备快照、消费记录、受益单位与已经应用的初始状态。
- **时效：**准备在战略层到期时不影响已经开战的状态；战内护盾按正常战斗规则吸收、到期或消失，不能返回城市账簿重新兑换。
- **失城：**旧势力主动准备清除，完成建筑按占城规则保留；新占领者不能继承旧势力的操演／动员和布置守备成果。

首版不再另设“城门临时护盾”，原“战前加固”的临时防护用途统一改为布置守备，提高守方单位初始护盾，避免混淆城门耐久和部队护盾。

### 7.5 军事负责人的选择

有大量伤兵时倾向救治；城内部队有合法缺额且预备兵、钱粮允许时倾向征兵；预备兵不足时考虑扩建兵营以提高后续收入，或等待下一旬；城防受损时考虑修缮；敌军逼近时提高抢修、操演、动员与守备准备的优先级；长期安全且资源宽裕时考虑扩建建筑。没有预备兵、没有合法接收部队、没有伤兵、部队已满编或准备效果已达上限时排除对应无效动作。

被围城时停止军事内政建设、征兵、主动救治、修缮和新增准备；已经生成的战场状态继续按战斗规则运行，不能通过内政给交战部队持续刷战意、护盾或治疗。

## 8. 人才行动库

人才方向包含招贤馆建设，以及探索、登用、劝说、安抚四类人才事务。寻访、宴请、赠礼等可以作为具体事件描述或费用方式，不再扩展为独立的人才事务类别。

| 第一级：行为 | 第二级：对象 | 第三级：成效 |
| --- | --- | --- |
| 新建 | 招贤馆 | 建成后提高本城探索和登用成功把握；可能节支、延期或施工失败 |
| 扩建 | 招贤馆 | 提高设施等级与对应加成，上限明确；可能延期或本期失败 |
| **探索** | 本城及周边尚未发现的人才 | 发现具体人物、获得有效线索，或探索失败 |
| **登用** | 已发现的在野人才 | 加入我方、愿意继续接洽，或拒绝加入 |
| **劝说** | 周边其他势力的人才 | 同意投靠、忠诚动摇，或拒绝接触；接触暴露时进入防备期 |
| **安抚** | 本城我方人才 | 忠诚明显提高、小幅提高，或安抚未奏效 |

招贤馆不自动生成武将，不把人才招募变成必成，不直接降低敌方忠诚。负责人仍需执行具体事务；没有招贤馆也可进行基础人才事务。建馆、扩建与人才事务共用同一执行人的行动时间。

### 8.1 探索

- 从真实候选名单选择人物，区域范围按本城和战略地图相邻城池定义。
- 已知、已加入、死亡或其他不符合条件的人物不能重复生成为新人。
- 发现不等于加入；未知人物信息须经发现流程揭示。
- 线索使用轻量事件状态记录，不建立多层情报资源体系。
- 候选池为空时内部排除无效探索，但不向玩家泄露尚未获知的名单。

### 8.2 登用

- 目标必须是已发现、当前没有所属势力且可接洽的人物。
- 执行人能力、双方关系、对方意愿及此前接洽结果影响成功率。
- 失败或拒绝后设置冷却，不能立即反复赠礼重试。
- 加入后放入唯一人物名册；需要移动时按正常战略时间抵达，未到任前不能在目标城市任职或编军。

### 8.3 劝说

- 目标限于周边其他势力、已经掌握必要信息且符合可劝说条件的人物。
- 不作用于势力君主等不可转投角色。
- 比登用在野人才更难；忠诚、关系与接触条件影响成功率。
- 部分成功可以降低目标忠诚或保留接洽优势，但有幅度上限、期限与冷却，不能靠机械重复必然挖走所有人。
- 防备期内暂停对同一目标的反复劝说。
- 投靠只转移人物，不附赠敌方军团、兵力或城市。
- 对正在交战或无法安全脱离的目标暂不执行投靠结算，待合法交接时点处理；必须同步移除其原职位并修复编制引用。
- 目标已有军职时，其原部队留在原势力，不能因人物转移复制或删除兵力。具体编制接替复用军事规则。
- 首版不加入俘虏招降和独立外交惩罚系统。

### 8.4 安抚

- 对象是本城我方人物，包括本城合法驻守且可接洽的人物。
- 使用统一武将忠诚字段；忠诚高降低被劝说概率，低忠诚不是自动离开的定时器。
- 忠诚满值时不执行无效安抚；失败不无理由额外扣忠诚。
- 宴请、慰问、赏赐的描述必须对应真实费用和结算，不凭叙事改变其他属性。

### 8.5 人才方向的选择逻辑

| 当前情况 | 倾向行动 |
| --- | --- |
| 本城重要人物忠诚偏低 | 安抚 |
| 有值得争取且把握较高的在野人才 | 登用 |
| 周边存在有机会转投的其他势力人才 | 劝说 |
| 缺少合适的已知目标 | 探索 |
| 无有效对象、冷却未结束或资金不足 | 待命 |

存在持续招募需求且资金允许时，负责人也可以选择新建或扩建招贤馆；没有可用候选、接洽机会或可预期用途时，不为了保持忙碌而盲目建设。

以上是优先级依据，不是每人固定执行的脚本。

## 9. 成败与随机性

### 9.1 结果类型

每项行动显式定义合法结果集：超额成功、正常成功、部分达成、失败；外部事件造成的暂停或中止另行记录。

不是每个动作都必须使用四档结果，但不能把全部内政写成付费后必定获得固定收益。能力强意味着更可靠，不意味着所有风险永久为零。

| 类型 | 好结果 | 普通或部分结果 | 坏结果 |
| --- | --- | --- | --- |
| 商业 | 超额盈利、合作优惠 | 收益正常或较少 | 亏损、招徕失败 |
| 农业 | 增产明显、开垦顺利 | 小幅增产、挽回部分损失 | 无额外增产、救灾未奏效 |
| 建设 | 正常或提前完成、节支 | 延期、保留已完成进度 | 本期投入未带来有效进展 |
| 技术 | 大幅进展、验证通过 | 少量进度、需要继续改进 | 本期无进展、验证失败 |
| 军事 | 征兵顺利、较多伤兵康复、守备准备充分 | 募得或恢复人数较少、准备加成较低 | 本次额外征兵、救治或准备未奏效 |
| 人才 | 人物加入、忠诚提高 | 获得线索或保留接洽机会 | 拒绝、无功而返、接触暴露 |

一次失败只影响本次规则允许的投入和成果。除独立、明确的战争或灾害事件外，不因一次普通失败清空城市设施、研究积累或库存。

### 9.2 成功率依据

概念公式：

```text
行动成功率 = 基础概率 + 执行能力修正 + 有利条件 - 难度与不利条件
```

| 方向 | 主要能力 | 环境依据 |
| --- | --- | --- |
| 商业 | 政治、魅力 | 市场、商机、道路可达性 |
| 农业 | 政治 | 农田、灾情、战争干扰 |
| 技术 | 智力、政治 | 技术难度、已有进度、辅助机会 |
| 军事 | 统率、政治；征兵可参考魅力 | 兵营与医馆、可用预备兵、真实兵伤数量、城防受损程度、校场、战争压力 |
| 人才 | 魅力、政治 | 人物关系、忠诚、意愿和接洽记录 |

具体概率和上下限通过调参确定。费用、主要风险和可见成功把握在开始时可查看；敌方未公开的忠诚等信息不能直接泄露。

### 9.3 随机来源与约束

1. **行动选择随机性：**先过滤非法或明显不合理动作，再从价值接近的候选中带权选择。
2. **机会随机性：**商机、名匠、良田、灾情等低频事件改变可选行动。战果类机会必须来源于真实战斗。
3. **结果随机性：**依据规则抽取成果幅度、成败、费用节省或工期变化。

限制：

- 不随机选择必然耗尽供军粮、超支或重复获利的动作。
- 临时效果、折扣、商机有有效期、上限与消费标记。
- 同一事件只结算一次；随机结算使用可保存的确定性随机流，刷新和读档不重抽。
- UI查看、暂停和日志展开不消耗随机数；内政随机流与战斗随机流分开，避免改变日志顺序影响战斗。
- 不为常规行动强行编造灾难；高风险动作必须有对应收益与可见风险。

## 10. 武将决策

能力决定效率和成功把握，性格倾向决定对短期收益、长期建设、风险和资源保留的偏好。

评分考虑：当前需求、预期净收益、持续价值、战略价值、费用、耗时、风险、机会期限和重复行动收益下降。不同量纲应换算为可比较的评分。

无需通用复杂规划器，但必须识别基本后续价值，例如建成市场会开放集市，完成技术会解锁本城缺少的兵种。

决策可利用战争需求，但不能越过玩家指定方向：商业负责人可以筹钱，不能擅自调动军团；技术负责人可以根据军队组成选择研究目标，不能擅自改编部队。

失败后更新下一次选择：

- 集市亏损后降低短期重复举办的优先级。
- 工程受阻后评估继续投入、等待或寻求优惠。
- 技术遇到瓶颈后考虑工匠、仿制或调整方法。
- 征兵或救治效果不足后重新核对兵员需求、伤兵和资源，不能无条件重复加急投入；守城准备已满时转向其他事务。
- 人才拒绝后遵守冷却，考虑其他目标。

不同武将可能做出相同的合理选择，不为表现个性强行制造差异。

## 11. 时间、费用与中断

### 11.1 时间与结算

- 沿用一旬十天、战略筹划后逐日执行的世界时间。
- 玩家完成旬首操作、点击执行后，负责人统一开始或继续行动。
- 常规事务以一旬为基础，建设和研究方法可以跨旬；紧急抢修可有更短日数，具体时长待调参。
- 按世界日推进动作，日末检查到期；只在完成、中断或指定阶段发生一次结果判定。
- 旬末当天先结算到期动作，再计算城市常规产出；同一笔额外产出不能在两个环节重复添加。
- 本旬完成动作后不在同一时点无限串行执行；下一次开工在下一旬统一决策。
- 临时“若干旬”增益从首次参与对应产出结算时计一次有效旬，避免创建后立即到期。

### 11.2 共享资源

- 势力设置统一保留军费；农业交易另检查供军保留粮。
- 各城市、各执行人真实共享府库，按稳定优先级与ID顺序批准费用。
- 每城一个建设队列；研究单独占用研究槽，普通事务不占建设队列。
- 五个方向的新建、扩建和加固共同占用该建设队列；不能因工坊、招贤馆属于不同方向而另开免费并行队列。
- 队列已占用时，同方向及其余方向的其他负责人可以选择合法的非建设事务或等待；多人委任与协作不增加建设队列或研究槽。
- 开始时扣除明确费用；节省部分在结算时退回。多阶段费用分阶段批准，不允许失败或延期偷偷无限追加支出。
- 随机亏损不超过已批准投入；收入不足记为亏损，不额外透支府库。

### 11.3 中断规则

| 原因 | 处理 |
| --- | --- |
| 玩家给执行人新命令 | 立即解除旧委任；已完成成果保留，当前动作按类型中止 |
| 建设执行人离开 | 工程保留已支付的有效进度，等待新负责人接续，接续不重复收费 |
| 研究执行人离开 | 研究目标和进度保留，停止推进 |
| 普通活动取消 | 不发放未完成收益，按实际已发生费用结算，未支付部分不扣 |
| 目标失效或加入其他势力 | 停止对原目标的无效动作，记录原因，下一旬重新选择 |
| 城市被围 | 暂停内政执行及常规产出；不增加工期进度、不重复扣费；日历型优惠照常到期 |
| 城市失守 | 旧势力委任终止；未完成建设按现有占城规则中止，研究进度保留但暂停；旧势力守城主动准备清除，未结算的普通活动不凭空发奖 |
| 无合法动作 | 进入待命，直到下一旬或条件变化后重新评估 |

城市失守后的武将去向继续由占城和军事规则负责，人才系统不得额外复制人物。

## 12. 事件与界面

### 12.1 必须展示的信息

城市面板显示资源与产出、军事状态、设施等级、已掌握技术，以及各方向的负责人列表、个人当前行动和本旬协作记录。

军事状态明确显示“预备兵库存／已预留／当前可征”“每旬预备兵收入”“城内士兵总数”“城内伤兵总数”和可展开的城内大军团部队列表，另显示部队缺额、征兵与整补额度、预计恢复，以及守城初始战意和护盾的建筑来源、有效准备、预计加成、期限和适用范围。士兵和伤兵总数均从部队汇总，没有第二份待编库存。不能把预备兵收入显示为自动增加现役兵力，也不能把“守城开场加成”显示为武将永久属性。

行动卡显示：执行人、具体行为、对象、进度或预计完成时间、已付费用、主要决策理由、可见风险和等待原因；发生协作时附协助者、增益类型和实际生效量。

### 12.2 开始与结束事件

开始事件：

> 荀彧开始在许昌扩建市场，预计需要若干旬，批准支出X金。

结束事件：

> 许昌市场扩建完成，每旬钱收入增加Y，实际支出Z金。

失败事件：

> 本次集市收入低于预期，收入A金，支出B金，净亏损B-A金。

人才事件：

> 荀彧开始劝说邻城的一名武将。  
> 对方拒绝接触，本次劝说失败，支出X金，目标进入接洽冷却。

事件必须来自真实数据，不允许用“商队到来”“城墙坍塌”等描述解释一个实际上没有发生的规则事件。

普通开始、结束进入事件流，不反复弹窗暂停。重要人才加入、城市失守、委任失效或重大损失突出提示。

### 12.3 事件记录字段

```text
事件ID / 行动ID / 委任ID
城市 / 执行人 / 方向 / 行为 / 对象
协作参与人 / 协作事件ID / 增益类型 / 实际增益量（发生协作时）
开始日 / 预计结束日 / 实际结束日
费用与实际收入 / 状态变化前后值
结果类型 / 实际原因 / 相关机会ID
```

同一次行动的开始、暂停、恢复和结束通过行动ID关联。收益报告区分已获得收入、永久每旬产出变化和临时效果。

## 13. 示例：许昌商业持续委任

以下仅展示可能发生的过程，不是固定剧本或正式数值：

| 时间 | 状态与决策 | 事件 |
| --- | --- | --- |
| 第1旬 | 没有市场，资金允许 | 开始新建市场 |
| 第1旬末 | 本次施工成功 | 市场建成，基础钱收入提高 |
| 第2旬 | 需要近期资金 | 开始举办集市 |
| 第2旬末 | 本次交易冷清 | 收入低于筹办费用，记录亏损 |
| 第3旬 | 调低重复集市优先级，存在合作机会 | 开始招商合作 |
| 第3旬末 | 合作成功 | 获得一次性市场扩建优惠 |
| 第4～5旬 | 府库满足保留军费要求 | 扩建市场，结束时结算工期和实际费用 |
| 后续 | 继续保留商业委任 | 根据新状态选择招徕商旅、整顿税务或其他合法事务 |

如果途中失去资金、被围或玩家改派荀彧，按统一规则等待、暂停或中止。不能为了完成预设故事强行推进。

## 14. 实现范围与接入顺序

### 14.1 与现有项目的关系

- `strategic-campaign.mjs`：接入持续委任、世界日推进、旬末产出、城市技术与存档校验。
- 军事接入预备兵库存及收入、征兵转化、每日伤兵恢复及攻守战初始化；统一现有守城首发护盾与新增校场、守备加成，保持战意门槛和护盾吸收机制。
- 现有 `manpower` 及其每旬自然产出在新结构中明确为预备兵，不新增独立已征士兵库存。直接补兵入口与军事委任统一为“扣预备兵和钱粮、按规则补入具体部队”，共用预留、额度和一次性结算。开局预备兵与各部队兵力由当前剧本明确配置，不做旧档迁移。
- 城内大军团取消现有十队容量限制，同城归并及离城拆分保留部队ID和战斗状态；城市兵力、伤兵由部队或正在交战的权威状态派生。存档校验不得再以十队为城市军团上限，也不得同时保存两份可独立修改的城市士兵库存。
- `strategic-view.mjs`：增加各方向的多名负责人、个人行动进度、自动协作与事件报告。
- 行动目录、效果规则、决策评分、人才状态建议拆成独立模块，避免继续堆入单一战略文件。
- 已有太守内政特技应映射到明确的费用、产出或行动规则；每个效果只应用一次，既有内政经验成长沿用原规则，不在本方案新增重复奖励。
- V1.5将方向委任改为多人结构，保存每城每方向本旬协作判定、参与人、承接行动、已应用增益及关系成长去重记录。
- 现有设施初始等级由剧本确定。示例“许昌没有市场”不要求所有城市开局归零。
- 战略存档升级版本，包含预备兵库存、城内大军团与具体部队、征兵预留及接收部队分配、委任、动作、建筑、研究、人物归属、忠诚、临时效果、守城准备及战役应用记录、事件消费标记和内政随机状态。
- 遵守项目存档策略：不做旧档迁移，不兼容存档提示重新开始；保留当前版本自动保存、读取、导入导出与确定性续战。

### 14.2 实现顺序

1. 统一资源、城内大军团、部队与人物归属和技术字段，建立动作与事件数据结构。
2. 建立持续委任、费用批准、推进、中断和一次性结算框架。
3. 接入五个方向的建筑，以及商业、农业和军事征兵、救治、修缮行动。
4. 接入城市技术和兵种编制、整补条件。
5. 接入人才四类动作、候选名单、忠诚和转投交接。
6. 接入守城初始战意与护盾，再增加机会事件、决策倾向和结果分布，调试长期收支与攻守平衡。
7. 完成城市界面、事件报告、存档和整体验证。

涉及灾情、工匠机会、战果器械等条件的动作，必须在事件来源接通后开放；目录保留完整设计，不能用假条件或虚构世界状态替代。

## 15. 验收标准

- 一次委任可持续跨旬执行，无需反复确认，也没有固定任期自动结束。
- 商业、农业、技术、军事、人才均有独立作用，五个方向均有建筑建设和升级动作；人才事务严格使用探索、登用、劝说、安抚四类。
- 同一方向可以根据资源、战争、机会和失败记录选择不同动作。
- 同城同方向可多人任职，并能在不同具体动作间自动协作；同城不同方向或同方向不同城市不触发。人数不绕过建设、研究、预算和目标占用限制。
- 协作有可追溯的实际增益与频次、幅度上限，不重复生成产出、兵力、人才或关系；读档、改派和增员不重抽。
- 常规行为具有合理的失败或部分结果，强者更可靠，但不会默认全部成功。
- 每个动作都有开始和结束或中止事件，花费和效果可追溯。
- 基础收入、一次性收入、临时增益不重复结算；城内士兵和伤兵严格等于实际部队汇总，预备兵不计入现役，不另设待编士兵库存。
- 同城本方部队默认组成一个大军团，超过十队仍可归并、保存和展示；每队带兵上限与战场同时上阵六队的规则继续有效。
- 部队出征、返回、同城合并及本城守城战中，城市汇总正确，不因军团ID变更重复结算征兵、救治或指挥加成。
- 粮食、补给、围城和伤兵恢复遵循已有战斗流程。
- 军事征兵必须扣除等量预备兵才能增加具体部队兵力；预备兵为零或没有合法接收部队时不能征兵，自然收入不直接生成士兵，成功人数不能超过预留、批准上限及接收缺额。
- 征兵失败、中止或接收部队离城时释放未转化预留，手动补兵与自动征兵不重复收费、不绕过共享额度；预备兵到账时点及部队耗粮正确，城市汇总不额外耗粮。
- 主动与自然恢复不重复计算伤兵，不能对离城或交战军团远程治疗。
- 守城初始战意和护盾只作用于本城守方首发在场单位，受统一上限约束，不给野战、攻方或后续援军加成。
- 既有15%首发护盾与新规则合并计算；接管、读档、跨旬、轮换不重复发放，主动准备只消费一次。
- 技术真正限制本城新编、转兵种和新兵整补，不限制现有部队在外作战或正常伤兵康复。
- 人才不会重复生成；转投不复制兵力、不凭空取得城池；无效目标与冷却被正确排除。
- 新命令、围城、失城、执行人离开不会导致重复扣费、幽灵任务或无条件领奖。
- 多个城市和负责人不能同时消费同一笔资金或同一事件机会。
- 读档前后决策与结算一致，查看界面不会改变随机结果。
- 不启用隐藏民心倍率；没有独立商品、商户、原料和知识点维护体系。
